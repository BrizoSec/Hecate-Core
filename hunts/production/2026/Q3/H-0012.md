## LEARN: Prepare the Hunt

### Hypothesis Statement

Adversaries operating in the environment will attempt to open handles to `lsass.exe` with access rights that permit memory reading (e.g., `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION`, mask `0x1010` or `0x1410`) from unsigned or non-standard processes, indicating credential dumping activity via tools such as Mimikatz, ProcDump, or comsvcs.dll MiniDump.

### Threat Context

Credential dumping from LSASS is a foundational post-compromise technique used by nearly every major intrusion set (APT29, FIN7, Lazarus, ransomware affiliates). Once an adversary has SYSTEM or a privileged token, extracting cached credentials enables lateral movement, persistence via valid accounts, and privilege escalation across trust boundaries.

## OBSERVE: Expected Behaviors

### What Normal Looks Like

Legitimate processes access `lsass.exe` handles with limited rights: Windows Defender / MsMpEng, EDR agents (falcond, CSFalconService), LSA plugins, and svchost-hosted services. These typically request `PROCESS_QUERY_LIMITED_INFORMATION` (0x1000) rather than memory-read rights.

### What Suspicious Looks Like

- Non-signed or user-space processes requesting handles with mask containing `PROCESS_VM_READ` (0x10) against lsass.exe
- Processes such as `rundll32.exe` invoking `comsvcs.dll,MiniDump` with lsass PID as an argument
- Command lines referencing common dumping tools (procdump, mimikatz, nanodump, dumpert)
- Access from unusual parent process chains (e.g., cmd.exe -> powershell.exe -> suspicious binary)

### Expected Observables

- **Processes:** rundll32.exe with comsvcs.dll arguments, procdump.exe, mimikatz.exe (or renamed variants)
- **Network:** N/A for this technique (credential exfil is a separate stage)
- **Files:** .dmp files written to %TEMP%, %APPDATA%, or C:\Windows\Temp
- **Registry:** N/A
- **Authentication:** Post-hunt, review 4624/4648 logon events for reused credentials
