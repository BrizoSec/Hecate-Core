## LEARN: Prepare the Hunt

### Hypothesis Statement

Adversaries use wevtutil cl or PowerShell Clear-EventLog to clear Windows Security and System logs before ransomware deployment on domain-joined endpoints to destroy forensic evidence.

### Threat Context

Ransomware operators routinely wipe event logs immediately before or during encryption to hinder IR. Event ID 1102 (Security log cleared) and 104 (System log cleared) are the primary detection signals, but adversaries may also suppress these by disabling the event log service first.

### ABLE Scoping

| **Field**   | **Your Input** |
|-------------|----------------|
| **Actor** *(Optional)* | Ransomware operators (e.g., LockBit, BlackCat affiliates); post-exploitation toolkits with built-in log-wiping modules |
| **Behavior** | Execution of wevtutil.exe with 'cl' (clear-log) argument, or PowerShell invoking Clear-EventLog / [System.Diagnostics.EventLog]::Delete; may be preceded by net stop eventlog or sc config eventlog start=disabled to suppress detection events |
| **Location** | Windows domain-joined endpoints and servers; especially high-value targets (DCs, file servers, backup servers) |
| **Evidence** | SIEM windows_logs index: Event ID 1102 (Security log cleared by user), Event ID 104 (System log cleared); EDR process telemetry: wevtutil.exe with command_line containing 'cl ' or 'clear-log', parent process anomalies |
