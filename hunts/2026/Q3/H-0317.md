## LEARN: Prepare the Hunt

### Hypothesis Statement

Adversaries query Active Directory for accounts with the DONT_REQUIRE_PREAUTH flag set and request AS-REP tickets without providing credentials, allowing the encrypted ticket material to be cracked offline. This technique is detectable via Event ID 4768 with etype 0x17 (RC4) or 0x12 (AES) originating from non-Domain Controller hosts.

### Threat Context

Our environment runs on-premises Active Directory with Kerberos event logging (4768, 4769, 4771) centralized in SIEM. AS-REP Roasting is a low-noise, high-value technique frequently used by ransomware operators and initial-access brokers to obtain crackable credential material without triggering lockouts. High priority given AD is a tier-0 asset.

## OBSERVE: Expected Behaviors

### What Normal Looks Like

- Domain Controllers requesting Kerberos TGTs for service accounts (source IP = DC IP)
- Scheduled tasks or service account logins generating 4768 events with etype 0x12 (AES256) during business hours
- Automated monitoring or backup tools performing Kerberos authentication against DCs
- LDAP queries from sysadmin tools (e.g., ADUC, ADSI Edit) that do NOT result in 4768 with RC4

### What Suspicious Looks Like

- Event ID 4768 with `TicketEncryptionType = 0x17` (RC4-HMAC) from a **non-DC** source IP
- Multiple 4768 events for **different target accounts** within a short window from a single workstation
- 4768 requests for accounts that are **service/machine accounts** with low login frequency (indicates enumeration)
- Tooling signatures: Rubeus generates distinctive `Pre-Authentication Type = 0` (no preauth) requests; Impacket leaves Python-generated packets with unusual TGT sizes
- Off-hours Kerberos TGT requests from workstations for accounts that never interactively log in

### Expected Observables

- **Authentication:** Event ID 4768 (Kerberos TGT requested), `Pre-Authentication Type = 0`, `Ticket Encryption Type = 0x17` (RC4) or `0x12` (AES), source address = non-DC workstation/server
- **Processes:** `lsass.exe` on attacker host (Rubeus), Python process (Impacket GetNPUsers.py), PowerShell with `Get-ADUser -Filter {DoesNotRequirePreAuth -eq $true}`
- **Network:** Kerberos traffic (TCP/UDP 88) from endpoints to DCs; abnormal volume or rapid succession of AS-REQ packets
- **Files:** Ticket dump files (`.ccache`, `.kirbi`) written to disk post-exploitation
- **Registry:** N/A for AS-REP Roasting itself; may see Mimikatz-related artifacts in follow-on stages

### Query Performance

**What Worked Well:**
- COUNT-FIRST strategy prevented pulling 14M raw events upfront
- Filtering on `TicketEncryptionType=0x17` dramatically reduced noise (14M → 47 hosts)
- `dc(TargetUserName)` aggregation quickly surfaced enumeration pattern
- EDR pivot confirmed the attack tool and compromised account within one query

**What Didn't Work:**
- Initial DC subnet exclusion used placeholder CIDR — required manual DC IP list for accuracy
- `TicketEncryptionType=0x12` (AES) filter produced many false positives from legitimate service accounts using AES; RC4 filter was more signal-rich for this hunt

**Iterations Made:**
1. Baseline count → filtered to RC4 → grouped by source → pivoted on anomalous host → corroborated with EDR → scoped campaign
