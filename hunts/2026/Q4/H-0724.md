## **TASK#STOMP Backdoor Steals Documents**

The installer stages files in a folder named `WinDefendSvc`, a name that resembles a Windows security component. It launches two hidden PowerShell scripts, `sysloader.ps1` and `winconn.ps1`, after terminating older instances.

`WinDefendSvc`
`sysloader.ps1`
`winconn.ps1`

It also changes the modification times of five staged files to January 15, 2024, making them appear older than the observed activity.

Each script reads a [Base64-encoded](https://cyberpress.org/steganography-and-base64-obfuscation-used-to-hide-malicious-payload/?amp=1) DAT file, decodes its PowerShell payload, and executes it in memory. The primary payload, `diagpack.dat`, handles document collection and surveillance.

The secondary payload, `winconncfg.dat`, maintains a separate remote-access channel. The modules can restart one another, although researchers found a coding flaw that prevents one additional watchdog check from normally running.

`winconncfg.dat`

The scheduled tasks and Startup script provide persistence independently of that check. Both PowerShell processes also compile small C helpers through the legitimate `csc.exe` compiler.

`csc.exe`

These helpers disable TLS certificate validation, letting the malware connect even when a server presents an invalid or mismatched certificate.

The backdoor’s main functions remain inside PowerShell; the compiled helpers support its network connections.

TASK#STOMP scans fixed drives for Word, PDF, PowerPoint, Excel, and archive files created or modified within the previous 365 days.

It skips files larger than 500 MB, tracks completed uploads, and retries failed transfers. After the initial scan, a filesystem watcher detects matching files as they are created or changed, enabling continuous collection.

The modules communicate with `corecloudfileshare.xyz` and `attachmentsharingdrive.xyz`, switching between them if a request fails.

### Justification

The TASK#STOMP backdoor specifically targets business document theft by scanning for Office and archive files modified within the last year. It establishes persistence via scheduled tasks created from XML in LOCALAPPDATA and uses legitimate compiler (csc.exe) to create helpers that bypass TLS validation, allowing it to communicate with C2 servers even if they have invalid certificates. Hunting for this specific combination is critical because standard TLS monitoring will miss the connection due to the certificate bypass, and scheduled task creation from non-standard locations (LOCALAPPDATA) is a strong indicator of malicious persistence rather than legitimate administration.
