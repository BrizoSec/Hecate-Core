### Justification

The threat intel explicitly describes a behavior where an adversary performs a container escape that does not appear in traditional process execution logs, indicating a gap between Kubernetes API audit logs and container runtime telemetry. This discrepancy enables evasion of EDR and process monitoring tools. Correlating audit logs with runtime data is critical to detect such escapes, as the malicious process may execute a binary like `/bin/sh` or `/usr/bin/docker` outside the expected pod context—revealing itself only through field-level correlation. This directly supports the goal of potentially maintaining persistence (capability; not observed in the source) and evading detection in cloud-native environments, which is a high-risk scenario for organizations using Kubernetes.
