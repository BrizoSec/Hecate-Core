### Hypothesis Statement

Adversaries use compromised domain admin credentials to author and link malicious Group Policy Objects (GPOs) at the domain root to enforce operational disruption, disable local security controls, and deploy ransom notes across all domain-joined endpoints via trusted Active Directory replication mechanisms.

Adversary/Attribution: Unknown
Tags: vpn compromise, sysvol abuse, gpo abuse, encryptionless extortion, esxi targeting, data exfiltration, payload, active directory, group policy object, domain controller
Description: In April 2026, a manufacturing organization in the Middle East suffered a ransomware attack where threat actors with domain admin privileges weaponized Active Directory Group Policy Objects to achieve domain-wide impact without deploying ransomware binaries on Windows endpoints. The attackers created malicious GPOs linked at the domain root, delivering ransom notes, hijacking wallpapers and lock screens, enforcing logon banners, and disabling local administrator accounts across all domain-joined workstations. No file encryption occurred on Windows systems; instead, the operation focused on encryptionless extortion through operational disruption and data exfiltration. Initial access was gained via compromised VPN credentials. The attack remained dormant for one day between GPO creation and detonation, evading file-based detection entirely by abusing trusted AD infrastructure.

### Justification

This hunt targets a sophisticated 'encryptionless extortion' tactic where attackers bypass traditional EDR by abusing legitimate infrastructure (Active Directory GPOs) rather than deploying malicious binaries on endpoints. The threat intel explicitly details the creation of specific GPOs ('PAYLOAD', 'win Firewall Off') and the modification of SYSVOL files to disable firewalls and display ransom notes. Hunting for these specific AD structural changes and SYSVOL artifacts is critical because standard endpoint monitoring will miss the initial compromise and lateral movement, which occur entirely within the directory service infrastructure.
