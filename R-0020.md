## 1. System Research: How It Works

### Summary
Securing the SDLC involves integrating security practices at every stage of software development, including planning, design, implementation, testing, deployment, and maintenance. This holistic approach aims to prevent vulnerabilities early in the process when they are cheaper to fix.

### Key Findings
- Security should be a continuous practice throughout all stages of the SDLC and not an afterthought or isolated phase.
- [UNCERTAIN] Many development teams overlook security testing until late in the development cycle, leading to more costly fixes and increased risk exposure.
- Educating developers about secure coding practices is crucial for reducing vulnerabilities from the outset.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries often exploit overlooked or less secure phases of the Software Development Lifecycle (SDLC) such as development environments, third-party code integration, and deployment processes. By focusing on these corners, attackers can inject malicious code, steal intellectual property, or gain unauthorized access to critical systems.

### Key Findings
- Adversaries may target development environments where less stringent security measures are in place compared to production environments.
- Third-party libraries and open-source components used in software projects can be compromised with backdoors or vulnerabilities that remain unnoticed during code reviews.
- Deployment pipelines lacking proper validation mechanisms allow attackers to inject malicious code into the build process, which then reaches end-users undetected.
- Integration testing phases might not thoroughly vet interactions between different systems, leading to potential exploitation of overlooked interfaces.
