## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are exploiting the trust in AI-augmented workflows by deploying supply chain attacks, such as SANDWORM_MODE, to inject malicious code into legitimate software updates. This method allows them to compromise systems at scale and evade traditional detection mechanisms.

### Key Findings
- Adversaries use sophisticated prompt injection techniques to manipulate AI-based decision-making processes within toolchains.
- Supply chain attacks like SANDWORM_MODE exploit vulnerabilities in third-party dependencies and cloud environments to gain a foothold within targeted networks.
- Indicators of compromise include unexpected or anomalous behavior in AI-augmented tools, such as unusual API calls or data exfiltration patterns.
- Falcon Data Security's exposure management capabilities are instrumental in detecting compromised systems in third-party environments.
- Adversaries increasingly leverage zero-day exploits to inject malicious payloads into software updates before patches become available.

## 3. Telemetry Mapping: OCSF Fields

### Summary
SANDWORM_MODE involves automated malware spreading techniques through compromised AI toolchains and software builds. Telemetry should capture anomalous network activity, unauthorized access attempts to build servers or repositories, unusual process execution chains, and signs of lateral movement within the environment.

### Key Fields
- network.http.request.uri (30% populated): Tracks URLs accessed by endpoints that could indicate C2 communication or malicious download sites used for malware distribution.
- process.create.image_file_name (85% populated): Monitors executable files being run on systems, which can help identify unexpected process creation events indicative of malware executing.
- process.create.parent_image (70% populated): Provides information about the parent process that initiated a suspicious activity, aiding in identifying compromised legitimate tools or scripts.
- file.access.path (50% populated): Logs accesses to files and directories, especially those related to build automation tools and repositories which could be targets of manipulation by malicious actors.
- network.tcp.listen.port (20% populated): Monitors open ports that might indicate a service being used as part of an exploit or C2 channel.
- process.create.command_line (65% populated): Captures the full command line arguments for process creation, useful in detecting unusual use of build tools or scripts potentially compromised by attackers.
