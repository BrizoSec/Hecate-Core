## 1. System Research: How It Works

### Summary
AhsayCBS backup utility normally operates via the cbssvcX64.exe service to manage system backups, but exposure of this application allows unauthenticated remote code execution through CVE-2026-105133 and CVE-2026-105134. Exploitation results in the deployment of malicious payloads disguised as legitimate Microsoft Edge components and the installation of a cryptominer (XMRig) via a fake Windows service.

### Key Findings
- The cbssvcX64.exe process is abused to spawn commands that drop files into %TEMP% or AppData/Local/Temp directories, specifically downloading Taskgmr.ps1, msedge.exe, edge.exe, config.json, and WinRing0x64.sys from Alibaba Cloud Object Storage.
- Threat actors establish persistence by creating a Windows service named 'MicrosoftEdgeUpdateSvc' designed to mimic the legitimate 'edgeupdate' service, running disguised binaries like msedge.exe (Hash: 481728a7c9c4c02be07051d9c1958d902ea6397ebb8952ab83944818e3d25d21) and edge.exe.
- The exploitation chain utilizes the vulnerable WinRing0x64.sys kernel driver to enable kernel-level hardware access for optimized mining performance, while Taskgmr.ps1 monitors and terminates Task Manager to hide mining operations.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Threat actors exploit two critical unauthenticated remote code execution vulnerabilities (CVE-2026-105133 and CVE-2026-105134) in AhsayCBS backup utilities to gain SYSTEM-level access on exposed systems. Post-exploitation, the adversaries deploy JSP webshells and XMRig cryptominers disguised as Microsoft Edge processes, utilizing kernel drivers for optimized performance and AI-assisted scripts to evade detection.

### Key Findings
- The attack chain leverages CVE-2026-105133 and CVE-2026-105134 in AhsayCBS versions through 10.3.4, allowing unauthenticated attackers to bypass authentication and execute code with SYSTEM privileges.
- Adversaries drop multiple malicious artifacts into %TEMP% or AppData folders, including a JSP webshell, XMRig miner binaries disguised as 'msedge.exe' and 'edge.exe', and the 'WinRing0x64.sys' kernel driver for hardware access.
- Persistence is maintained via a fake Windows service named 'MicrosoftEdgeUpdateSvc', while a PowerShell script ('Taskgmr.ps1') monitors and terminates Task Manager to hide mining activities.
- Infrastructure includes staging payloads on Alibaba Cloud Object Storage (imagefiles-backup.oss-ap-southeast-7.aliyuncs.com) and C2 connections to XMR pool 51.195.127.124:8029 via xmr.kryptex.network.
- File hashes 481728a7... and 4dcb0202... are identified as malicious (trojan.powershell/starter and trojan.agentb/ravartar) on VirusTotal, confirming the threat actor's tooling.

## 5. Research Synthesis

### Executive Summary
Threat actors exploit unauthenticated RCE vulnerabilities (CVE-2026-105133/105134) in AhsayCBS to execute SYSTEM-level code, staging and executing XMRig cryptominers disguised as Microsoft Edge binaries via a fake 'MicrosoftEdgeUpdateSvc' Windows service. Post-exploitation telemetry is heavily obscured by the use of WinRing0x64.sys for kernel-level access and Taskgmr.ps1 to terminate monitoring processes, requiring specific detection of kernel driver loading and anomalous parent-child process relationships involving legitimate backup services.

### Recommended Hypothesis
> Adversaries use unauthenticated exploitation of AhsayCBS CVE-2026-105133/CVE-2026-105134 to drop and execute kernel-enabled XMRig miners disguised as msedge.exe via a fake MicrosoftEdgeUpdateSvc service for persistent cryptomining.

### Gaps Identified
- Standard EDR telemetry may miss the initial exploitation phase if cbssvcX64.exe command-line arguments are not explicitly logged, and kernel-level activity driven by WinRing0x64.sys may bypass user-mode monitoring unless specific driver load events (e.g., PnP Manager or Sysmon Driver Load) are captured.
- Network detection often fails to identify the initial payload download from Alibaba Cloud Object Storage if TLS inspection is not configured, and outbound mining traffic to xmr.kryptex.network on port 8029 may be indistinguishable from legitimate web traffic without specific domain or protocol analysis.
