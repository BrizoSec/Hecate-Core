## 1. System Research: How It Works

### Summary
SQL injection attacks are used by threat actors to gain and maintain persistent access within a system, often involving the creation of backdoor scripts through scheduled tasks and the use of anomalous user agents. This technique allows attackers to escalate privileges and exfiltrate data.

### Key Findings
- Threat actors leverage SQL injection to execute commands that create persistent backdoors via scheduled tasks or services.
- Attackers frequently dump SAM and SECURITY registry keys to steal credentials for further exploitation.
- Anomalous user agents are used by attackers to masquerade as legitimate users, enabling them to evade detection.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit SQL injection vulnerabilities to gain unauthorized access to databases, subsequently deploying malware such as Demux PowerShell loader for persistence and lateral movement within the network. This technique is particularly prevalent in sectors like hospitality and retail, where adversaries aim to steal sensitive data including payment card information.

### Key Findings
- SQL injection attacks are commonly used by threat actors to inject malicious scripts into database queries
- The Demux PowerShell loader is frequently employed by Carbon Spider for establishing persistence on compromised systems
- Adversaries focus their SQL injection activities primarily in the hospitality and retail sectors due to high-value targets like payment card data
- Persistence mechanisms allow attackers to maintain access and repeatedly attempt re-entry even after initial detection and removal

## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry capturing this behavior would include logs and events related to SQL server operations, anomalous database changes, unusual process execution, and network communications indicative of lateral movement or data exfiltration. Specific focus should be on Windows Security Event Logs (such as account creation/modification), file system activities, registry modifications for persistence mechanisms, and external connections.

### Key Fields
- event.logon: Events related to user logons that might indicate a compromised account being used after the initial SQL injection attack
- event.file.create.modify.delete: Tracking changes in files potentially used by threat actors for lateral movement or creating backdoors
- event.registry.create.modify.delete: Detecting registry modifications, especially those under HKLM/SOFTWARE/Microsoft/W32Time/TimeProviders/NtpSynchronizers which could be used to maintain persistence
- network.http.request: Monitoring HTTP requests that might indicate data exfiltration after the attack
- process.create: Identifying unusual processes spawned by SQL server or other system services that may be indicative of malicious activity

## 5. Research Synthesis

### Executive Summary
Threat actors exploit SQL injection vulnerabilities to gain persistent access within systems by injecting malicious scripts, creating backdoors via scheduled tasks or services, and using anomalous user agents to evade detection. They particularly target sectors like hospitality and retail for sensitive data such as payment card information.

### Recommended Hypothesis
> Adversaries use SQL injection attacks to inject malware and establish persistence mechanisms on compromised systems in targeted industries such as hospitality and retail, aiming to steal high-value data like payment card information.

### Gaps Identified
- Current detection methods may not adequately cover the creation of persistent backdoors through scheduled tasks or services, leading to missed opportunities for early intervention.
- There is a lack of comprehensive monitoring for anomalous user agents used by attackers to masquerade as legitimate users, which could help in identifying and mitigating such evasion techniques.

### Key Findings
- Hypothesis: Adversaries use SQL injection attacks to inject malware and establish persistence mechanisms on compromised systems in targeted industries such as hospitality and retail, aiming to steal high-value data like payment card information.
- Gap: Current detection methods may not adequately cover the creation of persistent backdoors through scheduled tasks or services, leading to missed opportunities for early intervention.
- Gap: There is a lack of comprehensive monitoring for anomalous user agents used by attackers to masquerade as legitimate users, which could help in identifying and mitigating such evasion techniques.
- Focus: Enhancing detection capabilities for SQL injection attacks through continuous monitoring of database operations and anomalous process executions, especially those related to file creation/modification/deletion and registry changes indicative of persistence mechanisms.
- Focus: Implementing robust network security measures to identify and block HTTP requests that may indicate data exfiltration post-attack, ensuring the protection of sensitive information.
