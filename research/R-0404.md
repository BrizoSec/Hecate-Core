## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries use masquerading (T1036) to rename or modify malicious files, making them appear legitimate and thus evading detection by users and security tools. This technique involves altering file names, metadata, icons, or other attributes to mimic trusted binaries or system components.

### Key Findings
- Adversaries often disguise malware as common executables such as regsvr32.exe to blend in with normal system activity.
- Malware distribution through fake websites exploits user trust by mimicking legitimate software download pages.
- Masqueraded files are frequently placed in standard directories like System32 or SysWOW64, increasing the likelihood of execution without raising suspicion.
- Security tools may overlook masqueraded malware due to its resemblance to benign system components.
- Attackers use misleading icons and file names to trick users into executing malicious payloads that appear harmless.

## 5. Research Synthesis

### Executive Summary
Adversaries are leveraging masquerading (T1036) by creating a fake Corepack site to distribute infostealer and proxyware, exploiting the trust developers have in official Node.js tools. This tactic involves disguising malicious files as legitimate components, making them appear benign to both users and security systems.

### Recommended Hypothesis
> Adversaries use masquerading techniques to distribute malware disguised as trusted development tools (such as Corepack) on developer-targeted websites with the goal of compromising development environments and stealing sensitive information.

### Gaps Identified
- Current coverage lacks comprehensive monitoring for unexpected file types and changes in file attributes that could indicate masquerading attempts within development-specific directories like node_modules or project root folders.

### Key Findings
- Hypothesis: Adversaries use masquerading techniques to distribute malware disguised as trusted development tools (such as Corepack) on developer-targeted websites with the goal of compromising development environments and stealing sensitive information.
- Gap: Current coverage lacks comprehensive monitoring for unexpected file types and changes in file attributes that could indicate masquerading attempts within development-specific directories like node_modules or project root folders.
- Focus: Enhance detection capabilities by focusing on telemetry related to file_name, process_path, and file_extension in environments where developers manage dependencies with tools such as npm and Corepack.
