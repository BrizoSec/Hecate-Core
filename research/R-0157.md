## 1. System Research: How It Works

### Summary
DEV#POPPER is a remote access Trojan (RAT) that infects systems through compromised npm repositories. After infection, it establishes a command-and-control channel to allow attackers to remotely control the victim's machine and steal data.

### Key Findings
- DEV#POPPER uses npm repository compromises as an initial vector for distribution.
- The malware employs obfuscation techniques such as string shuffling to evade detection.
- Establishes a command-and-control channel post-compromise to facilitate remote access.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries compromised two npm packages by introducing a fake runtime dependency that automatically executes malicious code upon installation, allowing them to deliver the DEV#POPPER Remote Access Trojan (RAT) and potentially exfiltrate credentials and manage remote systems.

### Key Findings
- Attackers exploited supply chain vulnerabilities in npm packages to introduce a fake 'plain-crypto-js' dependency which automatically runs malicious scripts during package installation without user interaction.
- The compromised npm packages were used to deliver the DEV#POPPER RAT, capable of establishing remote access and potentially exfiltrating sensitive data such as credentials from affected systems.
- This attack highlights the importance of continuous monitoring and validation of dependencies in software supply chains to detect and mitigate such threats early.
- Indicators of compromise (IoCs) include unexpected network connections established by npm packages after installation, unusual activity related to credential harvesting, and attempts at remote system management.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry for detecting the delivery of DEV#POPPER RAT via compromised npm packages would include logs from package managers, network traffic related to npm registry requests, process monitoring on endpoints that install these packages, and outbound connections indicative of C2 activity. The goal is to identify anomalous behavior such as unusual npm package installation patterns or unexpected communication with unfamiliar IP addresses or domains.

### Key Fields
- process_creation (highly populated): Logs capturing the creation of new processes related to the execution of compromised npm packages would help in identifying the moment when malware starts running on endpoints. This includes process names and command line arguments.
- file_create (moderately populated): Logging file creation events can reveal if malicious files are being written by compromised npm scripts or binaries, such as DLLs or executables associated with DEV#POPPER RAT.
- dns_request (highly populated): DNS request logs will be crucial for identifying connections to suspicious domains or IP addresses used by the malware for command and control communications. This helps in correlating network activity with known malicious infrastructure.
- network_connection (moderately populated): Outbound network connection logs from endpoints running compromised npm packages can help track the communication patterns of DEV#POPPER RAT, especially if it establishes persistent connections or sends data to remote servers.
- registry_key_opened (low-to-moderate population): Monitoring registry changes related to malware persistence mechanisms such as adding registry keys for autorun at system startup would be essential. This helps in identifying how the malware maintains presence on compromised systems.

## 5. Research Synthesis

### Executive Summary
Adversaries have compromised two npm packages to deliver the DEV#POPPER Remote Access Trojan, which establishes a command-and-control channel for remote access and data exfiltration. This highlights the critical need for continuous monitoring of software supply chains and dependency validation.

### Recommended Hypothesis
> Adversaries use compromised npm package dependencies to automatically execute malicious scripts upon installation in order to distribute DEV#POPPER Remote Access Trojan and facilitate remote access and data exfiltration on targeted systems.

### Gaps Identified
- Current monitoring solutions may not adequately detect or respond to obfuscation techniques used by DEV#POPPER, such as string shuffling, which can evade initial detection mechanisms.
- There is a lack of visibility into the supply chain integrity of npm packages and how they are managed, making it difficult to proactively identify compromised dependencies before they are installed on endpoints.

### Key Findings
- Hypothesis: Adversaries use compromised npm package dependencies to automatically execute malicious scripts upon installation in order to distribute DEV#POPPER Remote Access Trojan and facilitate remote access and data exfiltration on targeted systems.
- Gap: Current monitoring solutions may not adequately detect or respond to obfuscation techniques used by DEV#POPPER, such as string shuffling, which can evade initial detection mechanisms.
- Gap: There is a lack of visibility into the supply chain integrity of npm packages and how they are managed, making it difficult to proactively identify compromised dependencies before they are installed on endpoints.
- Focus: Enhance continuous monitoring and validation of software dependencies in the npm ecosystem to quickly detect anomalies indicative of package compromise or malicious activity.
- Focus: Develop and implement detection rules for identifying obfuscation techniques employed by DEV#POPPER, such as string shuffling, to improve early warning systems.
