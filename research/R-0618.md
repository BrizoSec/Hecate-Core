## 1. System Research: How It Works

### Summary
Endpoint sensors and network monitors would detect the installation of Radmin and UltraVNC via compressed payloads downloaded from known IP and domain infrastructure, followed by execution of PowerShell scripts that deploy additional proxy tools such as Netch-gateway and CCProxy. These compromised systems then establish outbound connections to C2 domains and serve as proxy nodes, indicating lateral movement and infrastructure abuse.

### Key Findings
- The initial payload is delivered via a compressed file (e.g., .zip) containing batch scripts, a REG file, and Radmin, downloaded from http://103.86.86.244:800/Gateway/r.Zip, which triggers execution of remote administration tools.
- PowerShell scripts (e.g., deploy.Ps1, deploy_silent1.Ps1) are used to automate deployment, with evidence of Chinese-language comments and tools associated with Chinese-speaking actors, suggesting operational bias.
- Post-exploitation, systems deploy Netch-gateway and CCProxy, with configuration files referencing domains like www.sheng886.top, which resolve to Chinese-language proxy service pages, indicating proxy node registration and configuration.
- Network telemetry shows outbound connections to domains such as koreakr.top, tt.yeyoujs.com, and tvip.yeyoujs.com, used as C2 channels, while the IP 103.86.86.244 hosts multiple components including ag.exe, conima.exe, and ddengine64.dll.
- Malware files exhibit consistent hash indicators (e.g., MD5: 02153f3fbb3611bc8b01eb347bf86c5a, SHA256: 6413f8681087402683d64074a7ff58d4f555566edb7a404634190c92b071a080), which can be used to detect the presence of the malware family across endpoints.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries targeting Korean systems have been observed deploying Radmin and UltraVNC for remote access, followed by installation of proxy tools like Netch-gateway and CCProxy, and in recent variants, SoftEther VPN, to repurpose compromised systems as proxy nodes. These campaigns involve downloading malicious payloads via HTTP servers and using PowerShell scripts, some containing Chinese-language comments, suggesting possible ties to Chinese-speaking actors.

### Key Findings
- The initial intrusion vector remains unknown, but attackers distribute compressed files containing batch scripts, REG files, and Radmin, indicating a delivery mechanism likely involving social engineering or exploit chains.
- Post-compromise, adversaries deploy UltraVNC alongside proxy tools such as Netch-gateway and CCProxy, and in newer variants, SoftEther VPN, to establish infrastructure for proxy services and maintain persistence.
- Malicious payloads are hosted on HTTP servers, including the IP 103.86.86.244:800, with URLs such as http://103.86.86.244:800/Gateway/r.Zip and http://103.86.86.244:800/V/deploy.Ps1, suggesting a distributed delivery infrastructure.
- Indicators include multiple file hashes (MD5, SHA1, SHA256), domains (koreakr.top, tvip.yeyoujs.com, tt.yeyoujs.com), and a hostname (www.sheng886.top), with the latter resolving to a Chinese-language proxy service page, indicating possible operator localization.
- PowerShell scripts with Chinese-language comments and tools commonly used by Chinese-speaking actors are present, leading to an attribution suggestion to Chinese threat operators, though the adversary remains officially unknown.
- The campaign leverages common persistence and execution techniques, such as registry modifications (implied by REG file use) and hidden execution via scripts, aligning with MITRE ATT&CK techniques like T1012 (Query Registry) and T1059 (Command and Scripting Interpreter).

## 5. Research Synthesis

### Executive Summary
Adversaries deploy Radmin and UltraVNC via compressed payloads from a known C2 infrastructure (103.86.86.244:800), followed by automated execution of PowerShell scripts with Chinese-language comments to install proxy tools (Netch-gateway, CCProxy) and in recent variants, SoftEther VPN, repurposing compromised systems as proxy nodes. This behavior is characterized by staged execution, registry modifications, and outbound connections to C2 domains, enabling persistent access and infrastructure abuse.

### Recommended Hypothesis
> Adversaries use staged execution of batch scripts and PowerShell payloads, hosted on HTTP infrastructure (103.86.86.244:800), to deploy Radmin and UltraVNC, followed by installation of proxy tools (Netch-gateway, CCProxy, SoftEther VPN) to repurpose compromised endpoints as proxy nodes on Korean-targeted infrastructure.

### Gaps Identified
- Lack of telemetry mapping for registry key modifications (e.g., HKLM\Software\Microsoft\Windows\CurrentVersion\Run) triggered by batch scripts during initial payload execution, which may obscure early-stage persistence mechanisms.
- Absence of detection for outbound DNS queries to C2 hostnames (tt.yeyoujs.com, tvip.yeyoujs.com, www.sheng886.top) when resolved via non-standard ports (e.g., port 800), as many network monitoring systems do not correlate non-HTTP DNS traffic with malicious domains.

### Key Findings
- Hypothesis: Adversaries use staged execution of batch scripts and PowerShell payloads, hosted on HTTP infrastructure (103.86.86.244:800), to deploy Radmin and UltraVNC, followed by installation of proxy tools (Netch-gateway, CCProxy, SoftEther VPN) to repurpose compromised endpoints as proxy nodes on Korean-targeted infrastructure.
- Gap: Lack of telemetry mapping for registry key modifications (e.g., HKLM\Software\Microsoft\Windows\CurrentVersion\Run) triggered by batch scripts during initial payload execution, which may obscure early-stage persistence mechanisms.
- Gap: Absence of detection for outbound DNS queries to C2 hostnames (tt.yeyoujs.com, tvip.yeyoujs.com, www.sheng886.top) when resolved via non-standard ports (e.g., port 800), as many network monitoring systems do not correlate non-HTTP DNS traffic with malicious domains.
- Focus: Implement detection rules for PowerShell execution of .Ps1 files from non-standard paths (e.g., /V/, /Gateway/) with known malicious hashes, especially those containing Chinese-language comments or invoking network configuration tools.
- Focus: Enhance network telemetry to monitor for outbound HTTP-like traffic on non-standard ports (e.g., port 800) to known malicious IPs (103.86.86.244) with file paths matching known malware distribution patterns (e.g., /c/config.example.json, /gateway/ag.exe).
- Focus: Correlate file creation events (e.g., conima.exe, ddengine64.dll) in temporary or non-standard directories with subsequent execution of proxy-related processes (Netch-gateway, SoftEther VPN) to identify proxy node deployment behavior.
