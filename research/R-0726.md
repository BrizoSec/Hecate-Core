## 1. System Research: How It Works

### Summary
VectraRAT functions as a Malware-as-a-Service platform consisting of a Go-based control server (VectraHub) and a native C++ Windows implant that communicates via a proprietary binary TCP protocol over port 3308. The system utilizes a dynamic Command and Control address resolution mechanism through _callback.json_ in the %TEMP% directory, allowing for remote infrastructure updates without redistributing the malware binary.

### Key Findings
- The malware employs a native C++ Windows implant that communicates with the Go-based VectraHub control server using a proprietary binary TCP protocol on port 3308.
- Operational persistence and connectivity are maintained by dynamically updating the C2 address via _callback.json_ located in the %TEMP% directory, enabling the hub to overwrite embedded addresses without binary redistribution.
- The platform includes an operator panel built with Vue3 compiled directly into the binary, facilitating hidden-desktop control, keylogging, clipboard hijacking with cryptocurrency replacement, and browser credential theft.
- The implant features a UAC bypass capability that achieves system elevation without generating user prompts, distinguishing it from standard privilege escalation behaviors.

## 5. Research Synthesis

### Executive Summary
VectraRAT represents a novel, full-stack Malware-as-a-Service platform utilizing a Go-based C2 server (VectraHub) and a native C++ Windows implant communicating via a proprietary binary TCP protocol on port 3308. The threat is characterized by dynamic infrastructure evolution through remote JSON configuration updates and advanced persistence mechanisms like prompt-less UAC bypass, delivered primarily via spearphishing links targeting corporate environments.

### Recommended Hypothesis
> Adversaries use spearphishing links delivering a ClickFix payload to execute a native C++ implant that establishes communication with a Go-based C2 server over port 3308 to achieve privilege escalation and credential theft on Windows systems.

### Gaps Identified
- Detection is hindered by the proprietary MessagePack-over-TCP protocol on non-standard port 3308, which likely evades standard HTTP/HTTPS inspection and signature-based network monitoring.
- The dynamic C2 address resolution via remote overwriting of %TEMP%\callback.json allows the adversary to change infrastructure without binary redistribution, bypassing static IOCs and file integrity monitoring focused on the executable itself.

### Key Findings
- Hypothesis: Adversaries use spearphishing links delivering a ClickFix payload to execute a native C++ implant that establishes communication with a Go-based C2 server over port 3308 to achieve privilege escalation and credential theft on Windows systems.
- Gap: Detection is hindered by the proprietary MessagePack-over-TCP protocol on non-standard port 3308, which likely evades standard HTTP/HTTPS inspection and signature-based network monitoring.
- Gap: The dynamic C2 address resolution via remote overwriting of %TEMP%\callback.json allows the adversary to change infrastructure without binary redistribution, bypassing static IOCs and file integrity monitoring focused on the executable itself.
- Focus: Monitor for anomalous outbound TCP connections on port 3308 originating from user profiles or TEMP directories, specifically looking for high-frequency small-packet exchanges indicative of binary protocol communication.
- Focus: Implement behavioral detection for prompt-less UAC bypass techniques and monitor for the creation/modification of callback.json files in %TEMP% by processes attempting to establish persistent C2 channels.
