## 1. System Research: How It Works

### Summary
Kerberoasting is a technique used by attackers to extract NTLM hashes from Active Directory domains, which can then be cracked offline to gain access to sensitive resources. It leverages Service Principal Names (SPNs) enumeration and Ticket-Granting Service (TGS) ticket requests in Kerberos authentication protocol.

### Key Findings
- Normal behavior involves the Kerberos client requesting a TGS service ticket for a specific SPN, which is then issued by the Key Distribution Center (KDC).
- Each SPN on a domain controller has an associated key derived from the account password of the corresponding service account.
- Attackers can enumerate all possible SPNs for a user to find weakly protected services and request TGS tickets, potentially revealing the user's NTLM hash.
- The attacker can then use the obtained NTLM hash in an offline attack to crack the password of the associated domain account.
- Kerberos is designed to provide secure authentication within a network, but its design principles and implementation can unintentionally expose sensitive information if not properly configured or managed.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit Kerberoasting via SPN enumeration and TGS ticket requests (T1558.003) by abusing the Kerberos authentication protocol's Service Principal Name (SPN) feature to extract NTLM hashes of high-value domain accounts, which can be used offline for pass-the-hash attacks.

### Key Findings
- Attackers enumerate SPNs for services linked to high-value domain accounts using tools like Mimikatz or PowerSpaces, gathering a list of potential NTLM hashes.
- Adversaries then request Ticket-Granting Service (TGS) tickets for these services, triggering the Kerberos protocol to return encrypted TGS tickets containing the victim's NTLM hash.
- The attackers can extract the NTLM hash from the TGS ticket using various methods, such as replaying the request or decrypting the ticket offline with tools like Mimikatz or John The Ripper.
- Indicators of compromise (IOCs) for this technique may include unusual SPN enumeration events, multiple failed TGS ticket requests targeting specific services, and suspicious NTLM hashes in log files or memory dumps.
- Defensive measures against Kerberoasting include restricting the use of SPNs, limiting the number of service principals per account, implementing strong password policies, and monitoring for abnormal Kerberos activity.
