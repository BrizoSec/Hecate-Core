## 1. System Research: How It Works

### Summary
Settra ransomware is a variant observed in mid-2026 that typically gains initial access via compromised credentials or VPNs and establishes persistence through the deployment of MeshAgent Remote Monitoring and Management (RMM) tools. The malicious activity involves encrypting files with specific extensions, disabling Windows recovery environments, and attempting to clear event logs to inhibit incident response and data recovery.

### Key Findings
- The ransomware executable is consistently named after the victim organization's domain appended with '_win64.exe' (e.g., 'domain_win64.exe').
- Attackers deploy MeshAgent RMM for persistence, utilizing distinct Command-and-Control IP addresses in different incidents: 45.13.122[.]7 and 193.5.65[.]114.
- File encryption results in two observed extensions: '.locked' and '.locked_wip', accompanied by a ransom note named 'RESTORE_FILES.txt'.
- Recovery inhibition tactics include running 'reagentc /disable' to disable the Windows Recovery Environment, using 'diskpart' to remove recovery partitions, and attempting to overwrite free space with the 'cipher /w' command.
- The malware attempts to clear specific Windows Event Logs (Application, Security, System, Setup, ForwardedEvents, Terminal Services, Sysmon), but has demonstrated operational security failures by missing the Windows Defender Event Log path due to typographical errors.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The Settra ransomware variant, first observed in June 2026, targets organizations via compromised VPNs or credentials to deploy MeshAgent RMM for persistent access. Adversaries encrypt files with specific extensions, disable Windows recovery options, and attempt to clear event logs to inhibit incident response and data recovery.

### Key Findings
- Attackers deploy the MeshAgent Remote Monitoring and Management (RMM) tool for persistence, linking to C2 IPs such as 45.13.122[.]7 and 193.5.65[.]114.
- Ransomware executables are named after the victim organization's domain followed by '_win64.exe' and launched from locations like C:\Perflogs or user Documents folders.
- File encryption results in .locked or .locked_wip extensions, accompanied by the deployment of a RESTORE_FILES.txt ransom note.
- Adversaries inhibit recovery by disabling the Windows Recovery Environment via reagentc, removing partitions with diskpart, and overwriting free space using cipher /w.
- One incident involved Bring Your Own Vulnerable Driver (BYOVD) tactics using gdrv.sys to impact security tooling, while another incident featured a misspelling that prevented the deletion of Windows Defender logs.

## 5. Research Synthesis

### Executive Summary
The Settra ransomware variant employs domain-named executables and deploys MeshAgent RMM binaries (often renamed) for persistent C2 access while inhibiting recovery via reagentc, diskpart, and cipher utilities. Detection is complicated by the use of legitimate remote management tools and a specific operational security failure where attackers misspelled the Windows Defender Event Log path, leaving residual telemetry.

### Recommended Hypothesis
> Adversaries deploy renamed MeshAgent RMM binaries and domain-specific ransomware executables to establish persistent C2 access and encrypt data while inhibiting recovery via system utilities like reagentc and diskpart.

- Lack of detection for the specific log-clearing command string targeting the misspelled Windows Defender Event Log path, which serves as a high-fidelity indicator of this specific adversary's operational failure.
