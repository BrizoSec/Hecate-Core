# R-0711: The banana stand: brokering and managing infections across Asia using MQTT Research

## 1. System Research: How It Works

### Summary
BambooToken is a multiplatform malware family active since February 2023 that utilizes the MQTT protocol for covert command and control operations, leveraging a publish-subscribe architecture to hide infrastructure behind brokers. The malware primarily targets Windows and Linux systems in Asia and South America, using sideloading techniques via Tendyron's OnKey authentication software to execute malicious agents on backend servers.

### Key Findings
- The malware employs MQTT for C2 communications rather than standard HTTP, allowing for asynchronous interactions where compromised hosts subscribe to topics managed by a central broker, thereby obscuring the attacker's direct infrastructure.
- Initial access is achieved through DLL sideloading of Tendyron's 'OnKey' software (specifically OnKeySrv.exe), a legitimate authentication tool used in Chinese banking and government networks, rather than compromising the vendor's signing certificate.
- The Windows agent gathers extensive system telemetry including architecture, CPU info, memory, public IP (parsed from icanihazip.com), MAC address, and a hardcoded GUID mutex to prevent multiple instances.
- Infections have been observed on high-value backend infrastructure including GitLab instances, mobile application servers, legal/financial services, and software companies, with C2 domains ranking in Cloudflare's top 500,000 domains indicating widespread activity.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The BambooToken adversary abuses legitimate software execution flows by sideloading malicious DLLs into Tendyron's OnKey authentication utility, enabling covert command and control via the MQTT protocol. This approach allows the malware to hide infrastructure behind brokered communications while targeting Windows and Linux systems across Asia and South America for data exfiltration and surveillance.

### Key Findings
- The campaign utilizes a DLL sideloading technique (MITRE T1574) by infecting the legitimate Tendyron OnKey application, specifically exploiting the OnKeySrv.exe executable to load the malicious OnKeyToken_KEB.dll.
- BambooToken employs the Message Queueing and Telemetry Transport (MQTT) protocol for its Command and Control (C2), leveraging a publish-subscribe architecture to obscure infrastructure and allow asynchronous communication through Cloudflare proxies.
- The malware family is multi-platform, targeting both Windows and Linux systems, with initial activity dating back to February 2023 and evolving to use MQTT by 2024-2025.
- Infections have been observed on high-value backend servers including mobile application infrastructure, legal and financial services, software development companies (including GitLab instances), and hotels across Asia and South America.
- The malware maintains operational security by using Cloudflare as a proxy for C2 domains, with one domain ranking in the top 500,000 on Cloudflare Radar, indicating widespread infection capabilities.
- Capabilities include extensive host enumeration, antivirus detection plugins, keylogging, and clipboard theft, with the Windows agent extracting system details such as architecture, CPU info, memory, and public IP address.

## 5. Research Synthesis

### Executive Summary
The BambooToken threat cluster exploits DLL sideloading (T1574.001) by injecting malicious payloads into the legitimate Tendyron OnKeySrv.exe process, utilizing MQTT publish-subscribe architecture for covert command and control to obscure infrastructure behind brokers like Cloudflare. This technique allows adversaries to maintain persistent access on high-value backend servers in Asia and South America while evading standard HTTP-based detection mechanisms.

### Recommended Hypothesis
> Adversaries use DLL sideloading into legitimate OnKeySrv.exe processes and MQTT-based brokered C2 channels to establish covert persistence and data exfiltration on Windows/Linux backend infrastructure.

### Gaps Identified
- Standard endpoint telemetry often fails to detect 'living-off-the-land' DLL loads when the malicious module (OnKeyToken_KEB.dll) is loaded into a signed, legitimate process context, masking the injection from simple signature-based alerts.
- Network monitoring tools typically lack visibility into MQTT topic subscriptions and publish payloads, allowing asynchronous C2 communications to blend with legitimate IoT or telemetry traffic unless specific protocol parsing is enforced.

### Key Findings
- Hypothesis: Adversaries use DLL sideloading into legitimate OnKeySrv.exe processes and MQTT-based brokered C2 channels to establish covert persistence and data exfiltration on Windows/Linux backend infrastructure.
- Gap: Standard endpoint telemetry often fails to detect 'living-off-the-land' DLL loads when the malicious module (OnKeyToken_KEB.dll) is loaded into a signed, legitimate process context, masking the injection from simple signature-based alerts.
- Gap: Network monitoring tools typically lack visibility into MQTT topic subscriptions and publish payloads, allowing asynchronous C2 communications to blend with legitimate IoT or telemetry traffic unless specific protocol parsing is enforced.
- Focus: Monitor for module loads of unsigned or anomalous DLLs (e.g., OnKeyToken_KEB.dll) into non-standard or unexpected legitimate processes like OnKeySrv.exe, particularly in financial and government sectors.
