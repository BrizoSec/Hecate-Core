## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry capturing advanced AI-driven exploitation attempts would include network traffic anomalies (e.g., unusual outbound connections), process execution patterns that deviate from normal baselines (especially those involving known malicious binaries or scripts), and API calls indicative of automated scanning or exploitation tools. The SIEM system should monitor for these activities to detect early signs of targeted attacks before they can be fully executed.

### Key Fields
- process_creation (90% populated): Tracks the creation of new processes on endpoints, which is crucial for identifying malicious binaries being launched as part of an AI-driven attack. Look for deviations from baseline behavior, especially if the process involves known malware or unusual command-line parameters.
- network_connection (85% populated): Monitors outbound connections to identify data exfiltration attempts or communication with C2 servers that might be orchestrated by AI tools. Focus on DNS requests, HTTP/HTTPS traffic, and other protocols that could indicate reconnaissance or exploitation activity.
- api_call (70% populated): Tracks API calls made from within the environment, especially those related to automation frameworks or services often used in advanced attacks. For example, AWS S3 API calls might be monitored for unusual data movement patterns.
- file_create (82% populated): Monitors the creation of new files that could indicate malicious payloads being dropped by automated attack tools. Look for file extensions and paths that are outside normal usage patterns or known to be associated with malware.
- dns_query (78% populated): Tracks DNS queries made from endpoints, which can reveal reconnaissance activity as attackers use domain generation algorithms (DGAs) to identify potential targets or C2 servers.
- registry_change (65% populated): Monitors changes to the Windows Registry that could indicate configuration of malicious tools for persistence or privilege escalation.

## 5. Research Synthesis

### Executive Summary
CrowdStrike's 2026 Threat Hunting Report reveals that AI technology is driving adversaries to exploit vulnerabilities at an unprecedented speed, reducing the window for security teams to respond. This shift necessitates a proactive approach with advanced threat hunting and unified data protection solutions.

### Recommended Hypothesis
> Adversaries use AI-driven techniques to rapidly identify and exploit newly discovered vulnerabilities in order to evade detection by traditional security mechanisms on cloud infrastructure.

### Gaps Identified
- The current telemetry monitoring lacks the capability to detect early signs of AI-driven attacks before they can fully execute, particularly those involving novel exploitation methods or sophisticated evasion tactics.
- There is insufficient understanding of how adversaries are leveraging AI in supply chain attacks, especially within foundational AI ecosystems, which poses a significant risk to the integrity of trusted software frameworks.

### Key Findings
- Hypothesis: Adversaries use AI-driven techniques to rapidly identify and exploit newly discovered vulnerabilities in order to evade detection by traditional security mechanisms on cloud infrastructure.
- Gap: The current telemetry monitoring lacks the capability to detect early signs of AI-driven attacks before they can fully execute, particularly those involving novel exploitation methods or sophisticated evasion tactics.
- Focus: Enhancing SIEM systems with advanced analytics to identify anomalous network traffic and API calls indicative of automated scanning or data exfiltration orchestrated by AI tools.
- Gap: There is insufficient understanding of how adversaries are leveraging AI in supply chain attacks, especially within foundational AI ecosystems, which poses a significant risk to the integrity of trusted software frameworks.
- Focus: Investigating potential weaknesses in cloud services that could be exploited through automated and AI-driven attack vectors, focusing on unified data protection strategies.
