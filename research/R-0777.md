## 1. System Research: How It Works

### Summary
The OpenSUpdater malware disguises itself as a legitimate 7-Zip self-extracting archive (SFX) installer, embedding a reflective loader within the recompiled decompression stub's `ExtractArchive` function rather than in the payload files. This technique allows the malicious code to execute and beacon to command-and-control servers before or during the extraction of genuine software like foobar2000, evading standard analyst focus on configuration files and embedded executables.

### Key Findings
- The malicious reflective loader is inserted directly into the recompiled 7-Zip SFX module's `ExtractArchive` function (specifically at address 0x421400 in analyzed samples), located immediately before the progress bar initialization, a location typically overlooked by analysts focusing on configuration or payload files.
- Malware variants utilize static libraries to download components from C2 servers (e.g., codeonicinc.com) and employ a multi-stage reflective loading process: calling export 'cx1' of DLL1, then 'cx2' of DLL2 to decrypt an encrypted blob, which is then mapped to memory and executed via export 'cx3'.
- Samples exhibit suspicious triage characteristics including valid signatures from 'Animated Productions, LLC', bloated certificate data containing repeated bytes (0xB8 and 0x84), and version information consisting of random dictionary words, indicating an attempt to bypass detection or change hashes without invalidating the signature.
- The malware embeds genuine installers (such as foobar2000) within the malicious SFX or NSIS wrappers to appear legitimate, while the actual malicious activity is driven by the hidden loader in the stub rather than the extracted setup.exe file.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries distribute malware by recompiling open-source software stubs, such as the 7zip SFX module or NSIS plugins, to embed reflective loaders and C2 communication logic directly into the decompression code. This technique evades standard analysis because the malicious payload is hidden within legitimate-looking configuration markers and validly signed certificates containing bloated data.

### Key Findings
- Threat actors modify the 'ExtractArchive' function of recompiled 7zip SFX stubs to inject reflective loaders, a method difficult to detect as analysts typically focus on embedded files rather than the decompression module itself.
- Malicious samples are validly signed by 'Animated Productions, LLC' and feature bloated certificates (random bytes like 0xB8 and 0x84) to alter hashes while maintaining signature validity.
- The loader beaconing logic obtains C2 URLs via obfuscation, registers with a magic byte sequence, and downloads encrypted payloads using statically compiled curl library functions included in the stub.
- Samples often embed genuine installers for free applications (e.g., foobar2000) to appear legitimate, while version information consists of random dictionary words.
- Variants also abuse other open-source libraries, such as the NSIS plugin EmbedHtml, where malicious code triggers when specific functions are called with empty strings.
- Indicators include SHA256 hashes a7666e5aa3c6ecae0295caa7c3f49714eb561d6e1be6807cf1020b79f1902cd0 and ba38916e82c47cff6de71791f179ce762e640300d626f63429753c, and domains codeonicinc.com and setupsoftwarecenter.com.

## 5. Research Synthesis

### Executive Summary
OpenSUpdater evades detection by patching the decompression stub of recompiled open-source software (7zip SFX/NSIS) to embed a reflective loader within the `ExtractArchive` function, bypassing standard analyst focus on configuration files and embedded payloads. This technique leverages valid code signing from 'Animated Productions, LLC' with bloated certificates to maintain signature validity while altering binary hashes for evasion.

### Recommended Hypothesis
> Adversaries use reflective loading within recompiled open-source decompression stubs to execute malicious C2 communication and payload delivery on Windows endpoints while evading static analysis and signature-based detection.

### Gaps Identified
- Lack of telemetry monitoring for unusual memory allocation patterns (e.g., private executable regions) indicative of in-memory reflective DLL mapping, which allows the payload to operate without writing to disk.

### Key Findings
- Hypothesis: Adversaries use reflective loading within recompiled open-source decompression stubs to execute malicious C2 communication and payload delivery on Windows endpoints while evading static analysis and signature-based detection.
- Gap: Lack of telemetry monitoring for unusual memory allocation patterns (e.g., private executable regions) indicative of in-memory reflective DLL mapping, which allows the payload to operate without writing to disk.
- Focus: Implement behavioral analysis focused on the modification of legitimate installer stubs, specifically monitoring for `ExtractArchive` function anomalies and the use of statically compiled curl libraries within SFX modules.
- Focus: Enhance triage procedures to detect certificate bloating techniques (e.g., repeated 0xB8/0x84 bytes) and verify code signing entities against known legitimate software distributors to identify compromised or abused certificates.
