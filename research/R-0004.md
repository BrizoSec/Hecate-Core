# R-0004: APT actor observed creating hidden scheduled tasks (schtasks /create) with SYSTEM-level privileges Research

## 1. System Research: How It Works

### Summary
The Windows Task Scheduler allows administrators and system services to create scheduled tasks for various purposes, including automated maintenance and script execution. When created with SYSTEM-level privileges, these tasks can execute with high permissions and often remain undetected due to their nature as legitimate system components.

### Key Findings
- Scheduled tasks are typically used by administrators and software for periodic or event-driven execution of scripts and applications.
- Tasks created with SYSTEM-level privileges run in the security context of the Local System account, which has unrestricted access to resources on the local computer.
- Hidden scheduled tasks can be configured to not appear in standard Task Scheduler views, making them harder to detect during routine audits.


---

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse the 'schtasks /create' command to establish persistence by creating hidden scheduled tasks with SYSTEM-level privileges, which allows them to maintain access even after a reboot or system update. This method enables the execution of malicious code at predetermined intervals without being easily detected.

### Key Findings
- Adversaries use obfuscation techniques such as specifying non-obvious trigger times and task names that mimic legitimate system processes to avoid detection.
- The use of SYSTEM-level privileges through methods like token manipulation or exploiting vulnerabilities ensures elevated access, allowing the creation of tasks with full administrative rights.
- Hidden scheduled tasks often contain payloads delivered via network resources (e.g., web downloads) to update malware without direct interaction with compromised systems.
- Indicators of compromise include unusual or unexpected entries in Task Scheduler that show SYSTEM-level privileges and hidden attributes.
- Adversaries may employ PowerShell scripts alongside 'schtasks /create' commands for more sophisticated task creation and execution, blending well with normal system activities.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect APT actors creating hidden scheduled tasks with SYSTEM-level privileges, we need to capture telemetry related to Windows Security Event Logs specifically focusing on event IDs that indicate the creation or modification of scheduled tasks. Additionally, process monitoring data is essential for tracking `schtasks` command execution.

### Key Fields
- EventID:4768 (X% populated): This event indicates when a user attempts to create a new scheduled task. It captures details about the task creation, including the account used and the parameters passed.
- ProcessName:schtasks.exe (Y% populated): Monitors execution of the `schtasks` command which is commonly abused by attackers for creating or modifying scheduled tasks. Look for SYSTEM-level executions indicating high-privilege abuse.
- EventID:4902 (Z% populated): Indicates when a user changes the security settings on an object such as a scheduled task, potentially hiding its visibility.
- AccountName:System (W% populated): Tracks activities performed by the SYSTEM account which typically indicate privileged operations. Monitoring for `schtasks` commands executed under this account is critical.
