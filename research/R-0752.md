## 1. System Research: How It Works

### Summary
PolinRider compromises developer GitHub accounts to inject malicious code into development versions of packages across multiple ecosystems, leveraging Git-based collaboration as its primary spread channel rather than direct registry compromise. The malware utilizes techniques such as Git history rewriting, payload concealment in configuration and font files, and automatic execution through IDE tasks like VS Code 'folderOpen' triggers.

### Key Findings
- Infection is triggered automatically when developers open compromised repositories in integrated development environments (IDEs) via malicious `.vscode/tasks.json` configurations set to `"runOn": "folderOpen"`, or through obfuscated JavaScript executed directly from `index.php` using PHP's `shell_exec` function.
- Payloads are concealed within non-standard artifacts, specifically font files (`.woff2`) and configuration files such as `tailwind.config.js`, with hashes indicating specific malicious versions of these files.
- The campaign employs dead-drop mechanisms for staged payload delivery, utilizing Ethereum sender addresses like `0xa322E5f3D311D3080e6f0121063e9aDC2490Ef1a` and C2 infrastructure at IPs including `193.247.144.38` and `166.88.73.46`.
- Malicious code is present in unstable `dev-*` versions of the `visanduma/nova-two-factor` Packagist package (e.g., `dev-main`, `dev-nova4support`) but no stable malicious release has been identified, limiting exposure to users consuming development branches directly.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
PolinRider operators compromise developer GitHub accounts to insert malicious code into development versions of packages across ecosystems like Packagist, relying on Git-based collaboration rather than direct registry compromise. The campaign utilizes techniques such as Git history rewriting, payload concealment in configuration files, and automatic execution through IDE tasks to infect workstations and propagate through normal development workflows.

### Key Findings
- The primary spread mechanism is the compromise of developer accounts (e.g., 'LaHiRu') to inject malicious code into source repositories, with package registries serving as a secondary distribution channel for those who consume dev branches directly.
- In PHP projects, adversaries use heavily obfuscated JavaScript inserted into entry points like index.php and execute it via the shell_exec function, while maintaining persistence through .vscode/tasks.json configurations set to run on folder open.
- Payloads are concealed in non-executable files such as .woff2 font files and tailwind.config.js, leveraging Git history rewriting to deliver new malware variations without raising immediate suspicion.
- The campaign employs staged payload delivery via dead-drop mechanisms like EtherHiding and NullReceiver, with resolved C2 IP addresses including 193[.]247[.]144[.]38 and Ethereum sender address 0xa322E5f3D311D3080e6f0121063e9aDC2490Ef1a.
- The operator is linked to North Korean threat actors with a primary objective of cryptocurrency theft, targeting the visanduma/nova-two-factor Packagist package which has over 700,000 cumulative downloads.

## 5. Research Synthesis

### Executive Summary
PolinRider operators leverage compromised developer GitHub accounts to inject malicious payloads into development branches of packages like visanduma/nova-two-factor, utilizing Git history rewriting and non-standard file concealment (e.g., .woff2 fonts) to evade detection. The campaign executes code via IDE task triggers on folder open or PHP shell_exec calls, establishing persistence and staging data exfiltration through Ethereum-based dead drops and resolved C2 IPs.

### Recommended Hypothesis
> Adversaries use compromised developer Git repositories and IDE task configurations to automatically execute obfuscated JavaScript payloads upon environment initialization on targeted workstations.

### Gaps Identified
- Lack of telemetry for local process execution triggered by VS Code tasks.json 'folderOpen' events, which bypasses traditional command-line monitoring if invoked via the IDE's internal launcher.
- Inability to detect or validate the integrity of obfuscated JavaScript embedded within non-executable artifacts like .woff2 font files or tailwind.config.js during static analysis or dependency scanning.
- Network telemetry for outbound connections to Ethereum dead-drop addresses (e.g., 0xa322E5f3D311D3080e6f0121063e9aDC2490Ef1a) may be obscured by SSL/TLS inspection gaps or misidentified as legitimate blockchain traffic.

### Key Findings
- Hypothesis: Adversaries use compromised developer Git repositories and IDE task configurations to automatically execute obfuscated JavaScript payloads upon environment initialization on targeted workstations.
- Gap: Lack of telemetry for local process execution triggered by VS Code tasks.json 'folderOpen' events, which bypasses traditional command-line monitoring if invoked via the IDE's internal launcher.
- Gap: Inability to detect or validate the integrity of obfuscated JavaScript embedded within non-executable artifacts like .woff2 font files or tailwind.config.js during static analysis or dependency scanning.
- Gap: Network telemetry for outbound connections to Ethereum dead-drop addresses (e.g., 0xa322E5f3D311D3080e6f0121063e9aDC2490Ef1a) may be obscured by SSL/TLS inspection gaps or misidentified as legitimate blockchain traffic.
- Focus: Monitor for anomalous file creation or modification in .vscode/ directories with 'runOn': 'folderOpen' attributes and detect execution of shell_exec calls containing obfuscated JavaScript strings in PHP entry points.
- Focus: Correlate Git repository history rewriting events (force-pushes) in development branches with the presence of high-entropy data in non-code files (e.g., .woff2, tailwind.config.js) and subsequent outbound network connections to known C2 IPs (193.247.144.38).
