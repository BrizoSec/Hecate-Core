## 1. System Research: How It Works

### Summary
JSCeal is a JavaScript obfuscator that converts malware scripts into V8 bytecode, which makes it difficult for analysts to reverse engineer the original code. However, static deobfuscation tools like View8 can be used to convert this bytecode back into readable JavaScript, allowing researchers to uncover hidden configurations and functionalities of the malware.

### Key Findings
- JSCeal's obfuscated scripts undergo two transformations before reaching analysts: first, they are transformed into intermediate representation code, then compiled into V8 bytecode.
- Traditional source-code analysis tools cannot effectively analyze JSCeal-obfuscated scripts due to the loss of original structure and semantics during transformation.
- Static deobfuscation techniques can reveal detailed information about malware configurations by converting V8 bytecode back into JavaScript.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries often use JSCeal's V8 bytecode obfuscation to conceal malicious JavaScript from static analysis and detection tools. They leverage deobfuscation tools like MyAut2Exe to decode the bytecode without executing it, thereby avoiding behavioral detection while revealing the true nature of their payloads.

### Key Findings
- Adversaries use a variety of tools such as certutil, PowerShell scripts, copy commands, expand, and 7zip for deobfuscation tasks.
- The static constructor is modified or hooked by obfuscators to execute bytecode decoding dynamically without immediate execution.
- Detection strategies focus on identifying the specific file extensions and command-line patterns used during the deobfuscation process.
- JSCeal's compiled V8 bytecode relies heavily on the `compileMethod` function for generating native code, a critical target for both obfuscators and deobfuscation tools.
- Malware often employs additional layers of encryption or virtualization to further complicate static analysis efforts beyond simple bytecode manipulation.

## 5. Research Synthesis

### Executive Summary
JSCeal obfuscates JavaScript malware into V8 bytecode, making it difficult to analyze without deobfuscation tools like View8. Adversaries leverage this technique to avoid detection and execute malicious code.

### Recommended Hypothesis
> Adversaries use JSCeal's compiled V8 bytecode to dynamically switch between obfuscated JavaScript payloads for evading static analysis on Windows targets

### Gaps Identified
- Current detection strategies do not fully account for the dynamic execution of V8 bytecode and lack real-time monitoring of the `compileMethod` function used by JSCeal.

### Key Findings
- Hypothesis: Adversaries use JSCeal's compiled V8 bytecode to dynamically switch between obfuscated JavaScript payloads for evading static analysis on Windows targets
- Gap: Current detection strategies do not fully account for the dynamic execution of V8 bytecode and lack real-time monitoring of the `compileMethod` function used by JSCeal.
- Focus: Enhancing process_creation logs to identify anomalies in new processes related to V8 bytecode execution, improving file_event monitoring to capture modifications of obfuscated JavaScript files.
