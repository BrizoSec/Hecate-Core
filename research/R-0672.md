## 1. System Research: How It Works

### Summary
SloppyRAT is a ransomware-associated remote access tool that utilizes multi-stage ClickFix infection chains to deploy CastleLoader and CastleRAT components, eventually establishing persistence via rundll32. It employs advanced evasion techniques such as indirect system calls, junk code, and EtherHiding to resolve C2 infrastructure from the Polygon blockchain, while using certificate pinning to prevent TLS inspection.

### Key Findings
- The infection chain begins with a ClickFix lure using finger.exe to download a batch script from finger.linked4x.com, which subsequently triggers pythonw.exe to fetch and execute a Python script from stro7121.blob.core.windows.net.
- SloppyRAT resolves its Command and Control (C2) URLs dynamically using EtherHiding to query the Polygon blockchain, with fallback C2 domains including api.truesmart.org and api.telephoneip.net.
- The malware implements certificate pinning by comparing the server's TLS certificate against a hardcoded SHA256 hash during the handshake to defeat network monitoring tools like Man-in-the-Middle proxies.
- Persistence is attempted through two methods: adding a 'rundll32' entry to HKCU\Software\Microsoft\Windows\CurrentVersion\Run and performing COM hijacking by modifying HKLM\Software\Classes\CLSID\{clsid}\InprocServer32 registry keys.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
SloppyRAT is a newly identified malware family utilized by ransomware threat actors to establish initial footholds and facilitate lateral movement, distributed via sophisticated multi-stage ClickFix infection chains. The tool employs advanced evasion techniques such as EtherHiding for blockchain-based command-and-control resolution, certificate pinning, indirect system calls, and junk code to bypass security controls and analysis.

### Key Findings
- The infection chain begins with a ClickFix-style lure using finger.exe to download a batch script from the staging domain finger.linked4x.com, which subsequently invokes pythonw.exe to execute malicious Python scripts.
- SloppyRAT utilizes EtherHiding to resolve C2 URLs via the Polygon JSON-RPC protocol and implements certificate pinning to prevent TLS traffic inspection by security tools.
- The malware provides remote access capabilities through 47 built-in PowerShell-like commands and deploys CastleLoader and CastleRAT components, which are downloaded from skipraid.com using a custom User-Agent string.
- Persistence is attempted via the HKCU\Software\Microsoft\Windows\CurrentVersion\Run registry key under the name rundll32, though this mechanism contains bugs by failing to specify the DLL path correctly; COM hijacking via CLSID keys is also observed.
- The codebase exhibits numerous software bugs affecting persistence and other features, suggesting the malware is in active development, while utilizing indirect system calls and encrypted code blocks for evasion.

## 5. Research Synthesis

### Executive Summary
SloppyRAT represents a sophisticated ransomware delivery mechanism leveraging multi-stage ClickFix chains, blockchain-based C2 resolution via Polygon/EtherHiding, and certificate pinning to evade TLS inspection. Detection requires correlating anomalous process creation events (finger.exe, pythonw.exe) with specific registry modifications for persistence and network traffic exhibiting JSON-RPC interactions or known malicious domain resolutions.

### Recommended Hypothesis
> Adversaries use multi-stage ClickFix delivery chains involving finger.exe and IronPython to deploy SloppyRAT and CastleLoader components, aiming to establish persistent remote access and lateral movement capabilities while evading TLS inspection via certificate pinning.

### Gaps Identified
- Current telemetry likely lacks visibility into the specific JSON-RPC payloads required to detect EtherHiding-based C2 resolution on the Polygon blockchain, as standard network logs often mask this traffic behind encrypted HTTPS without deep packet inspection of the RPC method calls.
- The environment's file hashing and registry monitoring may miss the initial staging phase because the malware utilizes legitimate binaries (finger.exe, pythonw.exe) with dynamic command-line arguments pointing to remote storage accounts (Azure Blob) rather than direct malicious executables at execution time.
