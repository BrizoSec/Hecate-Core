## 1. System Research: How It Works

### Summary
SANDWORM_MODE refers to a sophisticated supply chain attack where automated tools are used to compromise software packages by injecting malicious code into legitimate repositories, often through the use of obfuscation techniques. This method targets both cloud service secrets and key management systems, such as Azure Key Vault and GCP Secret Manager, highlighting the importance of continuous monitoring and robust security measures.

### Key Findings
- Automated tools are used to inject malicious code into legitimate software packages within supply chains.
- The use of obfuscation techniques helps evade detection by traditional security systems.
- Compromised cloud service secrets and key management systems, like Azure Key Vault and GCP Secret Manager, are common targets.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The 'Shai-Hulud' worm exploits vulnerabilities in the npm ecosystem to conduct supply chain attacks, using AI-generated content and tools for reconnaissance. It targets developers by harvesting credentials and compromising packages within the npm registry, thereby infiltrating multiple software development environments.

### Key Findings
- Adversaries leverage AI-powered toolchains to automate and scale their reconnaissance efforts in the npm ecosystem.
- The worm's payload includes credential harvesting scripts that steal developer credentials from compromised systems.
- Compromised packages serve as vectors for further attacks, spreading the 'Shai-Hulud' worm across interconnected software supply chains.
- Detection of such threats requires continuous monitoring of npm package activity and maintaining strict security practices in software development environments.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect advanced attack behaviors related to the SANDWORM_MODE campaign and similar AI-driven supply chain threats, it's crucial to capture detailed process execution details, network communication patterns, and file system changes. This includes monitoring for unusual process creation events, suspicious API calls indicative of automation or tool deployment, and irregularities in software installation processes.

### Key Fields
- process_creation: Indicates the launch of a new process (usually high volume). Look for anomalies such as unexpected parent-child relationships, known malicious binaries being executed, or deviations from baseline behavior.
- network_connections: Tracks outbound connections to identify data exfiltration attempts or communication with command and control servers. Focus on protocols commonly used in APT activities like HTTP/HTTPS, DNS, or SMTP.
- file_creation_modification_deletion: Monitors file system changes to detect signs of malware installation or modification of legitimate executables to include backdoors or additional functionality.
- registry_key_opened: Observes registry activity for unusual modifications that might indicate the establishment of persistence mechanisms or configuration changes enabling malicious operations.
- process_injection: Tracks process injection events, which are often used by sophisticated threats to evade detection and gain deeper access within a system.

The Shai-Hulud worm leverages AI to automate reconnaissance in npm ecosystems, compromising developer credentials and spreading through compromised packages.

### Recommended Hypothesis
