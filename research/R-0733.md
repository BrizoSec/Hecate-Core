## 1. System Research: How It Works

### Summary
AlertZero functions as an agentic layer within Elastic Security that utilizes four specialized 'Watches' (Triage, Hunt, Detection, Forensics) to correlate alerts, enrich telemetry with endpoint data, and propose automated actions for human approval. From a sensor perspective, it relies on continuous ingestion of security alerts, endpoint process/activity logs, and authentication events to build attack narratives and identify anomalies like impossible travel or unsigned processes accessing browser sessions.

### Key Findings
- The system correlates authentication telemetry with endpoint activity, specifically flagging anomalies where a session identifier is reused across distant geolocations (e.g., Boston and a hosting network) without a fresh multifactor authentication (MFA) event.
- Endpoint sensors provide context for alerts by identifying unsigned processes that access browser session material, which the Forensics Watch analyzes to establish incident scope and potential persistence mechanisms.
- The Detection Watch utilizes Elasticsearch Query Language (ES|QL) to query `.alerts-security.alerts-*` indices, filtering by `kibana.alert.workflow_status == 'closed'` and `kibana.alert.workflow_reason == 'false_positive'` to identify noisy rules for tuning.
- Proposed actions, such as host isolation via Elastic Defend, are generated only after evidence-backed analysis by Triage and Forensics Workers, with all consequential actions requiring explicit human approval (manual, assisted, or supervised) before execution.

This technique bypasses traditional identity-based detection by maintaining active authentication states while masking origin via hosting networks or proxies.

### Recommended Hypothesis
