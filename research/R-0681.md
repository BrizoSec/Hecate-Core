## 1. System Research: How It Works

### Summary
Sogou Input Method utilizes a custom 'sgbiz:' protocol handler to launch the SGMyInput.exe configuration application, which in turn renders web content via an unsandboxed, outdated Chromium-based engine (SGWebRender.exe). This architecture allows arbitrary URL arguments to be passed directly into the browser view, bypassing standard security boundaries and enabling remote code execution if malicious URLs are processed.

### Key Findings
- The 'sgbiz:' custom protocol handler delegates execution to SGMyInput.exe with unvalidated command-line arguments (specifically -page=skincenter and -url), allowing attackers to inject arbitrary URLs into the application's internal webview.
- The rendering process SGWebRender.exe operates on a severely outdated, unsandboxed Chromium engine (circa 2020), lacking modern security mitigations and exposing it to known vulnerabilities like CVE-2021-38003 for code execution.
- Post-exploitation activity involves the use of a legitimate 7-Zip binary (7z.exe) as a sideloading host to encrypt an encrypted PE loader shellcode (file 'p') into p.7z within C:\Users\Public\Documents, using the CREATE_NO_WINDOW flag for stealth.
- The deployed GRAYRABBIT backdoor utilizes core.dll as its internal module and communicates with a command-and-control infrastructure hosted on mail.uaiubifas.top, with staging servers located at 8.218.50.207 (Alibaba Cloud, Hong Kong).

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversary UNC3569 exploits a critical remote code execution vulnerability (CVE-2026-51990) in Sogou Input Method by chaining unvalidated command-line injection, unrestricted CEF webview navigation, and an outdated unsandboxed Chromium engine to deploy the GRAYRABBIT backdoor with a single user click. The attack leverages CVE-2021-38003 to execute shellcode that fetches encrypted payloads from staging servers, ultimately establishing command-and-control functionality while employing anti-sandbox and self-deletion techniques.

### Key Findings
- The exploit chain targets Sogou Input Method by abusing the 'sgbiz:' custom protocol handler to inject malicious arguments (-page=skincenter -url=...) into SGMyInput.exe, which launches an unsandboxed Chromium webview (SGWebRender.exe) to trigger CVE-2021-38003.
- UNC3569 utilizes a one-click attack vector where a crafted URL redirects to a staging server (noht1ng.top / 8.218.50[.]207) hosting JavaScript that fetches and executes an encrypted PE loader shellcode in memory.
- The GRAYRABBIT backdoor employs fileless and stealthy persistence mechanisms, including sideloading via a trojanized 7-Zip DLL (7zp.dll / boy.dll), using legitimate 7z.exe to archive payloads, and self-deletion via NTFS Alternate Data Streams.
- Indicators of Compromise include SHA256 hashes for the GRAYRABBIT backdoor (d7a3c7eb...), encrypted shellcode (749160a2...), and trojanized library (29c7ee41...), alongside C2 domain mail.uaiubifas[.]top and staging IP 8.218.50[.]207.
- Although Tencent patched the primary vulnerability within twelve days of disclosure, the underlying Chromium browser engine remains outdated and unsandboxed, leaving potential for similar exploitation techniques.

## 5. Research Synthesis

### Executive Summary
Adversary UNC3569 exploits a critical remote code execution chain in Sogou Input Method via the unvalidated 'sgbiz:' protocol handler to trigger CVE-2021-38003 in an unsandboxed Chromium webview, deploying the GRAYRABBIT backdoor. The attack leverages legitimate tools like 7z.exe for payload encryption and sideloading trojanized DLLs (boy.dll) to establish persistence and command-and-control communication with staging infrastructure.

### Recommended Hypothesis
> Adversaries use unvalidated custom protocol handlers in legacy software to inject malicious URLs into unsandboxed Chromium webviews, enabling remote code execution via outdated browser engine vulnerabilities on targeted endpoints.

### Gaps Identified
- Standard EDR telemetry may fail to detect the initial exploitation phase if the 'sgbiz:' protocol handler is not explicitly monitored for argument injection, and fileless shellcode execution (749160a2...) lacks persistent disk artifacts for detection until post-exploitation packing occurs.

### Key Findings
- Hypothesis: Adversaries use unvalidated custom protocol handlers in legacy software to inject malicious URLs into unsandboxed Chromium webviews, enabling remote code execution via outdated browser engine vulnerabilities on targeted endpoints.
- Gap: Standard EDR telemetry may fail to detect the initial exploitation phase if the 'sgbiz:' protocol handler is not explicitly monitored for argument injection, and fileless shellcode execution (749160a2...) lacks persistent disk artifacts for detection until post-exploitation packing occurs.
- Focus: Implement strict command-line argument filtering for Sogou Input Method executables (SGMyInput.exe) and monitor for the creation of encrypted payload files in user-writable directories like C:\Users\Public\Documents alongside suspicious 7z.exe invocations.
- Focus: Detect DLL sideloading anomalies by identifying the loading of non-standard libraries (e.g., boy.dll/7zp.dll) within Sogou processes and monitor for network connections to known staging domains (noht1ng.top) or Alibaba Cloud IPs associated with this threat actor.
