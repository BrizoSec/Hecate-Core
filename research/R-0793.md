## 1. System Research: How It Works

### Summary
RATHat operates as an Android banking trojan where the initial malicious application serves only as a pivot point to enable wireless debugging and establish ADB shell access, allowing the deployment of a native Go service that persists outside Android's standard permission model. This infrastructure supports a Malware-as-a-Service (MaaS) operation utilizing evolving C2 panels (BlackCat, Panda Workshop V5/V6) to automate payload generation, signing, and scheduling while integrating Gemini LLMs for both dynamic UI automation on the device and financial data scoring via SMS analysis.

### Key Findings
- The malware achieves persistent shell-level control by leveraging granted Accessibility Service permissions to autonomously enable wireless debugging, pair with the local ADB daemon, and deploy a native Go service that survives app removal until reboot.
- The C2 infrastructure evolved through three distinct panel generations (BlackCat, Panda Workshop V5, and V6) between April and September 2026, with the latter featuring obfuscated frontends, operator TOTP authentication, and consolidated AI integration using Gemini models.
- The operation functions as a Malware-as-a-Service model with nearly 100 separate deployments across Europe, LATAM, and South-Eastern Asia, utilizing automated 'builders' that schedule payload regeneration to evade hash-based detection without manual operator intervention.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
RATHat is an Android banking trojan that uses Accessibility Service permissions to enable wireless debugging and deploy a native Go service via ADB, granting shell-level control outside the Android permission model. The operation employs a Malware-as-a-Service model with three evolving C2 panels (BlackCat, Panda Workshop V5/V6) that automate payload generation and use AI for banking fraud.

### Key Findings
- RATHat's architecture relies on enabling wireless debugging to pair with the local ADB daemon, deploying a native Go service and FRP client to establish a reverse tunnel that survives app removal until reboot.
- The operation utilizes three successive C2 panel generations between April and September 2026: BlackCat, followed by Panda Workshop V5 and V6, all derived from a common source codebase.
- The C2 panels function as automated malware factories that build, sign, pack, and publish APKs on fixed schedules to evade hash-based detection without operator intervention.
- AI integration is bidirectional: the malware uses Gemini to locate on-screen controls when automation fails, while the panel uses LLMs to estimate victim bank balances from collected SMS messages.
- Nearly 100 separate C2 deployments have been identified since April 2026, primarily affecting Europe, LATAM, and South-Eastern Asia, consistent with a Malware-as-a-Service model.

## 5. Research Synthesis

### Executive Summary
RATHat leverages Accessibility Service permissions to autonomously enable wireless debugging and establish a persistent ADB shell, deploying a native Go service that bypasses Android's permission model for long-term access. The associated MaaS infrastructure utilizes evolving C2 panels (BlackCat to Panda Workshop) to automate payload generation with scheduled hash evasion and integrates Gemini LLMs for dynamic UI automation and financial data extraction.

### Recommended Hypothesis
> Adversaries use Accessibility Service-driven wireless debugging to deploy a native Go service outside Android's permission sandbox, enabling persistent shell access and AI-assisted banking fraud across MaaS deployments.

### Gaps Identified
- Lack of telemetry for local ADB pairing events and wireless debugging configuration changes allows the initial persistence mechanism to go undetected on endpoint agents.
- Absence of behavioral detection for native Go binary execution in temporary directories or FRP tunnel establishment masks the core C2 channel independent of the APK's signature.

### Key Findings
- Hypothesis: Adversaries use Accessibility Service-driven wireless debugging to deploy a native Go service outside Android's permission sandbox, enabling persistent shell access and AI-assisted banking fraud across MaaS deployments.
- Gap: Lack of telemetry for local ADB pairing events and wireless debugging configuration changes allows the initial persistence mechanism to go undetected on endpoint agents.
