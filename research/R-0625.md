## 1. System Research: How It Works

### Summary
The BengalSEO operation uses a multi-stage redirection chain triggered by users clicking on SEO-poisoned search results, typically on Bing. Victims are routed through a series of redirector domains, with browser session data sent to the hCaptcha API for validation, and the resulting token used to determine the next redirect step. The system ultimately delivers malware or tech support scam payloads via domains hosted on platforms like GitHub Pages and Pages.dev, while using Matomo analytics for visitor tracking and fingerprinting.

### Key Findings
- The TDS employs a rotating network of redirector domains (e.g., ts.remdos.com, to.ghredir.com) that act as gateways, evaluating tokens generated by the hCaptcha API before issuing HTTP 302 redirects.
- Browser session data—including IP address, user agent, screen resolution, and behavioral metrics—is transmitted to the hCaptcha API as part of a validation mechanism, which is then used by the TDS to route victims.
- A Matomo analytics instance hosted at stats.us3.org is used to track and fingerprint victims, monitor campaign performance, and filter unwanted traffic, indicating integration of legitimate analytics for operational stealth.
- Payload delivery occurs through domains like insurance.ug, ustechnio.com, and tax.dll.lat, with final landing pages hosted on platforms such as github.io and pages.dev, often using Matomo for telemetry.
- C2 infrastructure for the MayaBot malware includes domains like cus.cam and dll.lat, which were registered alongside the Matomo tracking domain us3.org, suggesting coordinated infrastructure deployment.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
BengalSEO leverages aggressive Black Hat SEO techniques—such as keyword stuffing, backlink generation, and DOM injection—to manipulate search engine rankings and promote malicious lure pages disguised as legitimate technical support sites. These pages redirect victims through a rotating Traffic Distribution System (TDS) using domains hosted on platforms like GitHub.io and pages.dev, while Matomo analytics track and fingerprint users to refine targeting and deliver malware (MayaBot) or funnel victims into tech support scams.

### Key Findings
- BengalSEO uses a complex SEO poisoning campaign involving backlinks, DOM injection, and keyword stuffing to rank malicious lure pages at the top of search results, particularly on Bing.
- The operation employs a Traffic Distribution System (TDS) with rotating redirector domains (e.g., ts.remdos.com, to.ghredir.com) that route victims through a chain of domains before reaching final payloads or scam call centers.
- Matomo analytics are hosted at stats.us3.org and used to track visitor behavior, fingerprint users, and filter traffic, indicating sophisticated campaign monitoring and optimization.
- Malware delivery is facilitated via domains such as cus.cam, dll.lat, and us99.org, which serve as MayaBot C2 servers, while domains like insurance.ug and ustechnio.com act as payload delivery landing pages.
- Infrastructure is hosted across Cloudflare and Hostmaza, with many domains resolving to the IP 5.101.140.80 (AS42831 - UK Dedicated Servers Limited), and DNS control is established via name servers like cp1.hostmaza.co.in and hostmaza.co.in.
- The group maintains a dual infrastructure: Garage2Global develops malicious web infrastructure, while WeConnect Solutions LLC operates tech support call centers, indicating a coordinated criminal enterprise with both technical and social engineering components.

## 5. Research Synthesis

### Executive Summary
BengalSEO employs a sophisticated, multi-stage traffic distribution system leveraging black hat SEO to poison search results, routing victims through rotating redirector domains that validate client-side behavior via hCaptcha tokens before delivering payloads. The operation integrates Matomo analytics for real-time fingerprinting and campaign optimization, while using GitHub and Pages.dev for stealthy hosting of lure pages and MayaBot malware delivery via C2 domains hosted on consolidated infrastructure.

### Recommended Hypothesis
> Adversaries use rotating redirector domains with hCaptcha-based client validation and Matomo analytics fingerprinting to dynamically route victims through a multi-layered TDS, enabling precise delivery of MayaBot malware or tech support scam payloads.

### Gaps Identified
- Lack of telemetry capture for hCaptcha token validation responses and client-side behavioral metrics (e.g., screen resolution, user agent, timing) prevents detection of TDS logic flow and victim classification.
- Absence of correlation between Matomo instance usage (stats.us3.org) and known malicious redirector chains limits automated detection of campaign-specific fingerprinting patterns.

### Key Findings
- Hypothesis: Adversaries use rotating redirector domains with hCaptcha-based client validation and Matomo analytics fingerprinting to dynamically route victims through a multi-layered TDS, enabling precise delivery of MayaBot malware or tech support scam payloads.
- Gap: Lack of telemetry capture for hCaptcha token validation responses and client-side behavioral metrics (e.g., screen resolution, user agent, timing) prevents detection of TDS logic flow and victim classification.
- Gap: Absence of correlation between Matomo instance usage (stats.us3.org) and known malicious redirector chains limits automated detection of campaign-specific fingerprinting patterns.
- Focus: Instrument network and endpoint telemetry to capture and correlate hCaptcha API interaction patterns, including token generation and validation responses, across redirector domains.
- Focus: Implement behavioral analytics to detect anomalous client-side metrics (e.g., consistent screen resolution, user agent, timing) transmitted during redirector interactions, indicative of TDS automation.
- Focus: Deploy correlation rules linking Matomo analytics requests (matomo.php) from redirector domains to known C2 and payload delivery endpoints, enabling detection of campaign-wide infrastructure use.
