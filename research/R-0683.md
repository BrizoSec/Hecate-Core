## 1. System Research: How It Works

### Summary
Legitimate Remote Monitoring and Management (RMM) tools like MSP360 are designed to provide unattended remote access by registering as automatically starting Windows services and leveraging built-in functionalities to manage endpoints. Attackers exploit this trust by delivering signed installers via phishing, using the RMM agent's native capabilities to silently deploy secondary remote access channels like ScreenConnect for persistent control.

### Key Findings
- Threat actors utilize legitimate, digitally signed MSP360 RMM v2.5.0.67 installers under deceptive filenames delivered via phishing lures to establish initial footholds.
- The MSP360 agent is abused to invoke PowerShell scripts that download and silently install ConnectWise ScreenConnect, creating a redundant remote-access channel.
- Persistence is reinforced by installing both MSP360 and ScreenConnect as Windows services for automatic startup at reboot, alongside registry Run entries to launch tray components upon user logon.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries use phishing lures to deliver a legitimate, digitally signed MSP360 RMM installer that deploys ConnectWise ScreenConnect, creating redundant remote-access channels for persistent access. This dual-channel approach allows threat actors to bypass security controls and execute follow-on activities such as credential access and local data collection.

### Key Findings
- The attack chain begins with phishing lures delivering a legitimate MSP360 RMM v2.5.0.67 installer disguised under deceptive filenames.
- The compromised device establishes MSP360 services to leverage the RMM agent's ability to invoke PowerShell for downloading and silently installing ConnectWise ScreenConnect.
- Threat actors utilize the second remote administration channel (ScreenConnect) to transfer and execute additional tooling, supporting post-compromise activities like credential access.
- The intrusion leverages MITRE ATT&CK techniques including T1583.001 (Acquire Infrastructure: Domains) and T1583.006 (Acquire Infrastructure: Web Services).

## 5. Research Synthesis

### Executive Summary
Threat actors leverage legitimate, digitally signed MSP360 RMM installers delivered via phishing to silently deploy ConnectWise ScreenConnect, creating redundant remote-access channels reinforced by Windows service and registry persistence mechanisms. This dual-channel architecture allows adversaries to bypass standard security controls and execute follow-on post-compromise activities such as credential access and local data collection.

### Recommended Hypothesis
> Adversaries use legitimate MSP360 RMM agents to silently install and configure ConnectWise ScreenConnect services for redundant persistent remote access on compromised endpoints

### Gaps Identified
- Current telemetry mapping lacks visibility into the specific process command-line arguments used during silent installations and does not track file path modifications in RMM installation directories, obscuring the deployment phase of the secondary tool
- The research indicates network connections to RMM infrastructure but does not map specific hostname telemetry fields, leaving outbound C2 beacons to MSP360 or ScreenConnect endpoints undetectable by standard DNS monitoring without explicit enrichment

### Key Findings
- Hypothesis: Adversaries use legitimate MSP360 RMM agents to silently install and configure ConnectWise ScreenConnect services for redundant persistent remote access on compromised endpoints
- Gap: Current telemetry mapping lacks visibility into the specific process command-line arguments used during silent installations and does not track file path modifications in RMM installation directories, obscuring the deployment phase of the secondary tool
- Gap: The research indicates network connections to RMM infrastructure but does not map specific hostname telemetry fields, leaving outbound C2 beacons to MSP360 or ScreenConnect endpoints undetectable by standard DNS monitoring without explicit enrichment
- Focus: Detect anomalous parent-child process relationships where installers (e.g., setup.exe) spawn PowerShell scripts that download and register new Windows services for known RMM tools like ScreenConnect
- Focus: Monitor registry persistence mechanisms, specifically 'Run' keys and service creation events, for simultaneous or rapid sequential entries associated with MSP360 and ScreenConnect components
