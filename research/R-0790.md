# R-0790: Telerik UI Exploitation Leads to Webshell Install and Scanner Execution Research

**Topic:** Telerik UI Exploitation Leads to Webshell Install and Scanner Execution
**Duration:** 3.0 minutes

## 1. System Research: How It Works

### Summary
Telerik UI for ASP.NET AJAX processes asynchronous file uploads via RadAsyncUpload, which involves .NET deserialization of uploaded data within the w3wp.exe process. When unpatched against CVE-2019-18935, this mechanism allows attackers to inject malicious payloads that execute code with the privileges of the IIS worker process.

### Key Findings
- The RadAsyncUpload component's deserialization logic in Telerik UI for ASP.NET AJAX (CVE-2019-18935) enables remote code execution within the w3wp.exe process when processing unpatched file uploads.
- Attackers can inject a memory-based web shell (Godzilla-style) directly into the w3wp.exe memory by hijacking ASP.NET's VirtualPathProvider, avoiding the creation of physical .aspx files on disk.
- Post-exploitation activities include establishing reverse TCP shells to C2 servers (e.g., 206.82.6.22:80) and attempting privilege escalation to SYSTEM using Potato-family tools like SweetPotato or PrintSpoofer.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit the unpatched Telerik UI for ASP.NET AJAX deserialization vulnerability (CVE-2019-18935) to execute remote code within Windows IIS w3wp.exe processes. These campaigns demonstrate distinct post-exploitation strategies, ranging from establishing persistent access via memory-resident Godzilla web shells and privilege escalation tools to deploying Rust-based scanners for lateral reconnaissance.

### Key Findings
- Exploitation targets CVE-2019-18935 in unpatched Telerik UI for ASP.NET AJAX servers, allowing remote code execution under the context of the w3wp.exe process on Windows IIS servers.
- One attack variant installs a memory-based Godzilla web shell that operates within the w3wp.exe process without writing separate .aspx files to disk, utilizing encrypted HTTP requests and cookie-based sessions for command execution.
- Attackers employ Potato-family privilege escalation tools, specifically modified versions of SweetPotato, to elevate permissions from the IIS user context to SYSTEM by spoofing tokens via PrintSpoofer techniques.
- A second distinct campaign utilizes a Rust-based scanner that retrieves target lists from external servers and asynchronously probes 53 common WordPress installation paths to identify exposed setup pages.
- Reconnaissance findings are exfiltrated via Telegram, with the scanner reporting discovered WordPress URLs and public IP addresses as attachments named red.txt to a specific bot account.
- Primary Indicators of Compromise include IP addresses 206.82.6.22 (C2 for reverse shell), 65.98.5.158 (scanner list source), and MD5 hashes such as 0a4be0b6c650ffdcd1c22db56f1c4aec and 18fb4e070653fc9791e0e408d8cb1c8e.

## 5. Research Synthesis

### Executive Summary
Adversaries exploit CVE-2019-18935 in unpatched Telerik UI to achieve remote code execution within the w3wp.exe process, subsequently deploying memory-resident Godzilla web shells that bypass disk-based detection via ASP.NET VirtualPathProvider manipulation. Post-exploitation tradecraft includes privilege escalation using modified SweetPotato/PrintSpoofer techniques and the deployment of Rust-based scanners for lateral WordPress reconnaissance, utilizing encrypted communication channels to Telegram and custom C2 infrastructure.

### Recommended Hypothesis
> Adversaries use CVE-2019-18935 deserialization in Telerik UI to inject memory-resident Godzilla web shells and Potato-family privilege escalation tools within the w3wp.exe process on Windows IIS servers.

### Gaps Identified
- Standard endpoint detection often fails to identify in-memory web shells that do not write physical .aspx files to disk, requiring deep inspection of `VirtualPathProvider` registrations or anomalous .NET assembly loads within `w3wp.exe` memory space rather than just file system monitoring.

### Key Findings
- Hypothesis: Adversaries use CVE-2019-18935 deserialization in Telerik UI to inject memory-resident Godzilla web shells and Potato-family privilege escalation tools within the w3wp.exe process on Windows IIS servers.
- Gap: Standard endpoint detection often fails to identify in-memory web shells that do not write physical .aspx files to disk, requiring deep inspection of `VirtualPathProvider` registrations or anomalous .NET assembly loads within `w3wp.exe` memory space rather than just file system monitoring.
- Focus: Monitor for the creation and execution of `.dll` or `.exe` artifacts in non-standard web directories (e.g., C:\Users\Public\Documents\) spawned by the IIS worker process, specifically looking for command-line arguments associated with SweetPotato variants or Rust-based scanner binaries connecting to Telegram API endpoints.
