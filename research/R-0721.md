## 1. System Research: How It Works

### Summary
ARTEX is an AI-driven penetration testing tool that utilizes large language models (DeepSeek v4.1-flash, GLM-5.3, Grok 4.6) to autonomously discover and exploit vulnerabilities in financial organizations. The system operates via a two-server architecture where a primary Hong Kong-based server manages operations while a secondary IP hosts the ARTEX instance, supplemented by multiple proxy IPs for evasion.

### Key Findings
- The ARTEX infrastructure relies on a distributed two-server model consisting of a primary controller in Hong Kong and a host at IP address 38.244.50[.]120, with traffic routed through multiple proxy IP addresses to obscure origin.
- Operational artifacts exposed via open directories included Chinese-language instructions, configuration files, memory logs documenting target activity, and Claude Code session histories, indicating the use of AI coding assistants during the attack lifecycle.
- The threat actor leveraged a suite of specific AI models (DeepSeek v4.1-flash, GLM-5.3, and Grok 4.6) to autonomously execute vulnerability discovery and exploitation against South Korean financial targets for financial gain.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries utilize proxy IP addresses to route outbound command and control traffic, thereby obscuring their origin and evading IP reputation blocklists. This technique was employed by a financially motivated, likely Chinese-speaking threat actor using the AI-driven ARTEX tool to target South Korean financial institutions.

### Key Findings
- The threat actor utilized the open-source, Chinese-developed agentic penetration testing tool ARTEX to automate reconnaissance and intrusions against South Korean financial institutions.
- Multiple proxy IP addresses were identified in ARTEX configuration files to hide the origin of exploitation traffic and dodge IP reputation blocklists.
- The operator leveraged multiple large language models, specifically DeepSeek v4.1-flash, GLM-5.3, and Grok 4.6, to drive the automated attack capabilities.
- Evidence suggests the threat actor is likely Chinese-speaking and financially motivated, based on the use of Chinese-developed tools and observed Chinese-language prompts.
- Acquisition of infrastructure was conducted via Virtual Private Servers (VPS) at multiple IP addresses, supporting the proxy-based C2 architecture.
