## 1. System Research: How It Works

### Summary
NetScaler ADC and Gateway devices process standard HTTPS traffic for application delivery and user authentication, while simultaneously handling Datagram Transport Layer Security (DTLS) sessions for client connectivity. Normal operation involves serving static configuration files and legitimate client installation packages without exposing internal executable payloads to unauthenticated external requests.

### Key Findings
- Normal system behavior includes serving static assets such as '/admin_ui/common/css/ns/ui.css' and language files like '/vpn/js/rdx/core/lang/rdx_en.json.gz', which are used by threat actors for version fingerprinting rather than indicating compromise.
- The directory '/vpn/scripts/linux/' normally hosts legitimate Citrix client installation packages, but in this context, it was abused to host malicious '.deb' web shell files disguised as installer components like 'nsgclient18.deb'.
- Standard DTLS processing should not result in memory corruption; however, the vulnerability allows crafted DTLS traffic to cause memory overflow, leading to either remote code execution or denial of service.
- Legitimate unauthenticated access is restricted, whereas exploitation involves repeated requests for specific binary files from '/vpn/scripts/linux/' by rotating IP addresses, including those masked by Cloudflare WARP.
- Web shell deployment manifests as either dropped '.deb' files via DTLS exploitation or PHP web shells via a three-stage command injection chain, establishing persistence on the compromised appliance.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are actively exploiting two zero-day vulnerabilities in Citrix NetScaler devices to execute remote code and deploy web shells for persistent access. Initial reconnaissance involves fingerprinting device versions, followed by exploitation of a memory overflow vulnerability to deliver malicious .deb files or using command injection chains to drop PHP web shells.

### Key Findings
- The threat actors exploited CVE-2026-88771 (RCE via input validation failure) and CVE-2026-88772 (memory overflow in DTLS configuration), both rated with a CVSS v4.0 base score of 9.5.
- Pre-disclosure activity began on August 21, 2026, with attackers sending crafted requests to standard NetScaler UI and language files to fingerprint device versions before launching exploits.
- Attackers utilized a DTLS exploitation method that caused memory corruption, leading to the deployment of .deb web shell files within the /vpn/scripts/linux/ directory, which is normally used for Citrix client installation packages.
- A separate three-stage command injection exploit chain was observed that resulted in the delivery of PHP web shells, indicating diverse post-exploitation capabilities.
- The threat actor rotated infrastructure frequently, using a mix of VPSs and Cloudflare WARP VPN addresses to mask their origin during the exploitation phase between September 4 and 24, 2026.

## 5. Research Synthesis

### Executive Summary
Adversaries are actively exploiting unpatched NetScaler ADC and Gateway devices via CVE-2026-88771 and CVE-2026-88772 to establish persistent access through .deb and PHP web shells. Detection must focus on anomalous DTLS memory overflow patterns, specific HTTP fingerprinting requests for version detection, and unauthorized file writes within the /vpn/scripts/linux/ directory.

### Recommended Hypothesis
> Adversaries use crafted DTLS traffic and command injection chains to execute remote code and deploy web shells in /vpn/scripts/linux/ to establish persistent initial access on NetScaler ADC/Gateway devices.

### Gaps Identified
- Standard network monitoring may fail to detect the initial exploitation due to the encrypted nature of DTLS payloads, requiring deep packet inspection or endpoint-level memory corruption telemetry to identify the overflow activity.
- Lack of file integrity monitoring or process execution logging for the /vpn/scripts/linux/ directory allows attackers to drop malicious .deb web shells disguised as legitimate client installers without triggering alerts on binary creation.

### Key Findings
- Hypothesis: Adversaries use crafted DTLS traffic and command injection chains to execute remote code and deploy web shells in /vpn/scripts/linux/ to establish persistent initial access on NetScaler ADC/Gateway devices.
- Gap: Standard network monitoring may fail to detect the initial exploitation due to the encrypted nature of DTLS payloads, requiring deep packet inspection or endpoint-level memory corruption telemetry to identify the overflow activity.
- Gap: Lack of file integrity monitoring or process execution logging for the /vpn/scripts/linux/ directory allows attackers to drop malicious .deb web shells disguised as legitimate client installers without triggering alerts on binary creation.
- Focus: Monitor for HTTP GET requests targeting /admin_ui/common/css/ns/ui.css and /vpn/js/rdx/core/lang/rdx_en.json.gz as indicators of pre-exploitation version fingerprinting.
