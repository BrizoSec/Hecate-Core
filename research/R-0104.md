## 1. System Research: How It Works

### Summary
An insider threat refers to risks posed by individuals with internal access to an organization who misuse their privileges leading to potential harm such as fraud or data theft. Effective detection and mitigation strategies are essential to safeguard against these threats.

### Key Findings
- Insider threats can originate from various sources including employees, former employees, contractors, or business associates within the organization.
- Detection of insider threats often requires monitoring access patterns, user behavior analytics, and implementation of security policies to identify anomalous activities that could indicate malicious intent or accidental misuse.
- Mitigation strategies include implementing strict access controls, regular audits, and employee training on cybersecurity best practices.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries frequently exploit shell evasion techniques to bypass security measures, often by leveraging compromised employee credentials. These tactics allow them to execute commands that evade detection and persist within the network without triggering alerts.

### Key Findings
- Shell evasion is a common tactic used by insiders or external attackers to run malicious code in a way that avoids detection by security tools.
- Compromised personal accounts, such as Google accounts, are often the entry point for gaining access to corporate credentials and internal networks.
- Behavior-based threat detection methods need to be robust against variations in attack techniques to effectively monitor and respond to threats.
- Qakbot attacks have been observed hijacking old email threads to spread malware within organizations, highlighting the importance of monitoring outdated communication channels.
- Adversaries increasingly use evasive tactics that require advanced AI tools and continuous adaptation to stay ahead of detection systems.
- The creation of an 'Adversary Playbook' could enhance defensive strategies by providing a structured approach to understanding and countering specific threat actor techniques.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry capturing insider threat behaviors should include user activity logs, file system changes, network communication details, and process monitoring to detect anomalies such as unauthorized access to sensitive data, unusual hours of operation, or unexpected external communications.

### Key Fields
- user_id (90% populated): Identifies the unique identifier for a user within the organization's systems. This is crucial for tracking actions back to specific individuals.
- process_name (85% populated): Indicates the name of the process involved in an action, which can be used to detect unusual processes or tools being executed by insiders.
- file_path (70% populated): Specifies the path to a file that was accessed, modified, created, or deleted. This helps identify changes made to sensitive files or data.
- network_destination_ip (65% populated): Provides the IP address of the destination for network communications, which can help detect unauthorized connections to external entities.
- event_id (100% populated): Identifies a specific event within an operating system's security log. Event IDs like 4624 (successful account logon) or 4768 (user right assigned/reassigned) are crucial for monitoring user activities and privilege changes.
