## 1. System Research: How It Works

### Summary
CARBONATO is a Docker-based botnet that exploits unauthenticated Docker daemons on port 2375 to deploy a privileged container, which then installs the Hermes Agent framework and overwrites its persona file to enable autonomous command execution via Telegram. The system prioritizes the theft of AI API keys for operator profit and maintains persistence through multiple host-level hooks while mimicking legitimate Linux infrastructure processes.

### Key Findings
- Infection occurs by targeting exposed Docker daemons on port 2375, where attackers use the daemon API to create privileged containers with mounted host filesystems and access to host process/network namespaces for lateral movement.
- The implant installs the open-source Hermes Agent framework unchanged but modifies the SOUL.md persona file to instruct the agent (named GH0ST) to execute Telegram-based commands and prioritize exfiltrating AI provider API keys over other credentials.
- Persistence is maintained through immutable hooks in cron, systemd timers, rc.local, and OpenRC, supplemented by watchdog scripts that monitor for container removal and re-pull the implant from a public Docker registry.
- The botnet conceals its presence by running inside a container named systemd-resolved, displaying fake systemd-networkd resolver banners, and mimicking kernel thread process arguments to blend in during quick process reviews.
- Communication is established via reverse SSH tunnels to relays (e.g., in Costa Rica) using deterministic ports derived from the victim's IP MD5 hash, with deployment reports sent to Telegram in voseo Spanish.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
CARBONATO is a botnet that exploits unauthenticated Docker daemons on port 2375 to deploy privileged containers, establish persistence, and hijack hosts for autonomous command execution. The operation centers on the Hermes Agent framework, which has been modified with a malicious persona to prioritize the theft of AI API keys and execute tasks via Telegram.

### Key Findings
- The infection vector is an unauthenticated Docker API exposed on port 2375, allowing attackers to launch privileged containers with host filesystem access to escape and control the underlying server.
- The botnet utilizes the open-source Hermes Agent framework, overwriting its 'SOUL.md' persona file with instructions that direct the AI to act as a post-exploitation tool prioritizing AI API key theft over other credentials.
- Command and control is managed via Telegram, where operators send tasks to compromised hosts; deployment reports are sent in voseo Spanish, suggesting operator origins in Central or South America.
- The infrastructure relies on an exposed Docker registry (found on port 5000) that serves as both the distribution source for malware and the update server for the fleet, with activity documented from October 2024 through August 2026.
- Persistence is maintained through a combination of reverse SSH tunnels to a relay in Costa Rica, immutable persistence hooks (cron, systemd timers), and watchdogs that re-pull the implant if it is removed.

## 5. Research Synthesis

### Executive Summary
CARBONATO exploits unauthenticated Docker daemons on port 2375 to deploy privileged containers that mount the host filesystem, enabling kernel-level persistence and lateral movement. The operation leverages a modified Hermes Agent framework with a malicious 'SOUL.md' persona to autonomously execute Telegram-based commands, prioritizing the exfiltration of AI API keys while masking its presence by mimicking legitimate systemd processes.

### Recommended Hypothesis
> Adversaries use unauthenticated Docker API calls to spawn privileged containers with host filesystem mounts to establish persistent access and harvest AI credentials via a modified Hermes Agent framework on [compromised hosts with exposed port 2375]

### Gaps Identified
- Lack of visibility into the 'SOUL.md' persona content within container layers prevents detection of specific malicious intent (e.g., AI key theft priorities) despite the underlying open-source agent being benign.
- Absence of telemetry correlating reverse SSH tunnel port generation with MD5 hashes of victim IPs makes it difficult to distinguish deterministic C2 connections from legitimate traffic without external IP reputation data.

### Key Findings
- Hypothesis: Adversaries use unauthenticated Docker API calls to spawn privileged containers with host filesystem mounts to establish persistent access and harvest AI credentials via a modified Hermes Agent framework on [compromised hosts with exposed port 2375]
- Gap: Lack of visibility into the 'SOUL.md' persona content within container layers prevents detection of specific malicious intent (e.g., AI key theft priorities) despite the underlying open-source agent being benign.
- Gap: Absence of telemetry correlating reverse SSH tunnel port generation with MD5 hashes of victim IPs makes it difficult to distinguish deterministic C2 connections from legitimate traffic without external IP reputation data.
- Focus: Monitor for Docker API requests creating privileged containers with 'Binds' including '/:/host' or 'PidMode:host', and alert on processes mimicking 'systemd-resolved' or '[kworker/u2:0]' that are not native to the host kernel.
