## 1. System Research: How It Works

### Summary
Windows Event Log is a system component that records various events occurring on a Windows system, such as user actions, system failures, and security incidents. These logs can be accessed through the Event Viewer application or programmatically.

### Key Findings
- Normal behavior includes the automatic creation of event logs by various system components and applications.
- Events are stored in log files (.evtx) within specific folders (Applications and Services Logs, Windows Logs) based on their type (e.g., Security, System, Application).
- Event logs can be configured to have different levels of retention and rotation policies.
- System events are typically generated by the operating system or critical services, while application events are produced by installed programs.
- Administrators or users with appropriate permissions can manually create, delete, or modify event logs using the Event Viewer or other tools like PowerShell.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit Windows Event Log tampering (T1070.001) to modify or delete system event logs, concealing their activities, and evading detection. They manipulate these logs to cover up unauthorized access, data exfiltration, or malicious actions.

### Key Findings
- Adversaries may use built-in tools like 'wevtutil' for log modification or third-party utilities like 'EventCleaner'.
- They can alter event logs to change timestamps or delete entries that reveal their presence and activities.
- Some attackers manipulate Event IDs to disguise malicious events as normal system activity.
- [UNCERTAIN] Adversaries may also employ advanced techniques like DLL injection to modify the event log APIs directly.
- Unusual changes in event logs, particularly those involving security, audit failure, or system integrity can serve as potential indicators of tampering.
