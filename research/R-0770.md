# R-0770: VeloCloud Orchestrator Remote Access Vulnerability Research

**Topic:** VeloCloud Orchestrator Remote Access Vulnerability
**Duration:** 2.1 minutes

---

## 1. System Research: How It Works

### Summary
VeloCloud Orchestrator (VCO) is a centralized management platform for on-premises deployments that manages VeloCloud Edge devices using certificate-based authentication. A critical vulnerability (CVE-2026-93952/CVE-2026-16812) allows remote attackers to bypass authentication and execute arbitrary commands on the host by exploiting an unauthenticated OS command injection in a privileged backend function exposed via the web interface.

### Key Findings
- Exploitation does not require tenant or operator credentials; it relies on network access to the VCO web interface and possession of the public portion of VeloCloud Edge authentication certificates.
- Successful exploitation results in Remote Code Execution (RCE), compromising the confidentiality, integrity, and availability of both the orchestrator host and managed data.
- The vulnerability affects specific on-premises software versions: 5.2.3.15 and below, 6.1.3.7 and below, 6.4.2.7 and below, and 7.0.0.2 and below; hosted/dedicated versions were already patched.
- Indicators of Compromise include suspicious HTTP headers referencing local/internal services, high request rates, and connections from malicious IPs such as 142.93.149.77 and 104.248.126.159.
- Malicious files associated with the exploitation activity include '/usr/local/sbin/.vcnode.js', '/usr/local/sbin/vc-sysmond', and '/etc/systemd/system/vc-sysmon.service'.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are actively exploiting a critical zero-day vulnerability (CVE-2026-16812, referenced as CVE-2026-93952 in vendor advisories) in Arista VeloCloud Orchestrator (VCO) on-premises deployments. This unauthenticated command injection flaw allows remote attackers to execute arbitrary commands and gain privileged access without requiring specific configuration or tenant credentials, solely by having network access to the VCO web interface.

### Key Findings
- The vulnerability is a maximum-severity command injection flaw (CVSS 10.0) affecting VCO on-prem versions 5.2.3.15 and below, 6.1.3.7 and below, 6.4.2.7 and below, and 7.0.0.2 and below; hosted/dedicated versions were patched prior to public disclosure.
- Exploitation requires only network access to the VCO web interface and does not necessitate tenant/operator credentials, though it typically relies on certificate-based authentication configurations from VeloCloud Edge being active.
- Indicators of Compromise (IOCs) include malicious files such as /usr/local/sbin/.vcnode.js, /usr/local/sbin/vc-sysmond, and /etc/systemd/system/vc-sysmon.service, along with the MD5 hash dc78e206eaeadec59fc5801fe4556bd0.
- Attackers have been observed connecting from specific IP addresses, including 142.93.149.77 and 104.248.126.159, and operators are advised to review web access logs for unusual URL paths, encoded characters, or high request rates.
- Successful exploitation compromises the confidentiality, integrity, and availability of the orchestrator host and managed data, potentially allowing lateral movement to VeloCloud Edge devices, necessitating credential rotation and system restoration from trusted sources.

## 5. Research Synthesis

### Executive Summary
Active exploitation of CVE-2026-93952 allows unauthenticated remote code execution on VeloCloud Orchestrator (VCO) by bypassing certificate-based authentication checks in on-premises deployments. Adversaries leverage this flaw to deploy persistent backdoors, specifically the vc-sysmond daemon and associated systemd service, while establishing C2 communications via specific external IP addresses.

### Recommended Hypothesis
> Adversaries use unauthenticated OS command injection in the VeloCloud Orchestrator web interface to achieve remote code execution and establish persistent backdoors on the orchestrator host for lateral movement to managed Edge devices.

### Gaps Identified
- Lack of visibility into the specific internal API endpoints or HTTP headers triggering the authentication bypass, as VCO web access logs may not capture the raw request payloads required to identify the injection vectors (e.g., encoded characters in URL paths).
- Absence of host-based telemetry monitoring for file integrity changes in /usr/local/sbin/ and /etc/systemd/system/ directories, specifically targeting the creation of .vcnode.js or vc-sysmond binaries and the registration of vc-sysmon.service.

### Key Findings
- Hypothesis: Adversaries use unauthenticated OS command injection in the VeloCloud Orchestrator web interface to achieve remote code execution and establish persistent backdoors on the orchestrator host for lateral movement to managed Edge devices.
- Gap: Lack of visibility into the specific internal API endpoints or HTTP headers triggering the authentication bypass, as VCO web access logs may not capture the raw request payloads required to identify the injection vectors (e.g., encoded characters in URL paths).
- Gap: Absence of host-based telemetry monitoring for file integrity changes in /usr/local/sbin/ and /etc/systemd/system/ directories, specifically targeting the creation of .vcnode.js or vc-sysmond binaries and the registration of vc-sysmon.service.
- Focus: Correlate network logs with external IP addresses 142.93.149.77 and 104.248.126.159 against VCO web interface access logs to identify anomalous connection patterns or high-frequency requests indicative of exploitation attempts.
- Focus: Deploy host-based detection rules monitoring for the execution or creation of suspicious binaries (vc-sysmond, .vcnode.js) and abnormal systemd service registrations on any system acting as a VeloCloud Orchestrator instance.
