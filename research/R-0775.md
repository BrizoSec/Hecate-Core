## 1. System Research: How It Works

### Summary
TASK#STOMP is a PowerShell-based backdoor that establishes persistence via VBScript, scheduled tasks, and startup folder entries to launch hidden PowerShell payloads. It continuously scans fixed drives for business documents and archives, utilizing filesystem watchers for real-time collection and C helpers to bypass TLS validation for data exfiltration.

### Key Findings
- Persistence is maintained through four rotating scheduled tasks created from XML files under LOCALAPPDATA and the deployment of msdiag.vbs in the user's Startup folder.
- The malware stages payloads in a 'WinDefendSvc' directory, decoding Base64-encoded DAT files (diagpack.dat and winconncfg.dat) to execute hidden PowerShell scripts that terminate older instances.
- Document collection targets Word, PDF, PowerPoint, Excel, and archive files modified within the last 365 days, excluding those larger than 500 MB, while also monitoring for new or changed files in real-time.
- Network communications utilize compiled C helpers to disable TLS certificate validation, allowing connections to command-and-control domains corecloudfileshare.xyz and attachmentsharingdrive.xyz even with invalid certificates.
- Surveillance capabilities include capturing screenshots, stealing saved Wi-Fi passwords and clipboard contents, and executing arbitrary PowerShell commands via remote operators.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
TASK#STOMP is a sophisticated PowerShell-based backdoor that establishes persistence via VBScript, scheduled tasks, and startup folder entries to maintain remote access. It primarily targets business documents by scanning fixed drives for specific file types modified within the last year and exfiltrating them to C2 servers while bypassing TLS validation.

### Key Findings
- The malware uses a dual-payload architecture with `sysloader.ps1` and `winconn.ps1` that decode Base64-encoded DAT files (`diagpack.dat`, `winconncfg.dat`) to execute in memory, supported by compiled C# helpers via `csc.exe` to bypass TLS certificate validation.
- Persistence is established through four scheduled tasks created from XML files in `LOCALAPPDATA` and the placement of `msdiag.vbs` in the user's Startup folder, allowing relaunch after restarts or logins.
- Document collection targets Word, PDF, PowerPoint, Excel, and archive files modified within 365 days, excluding those larger than 500 MB, with a filesystem watcher enabling continuous monitoring of new or changed documents.
- Additional surveillance capabilities include capturing screenshots, stealing saved Wi-Fi passwords and clipboard contents, executing arbitrary PowerShell commands, and providing system information to operators.
- Command-and-control communications occur over two domains (`corecloudfileshare.xyz` and `attachmentsharingdrive.xyz`) with failover logic to switch between them if a connection fails.

## 5. Research Synthesis

### Executive Summary
The TASK#STOMP backdoor establishes persistence via VBScript-triggered scheduled tasks and startup entries, deploying dual PowerShell payloads that utilize compiled C helpers to bypass TLS certificate validation for data exfiltration. The malware specifically targets business documents by scanning fixed drives for files modified within the last year and monitoring new file creation in real-time.

### Recommended Hypothesis
> Adversaries use scheduled task abuse and csc.exe-based TLS bypass to maintain persistent remote access and exfiltrate specific business documents on compromised Windows endpoints.

### Gaps Identified
- Lack of detection for compiled C# helpers created by legitimate tools like csc.exe, which enables the malware to ignore invalid SSL certificates and blend in with normal development activities.

### Key Findings
- Hypothesis: Adversaries use scheduled task abuse and csc.exe-based TLS bypass to maintain persistent remote access and exfiltrate specific business documents on compromised Windows endpoints.
