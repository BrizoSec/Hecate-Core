### Summary

This chain involved deploying the ShellBot DDoS bot, executing a user-mode rootkit via /etc/ld.so.preload, and installing XMRig cryptominers disguised as system processes using XHide concealment techniques.

### Key Findings
- The attack campaign utilized ShellBot, a Perl-based DDoS botnet, which communicated with Command and Control (C&C) infrastructure located at IPs 177.22.88.133 and 103.157.217.38.
- A sophisticated persistence mechanism was employed where launcher malware executed the user-mode rootkit libSSL2.3.0.So via /etc/ld.so.preload, allowing it to hijack system library calls.
- Cryptomining activity was disguised by running XMRig under the name '-bash' and using the XHide tool to conceal its process visibility from standard monitoring tools.
- The Fisieredoor backdoor was deployed to facilitate further lateral movement, including the installation of SSH brute-force tools like goauto and tsm-family for systematic credential targeting.

## 5. Research Synthesis

### Executive Summary
Adversaries are executing a multi-stage attack chain on Linux SSH servers involving Perl-based ShellBot DDoS bots, user-mode rootkit injection via /etc/ld.so.preload to hijack dynamic linking, and process concealment of XMRig cryptominers as '-bash' using the XHide tool. Detection requires correlating anomalous library loading events with specific file hashes and network traffic to identified C&C IPs, while monitoring for disguised process execution patterns that evade standard system monitoring.

### Recommended Hypothesis
> Adversaries use /etc/ld.so.preload manipulation and XHide process concealment to deploy ShellBot DDoS bots and XMRig cryptominers on Linux SSH servers, evading detection by disguising malicious processes as legitimate shell instances.

### Gaps Identified
- Standard EDR telemetry often lacks visibility into dynamic library injection events or the ability to correlate /etc/ld.so.preload modifications with subsequent process creation, allowing the rootkit component to operate stealthily.
- Network monitoring may fail to detect the initial ShellBot C&C communication if it occurs over standard ports (e.g., 80/443) or if the Perl-based botnet traffic blends with legitimate HTTP/S traffic without distinct behavioral anomalies in packet size or frequency.

### Key Findings

- Gap: Standard EDR telemetry often lacks visibility into dynamic library injection events or the ability to correlate /etc/ld.so.preload modifications with subsequent process creation, allowing the rootkit component to operate stealthily.

- Focus: Monitor for unauthorized modifications to /etc/ld.so.preload and correlate these events with the creation of processes named '-bash' or other system binaries that exhibit unusual memory allocation patterns consistent with XMRig or ShellBot execution.
