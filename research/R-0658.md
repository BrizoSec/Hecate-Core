## 1. System Research: How It Works

### Summary
Legitimate browser extensions operate within the context of authenticated web sessions, utilizing local storage mechanisms like IndexedDB and localStorage to manage application state and user preferences for trading platforms such as Axiom Trade. Normal behavior involves standard API communication patterns that respect Cross-Origin Resource Sharing (CORS) policies, ensuring that sensitive session tokens and wallet data remain confined to the trusted domain without external exfiltration.

### Key Findings
- Normal application state is stored securely within the browser's local storage containers (localStorage and IndexedDB) for authenticated sessions on trading platforms like Axiom Trade and Padre.
- Legitimate extensions do not transmit sensitive user information, wallet bundles, or Firebase tokens to external servers, particularly avoiding Base64-encoded data transmission via browser navigation which is a known evasion technique for CORS restrictions.
- Standard telemetry and network traffic for these applications should not involve connections to untrusted third-party domains such as Vercel deployments (e.g., dcfdc-eight.vercel.app) or unknown run domains (e.g., susi.bonto.run, cloudflare.bonto.run).
- Normal operation does not include the interception of fetch requests to harvest bundle keys (sBundles, eBundles) or authentication tokens from the application context without explicit user consent and transparent notification.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are distributing malicious Chrome and Firefox extensions that masquerade as legitimate trading tools to target cryptocurrency traders, specifically those using Axiom Trade and Padre platforms. These extensions execute identical malicious modules to harvest authenticated session tokens, wallet data, and application state from local storage and API responses, exfiltrating the stolen information to threat actor-controlled command and control infrastructure.

### Key Findings
- Six linked malicious extensions (including J7Tracker, VREO, and Orbit Tracker) share byte-identical code for collecting user credentials and wallet bundles from authenticated sessions.
- The campaign targets high-volume crypto trading platforms like Axiom Trade, which processes over $15 billion in volume across 650,000 wallets, by stealing localStorage, IndexedDB data, and Firebase tokens.
- Exfiltration is achieved by Base64-encoding stolen data and transmitting it via browser navigation to avoid CORS restrictions, directing traffic to Vercel deployments (e.g., dcfdc-eight.vercel.app) and custom domains (susi.bonto.run).
- The primary malicious module, identified as 'vamp/axiom-fetch-intercept.js' with SHA-256 hash 5b4fbe0658ff76f042c3cc2dfe3d1a3eda963e435a24dfc868cb583bde8c7b91, has been flagged as malicious by VirusTotal with trojan labels.
- The threat actors utilize a pattern of repackaging existing crypto trading tools to gain user trust before installing the silent data collection and exfiltration capabilities.

## 5. Research Synthesis

### Executive Summary
Threat actors are distributing malicious Chrome and Firefox extensions that intercept authenticated session tokens, wallet bundles, and application state from Axiom Trade and Padre users via Base64-encoded browser navigations to evade CORS restrictions. The campaign utilizes shared codebases and C2 infrastructure hosted on Vercel deployments (e.g., dcfdc-eight.vercel.app) and custom domains (susi.bonto.run) to exfiltrate sensitive cryptographic data without triggering standard cross-origin security policies.

### Recommended Hypothesis
> Adversaries use malicious browser extensions with shared intercept modules (e.g., axiom-fetch-intercept.js) to harvest localStorage, IndexedDB, and API responses from authenticated crypto trading sessions, exfiltrating Base64-encoded payloads to Vercel and bonto.run C2 endpoints.

### Gaps Identified
- Current telemetry lacks visibility into outbound HTTP request bodies or encoded query parameters in DNS/Proxy logs for legitimate hosting providers like Vercel, blinding detection of the 'd=' payload parameter used for data exfiltration.
- Endpoint Detection and Response (EDR) systems do not currently monitor file system paths associated with browser extension profiles (e.g., Chrome/Firefox user data directories) for the deployment or modification of specific malicious scripts like vamp/axiom-fetch-intercept.js.

### Key Findings
- Hypothesis: Adversaries use malicious browser extensions with shared intercept modules (e.g., axiom-fetch-intercept.js) to harvest localStorage, IndexedDB, and API responses from authenticated crypto trading sessions, exfiltrating Base64-encoded payloads to Vercel and bonto.run C2 endpoints.
- Gap: Current telemetry lacks visibility into outbound HTTP request bodies or encoded query parameters in DNS/Proxy logs for legitimate hosting providers like Vercel, blinding detection of the 'd=' payload parameter used for data exfiltration.
- Gap: Endpoint Detection and Response (EDR) systems do not currently monitor file system paths associated with browser extension profiles (e.g., Chrome/Firefox user data directories) for the deployment or modification of specific malicious scripts like vamp/axiom-fetch-intercept.js.
- Focus: Implement deep packet inspection or proxy logging to decode Base64 parameters in GET requests directed at Vercel subdomains and bonto.run hosts, specifically looking for patterns consistent with JSON or wallet bundle structures.
