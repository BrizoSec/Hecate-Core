## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry for detecting Abyssos should focus on process execution events, network communications indicative of C2 activity, file modifications made by suspicious binaries, and registry changes that hint at persistence mechanisms.

### Key Fields
- process.name (85% populated): Tracks the names of processes being executed. Suspicious patterns here could indicate malicious binary execution or unusual behavior from legitimate tools.
- network.dns.query (90% populated): Logs DNS queries made by endpoints. Unexpected domain lookups or requests to known bad domains can be indicative of C2 activity for a RAT like Abyssos.
- file.path (75% populated): Records file paths where modifications occur, such as new files being created or existing ones altered. This helps in identifying whether these changes are related to the deployment or execution of malware.
- registry.key.name (60% populated): Tracks registry keys that are modified by processes on endpoints. Persistence mechanisms often involve adding entries under certain keys like 'Run' or modifying services for auto-start purposes.
- process.parent.name (70% populated): Indicates the parent process from which a suspicious child process was spawned, useful in determining if the malware is leveraging legitimate tools to execute its payload.
- network.connection (85% populated): Logs all network connections established by processes. Outbound connections to unusual IP addresses or ports can be indicative of data exfiltration attempts.
