## 1. System Research: How It Works

### Summary
SectopRAT is a .NET-based remote access trojan that establishes full remote control and data exfiltration capabilities by embedding itself within tampered legitimate software components. The malware utilizes a multi-stage in-memory execution chain to bypass detection, ultimately communicating with a command-and-control server via encrypted TCP connections.

### Key Findings
- The malware is delivered via a tampered 'FrameworkBase.dll' that modifies its Import Address Table to load the malicious entry point 'sdkcra.dll', which is executed by the legitimate 'ReportDump.exe' configured as a scheduled task.
- Execution evasion relies on abusing the Windows API 'EnumSystemCodePagesW()' by passing decrypted assembly code as a callback function, while resolving 187 APIs dynamically using hash codes to avoid static signature detection.
- The primary payload is encrypted within 'pool.db' and decrypted in memory using a custom routine with key 0xBC before initializing the .NET runtime environment directly without writing the executable to disk.
- Command-and-control communication uses AES encryption with a hardcoded key, where packet size is encoded in the first five bytes and the IV follows immediately, transmitting plaintext JSON commands after decryption.
- The variant supports 29 distinct control commands for remote administration, including screen capture, browser credential theft ('DeployBrowserKey'), process management, and system reboot, connecting to C2 server 98.142.252.140:15847.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse MITRE ATT&CK T1027 by embedding encrypted SectopRAT payloads within legitimate software components, such as tampered DLLs and database files, to evade detection. This technique allows the malware to conceal its contents on the system while maintaining remote control capabilities and data theft functions.

### Key Findings
- The SectopRAT payload is encrypted and embedded in a 'pool.db' file within a legitimate software folder, specifically hidden alongside tampered DLLs like 'FrameworkBase.dll'.
- A malicious entry point in 'sdkcra.dll' reads encrypted data from 'Activation.Desktop.db' and decrypts it into ASM code using the SDL_IOFromFile() API.
- The decrypted ASM code abuses the Windows EnumSystemCodePagesW() API, treating the malicious code as a callback function to execute it dynamically.
- Runtime API resolution is employed within the ASM code using hash codes for 187 APIs, including dynamic loading of .NET runtime modules like mscoreei.dll and clr.dll.
- The SectopRAT payload itself is heavily obfuscated with randomly generated identifiers, control-flow flattening, and the use of 'calli' instructions to hinder reverse engineering.

## 5. Research Synthesis

### Executive Summary
This hunt focuses on detecting a SectopRAT variant that leverages T1027 by embedding encrypted payloads within legitimate software components, specifically tampering with `FrameworkBase.dll` to load `sdkcra.dll`. The adversary executes obfuscated assembly via the `EnumSystemCodePagesW` API abuse and resolves 187 APIs dynamically using hashes to bypass static analysis before initializing a .NET runtime in memory.

### Recommended Hypothesis
> Adversaries use encrypted payload embedding in legitimate DLLs and API hooking via EnumSystemCodePagesW to execute undetected SectopRAT payloads on Windows systems.

### Gaps Identified
- Standard endpoint detection often misses the in-memory initialization of the .NET runtime (clr.dll/mscoreei.dll) loaded by the malicious assembly without writing a PE file to disk, as well as the specific API hash resolution patterns used to dynamically load 187 functions.
- Network telemetry may fail to identify the C2 channel if it relies solely on IP reputation rather than detecting the unique AES packet structure (5-byte transformed size header + IV) or the JSON command format over TCP port 15847.

### Key Findings
- Hypothesis: Adversaries use encrypted payload embedding in legitimate DLLs and API hooking via EnumSystemCodePagesW to execute undetected SectopRAT payloads on Windows systems.
- Gap: Standard endpoint detection often misses the in-memory initialization of the .NET runtime (clr.dll/mscoreei.dll) loaded by the malicious assembly without writing a PE file to disk, as well as the specific API hash resolution patterns used to dynamically load 187 functions.
- Gap: Network telemetry may fail to identify the C2 channel if it relies solely on IP reputation rather than detecting the unique AES packet structure (5-byte transformed size header + IV) or the JSON command format over TCP port 15847.
- Focus: Monitor for `EnumSystemCodePagesW` being invoked with callback addresses pointing to non-standard memory regions or executable code segments, and correlate this with the loading of `clr.dll` by unexpected processes like `ReportDump.exe`.
