## 1. System Research: How It Works

### Summary
Brevo’s normal operation involves serving legitimate JavaScript SDKs (specifically sdk-loader.js and brevo-conversations.js) from its Cloudflare CDN to embed tracking, chat widgets, and forms on customer websites. Under normal conditions, these scripts execute client-side to facilitate email marketing automation without modifying DNS infrastructure or requiring administrative authentication for payload delivery.

### Key Findings
- Legitimate Brevo JavaScript assets are hosted at cdn.brevo.com/js/sdk-loader.js and brevo-conversations.js, which normally initialize the sender ID (sib) object for tracking and conversation widgets without injecting external script tags.
- The attack vector involved dynamic content rewriting via Cloudflare Workers to append a malicious script tag pointing to new subdomains under sendibt1.com (e.g., cdn2.sendibt1.com/f.js), leveraging DNS records created as early as August 25, 2026.
- The injected malware f.js contained dual payloads: a ClickFix overlay targeting regular visitors and a silent WordPress plugin installer that triggered POST requests to /wp-admin/update.php?action=upload-plugin when site administrators visited while logged in.
- Indicators of compromise include specific SHA-256 hashes for the clean vs. injected sdk-loader.js files, and C2 endpoints located at /api/v1/ paths on compromised cdn subdomains, which were active only between 16:05 and 20:12 UTC on September 14, 2026.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries compromised Brevo's Cloudflare infrastructure to inject malicious JavaScript into legitimate CDN assets, delivering a WordPress backdoor to site administrators and ClickFix malware to general visitors across over 100,000 customer sites. The attack leveraged dynamic DNS reconfiguration and content rewriting capabilities within the provider's ecosystem to bypass initial detection and distribute payloads via trusted domains.

### Key Findings
- The attacker gained write access to Brevo's Cloudflare account, evidenced by the creation of malicious subdomains (cdn*.sendibt1.com) with SSL certificates issued in August 2026, prior to the September 14, 2026 active attack window.
- Malicious code was injected into legitimate JavaScript assets (sdk-loader.js and brevo-conversations.js) hosted on cdn.brevo.com, which dynamically loaded a secondary payload from f.js located on attacker-controlled subdomains of sendibt1.com.
- The malware exhibited dual functionality: it automatically installed a WordPress plugin backdoor when administrators visited their own sites while logged in, and displayed a ClickFix overlay to regular visitors that tricked them into executing commands on their local machines.
- Active exploitation occurred during a specific four-hour window on September 14, 2026, between 16:05 and 20:12 UTC, affecting major clients such as eBay, Louis Vuitton, Michelin, and Amnesty International.
- The attack relied on DNS poisoning of subdomains under sendibt1.com; while the apex domain sendibt1.com is legitimate for email tracking, the attacker utilized distinct CDN subdomains (cdn2, cdn4, cdn9, etc.) to host the malicious infrastructure.

## 5. Research Synthesis

### Executive Summary
Adversaries leveraged compromised Cloudflare account credentials to dynamically rewrite legitimate Brevo JavaScript assets via Workers, injecting a secondary loader (f.js) that delivered dual payloads: a WordPress plugin backdoor for authenticated administrators and ClickFix overlays for end-users. The operation utilized attacker-controlled subdomains under sendibt1.com as distribution points and C2 infrastructure during a four-hour window on September 14, 2026.

### Recommended Hypothesis
> Adversaries use dynamic CDN content rewriting via compromised cloud provider credentials to inject malicious JavaScript loaders into trusted third-party SDKs for supply chain distribution of WordPress backdoors and ClickFix malware.

### Gaps Identified
- Current telemetry lacks correlation between legitimate Cloudflare Workers configuration changes and the subsequent injection of script tags into cached static assets, leaving dynamic content manipulation undetected by standard file integrity monitoring.
- Browser-based payload execution (ClickFix) and automated plugin installation via POST requests to /wp-admin/update.php generate low-volume, high-legitimacy traffic that is often obscured by normal CMS administrative activity logs without specific behavioral baselining.

### Key Findings
- Hypothesis: Adversaries use dynamic CDN content rewriting via compromised cloud provider credentials to inject malicious JavaScript loaders into trusted third-party SDKs for supply chain distribution of WordPress backdoors and ClickFix malware.
- Gap: Current telemetry lacks correlation between legitimate Cloudflare Workers configuration changes and the subsequent injection of script tags into cached static assets, leaving dynamic content manipulation undetected by standard file integrity monitoring.
- Gap: Browser-based payload execution (ClickFix) and automated plugin installation via POST requests to /wp-admin/update.php generate low-volume, high-legitimacy traffic that is often obscured by normal CMS administrative activity logs without specific behavioral baselining.
- Focus: Monitor Cloudflare API logs for unauthorized DNS record creation or Workers script modifications targeting known third-party SDK domains (e.g., brevo.com, sendibt1.com) and correlate with CSP violations involving external script sources.
