## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries compromised the AsyncAPI GitHub repositories to inject malicious npm packages into the supply chain, targeting developers who rely on these libraries. The @bitwarden/cli package version 2026.4.0 was used to deliver payloads during import time, exploiting trust in legitimate software ecosystems.

### Key Findings
- Adversaries gained unauthorized access to AsyncAPI GitHub repositories and pushed malicious code into popular npm packages like @bitwarden/cli.
- The attack leverages the timing of package imports to execute malicious scripts that can deliver payloads or establish backdoors.
- Attackers targeted specific versions (e.g., 2026.4.0) of vulnerable packages, highlighting the importance of version control and dependency management in npm projects.
- This supply-chain compromise underscores broader issues with npm security following the Shai-Hulud worm incident, necessitating robust monitoring and patching practices.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect the behavior associated with the AsyncAPI npm supply chain compromise and import-time payload delivery, telemetry should capture events related to npm package installation anomalies, unusual outbound network connections from the compromised packages, and signs of malicious code execution. Key data points include tracking failed or suspicious attempts to install specific versions of affected packages, monitoring for unexpected HTTP requests (especially those pointing towards known malicious domains), and capturing process creation activities that are inconsistent with normal application behavior.

### Key Fields
- process_creation (85% populated): Tracks the creation of processes related to npm installations. Suspicious patterns include attempts to install specific compromised versions of AsyncAPI or other affected packages.
- file_change: Monitors changes in files and directories that are typical targets for malware, such as scripts included within the node_modules directory after a package installation. This field would capture modifications indicative of malicious code injection.
- network_connection (90% populated): Captures outbound network connections initiated by npm-installed packages. Of particular interest are HTTP or HTTPS requests to IP addresses and domains associated with known malicious activities, indicating potential payload delivery mechanisms.
- process_spawned_from: Provides insight into the parent process spawning a suspicious process. For instance, if a benign-looking package spawns an unexpected child process that communicates with external systems, this field will help trace back to the root cause.
- event_type (80% populated): Identifies the type of event, which is crucial for filtering out false positives and focusing on security-relevant events such as installation commands or unusual network traffic patterns.

## 5. Research Synthesis

### Executive Summary
Adversaries compromised the AsyncAPI GitHub repositories to inject malicious npm packages into the supply chain, targeting developers through legitimate software ecosystems. The attack leverages import-time payload delivery mechanisms to execute malicious scripts, highlighting critical gaps in npm package security and version control practices.

### Recommended Hypothesis
> Adversaries use unauthorized access to GitHub repositories and compromised npm packages to deliver malicious payloads during import time for the purpose of establishing backdoors or delivering malware to target systems.

### Gaps Identified
- Current coverage lacks robust detection mechanisms for identifying anomalous npm package installations, especially when specific versions are targeted by adversaries. Additionally, there is a need for enhanced monitoring of outbound network connections and process execution patterns that may indicate malicious activities initiated from compromised packages.

### Key Findings
- Hypothesis: Adversaries use unauthorized access to GitHub repositories and compromised npm packages to deliver malicious payloads during import time for the purpose of establishing backdoors or delivering malware to target systems.
- Gap: Current coverage lacks robust detection mechanisms for identifying anomalous npm package installations, especially when specific versions are targeted by adversaries. Additionally, there is a need for enhanced monitoring of outbound network connections and process execution patterns that may indicate malicious activities initiated from compromised packages.
- Focus: Enhance telemetry to capture detailed installation events, monitor unexpected HTTP requests from installed packages, and track process creation anomalies indicative of payload delivery or backdoor establishment.
