## 1. System Research: How It Works

### Summary
Gitea is a self-hosted source-code management platform that, by default, allows open user registration and processes repository patches via a temporary bare clone to facilitate code collaboration. In its vulnerable state (versions 1.17–1.27.0), the system incorrectly exposes internal Git hook directories during patch application, allowing unauthenticated attackers to write executable payloads directly into the Gitea service account's context.

### Key Findings
- CVE-2026-60004 allows remote code execution because Gitea uses a bare temporary clone for patch processing; when Git 2.32+ is present, an add/add collision forces file checkout to disk, writing malicious hooks directly into the active $GIT_DIR (the repository root) which execute upon index changes.
- The vulnerability is exploitable without pre-existing credentials on instances with open registration enabled, as attackers can register new accounts, create repositories, and submit crafted patches to achieve code execution.
- Gitea version 1.27.1 (released July 27, 2026) mitigates this by switching the temporary clone from bare to non-bare, ensuring the repository root no longer serves as $GIT_DIR and preventing hook installation.
- The attacker utilized an automated framework that ingested target lists to auto-register accounts with a 'word_word_NNN' pattern, exploit vulnerabilities, dump repositories, and clean up traces via a file named exp_enhanced.py.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The Red Heron threat actor rapidly weaponized CVE-2026-60004, a critical remote code execution vulnerability in Gitea, to compromise internet-facing instances across multiple countries by exploiting open registration defaults and abusive git hook mechanisms. The campaign progressed from automated source code theft and credential collection to lateral movement within targeted environments, supported by the deployment of a novel Linux implant and rootkit.

### Key Findings
- Red Heron exploited CVE-2026-60004 (CVSS 9.8) in Gitea versions 1.17 through 1.27.0 by submitting crafted patches that abused the 'git apply' command to write malicious hooks into the repository's active directory, achieving code execution without prior credentials on instances with open registration.
- The actor developed an automated framework within days of the vulnerability's public disclosure that could register accounts, exploit targets, dump repositories, and clean up traces, scanning 1,386 instances across seven countries and specifically targeting 477 Taiwan-based systems.
- Confirms successful compromises in Canada, Argentina, Taiwan, the United States, and Sri Lanka, with one incident escalating from a Gitea server to root-level access on a three-node Proxmox cluster.
- The campaign deployed JITTERLY, a C++ Linux implant with over 30 post-exploitation commands, which embedded SIXZUT, a previously undocumented LD_PRELOAD rootkit designed to hide files, processes, and network connections while protecting the implant from termination.
- Target selection was guided by structured databases using Simplified Chinese labels covering sectors such as defense, elections, energy, aerospace, telecommunications, government, and research, indicating PRC-linked strategic priorities.

## 5. Research Synthesis

### Executive Summary
Red Heron exploited CVE-2026-60004 in Gitea to achieve unauthenticated RCE via malicious git hooks, deploying the JITTERLY implant and SIXZUT LD_PRELOAD rootkit to maintain persistent access while evading detection by hiding processes and network connections. Hunt efforts must focus on detecting the specific hook installation artifacts and anomalous system call patterns associated with LD_PRELOAD injection rather than relying on standard process monitoring.

### Recommended Hypothesis
> Adversaries use crafted git patches to exploit CVE-2026-60004 in Gitea to write malicious hooks into the active $GIT_DIR and deploy JITTERLY/SIXZUT for persistent, stealthy root access.

### Gaps Identified
- Standard endpoint detection may miss the SIXZUT rootkit's LD_PRELOAD injection which actively hides processes and network connections from standard telemetry tools.

### Key Findings
- Hypothesis: Adversaries use crafted git patches to exploit CVE-2026-60004 in Gitea to write malicious hooks into the active $GIT_DIR and deploy JITTERLY/SIXZUT for persistent, stealthy root access.
- Gap: Standard endpoint detection may miss the SIXZUT rootkit's LD_PRELOAD injection which actively hides processes and network connections from standard telemetry tools.
- Focus: Monitor file system activity for the creation of '.git/hooks/post-index-change' files and correlate with unexpected 'git apply' command lines or shell spawns by the Gitea service account.
