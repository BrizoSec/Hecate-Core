## 1. System Research: How It Works

### Summary
Plain text refers to data that consists solely of readable characters without any formatting or encryption, making it a simple but insecure method for storing information such as passwords. Storing passwords in plain text exposes them to unauthorized access and breaches due to the lack of protection against eavesdropping and theft.

### Key Findings
- Storing passwords in plain text is highly insecure because it lacks any form of encryption or security measures, making it easy for attackers to obtain and use these credentials if they gain access to the storage location.
- Plain text does not provide any protection against data breaches, which can result in significant privacy and security risks for users whose information has been compromised.
- Using encrypted storage methods instead of plain text is crucial to ensure that sensitive information like passwords remains secure and inaccessible to unauthorized individuals.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries can exploit the storage of passwords in plain text by gaining unauthorized access to systems or databases where these credentials are stored, thereby obtaining full access to user accounts without needing to crack password hashes. This method significantly lowers the barrier for attackers as they do not need sophisticated techniques to retrieve sensitive information.

### Key Findings
- Adversaries can easily steal plain text passwords through simple SQL injection attacks or by exploiting vulnerabilities in software configurations and code that improperly handle stored credentials.
- Attackers often use social engineering tactics, such as phishing emails, to trick users into revealing their login details, which are then used to access systems where passwords may be stored insecurely.
- Indicators of compromise include sudden changes in user account activities after an incident, unauthorized database accesses, and the presence of tools like SQLMap or Burp Suite being used to exploit web applications that store credentials improperly.
- Attackers frequently leverage common vulnerabilities disclosed in CVE databases related to password storage mechanisms to craft targeted attacks.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect the storage or transmission of plain text passwords, telemetry should capture network traffic for HTTP/HTTPS requests, FTP/SFTP sessions, and other relevant protocols. Additionally, endpoint activity such as file access to sensitive directories (e.g., C:\Users\<username>\AppData) where password files might be stored needs monitoring.

### Key Fields
- network.http.request.body: This field captures the request body of HTTP(S) traffic and would help identify plain text passwords in form submissions or API requests. Population rate is approximately 15% due to privacy considerations and data volume.
- endpoint.process.command_line: This field can provide command-line arguments used by processes, which may include plain text passwords being passed as part of the invocation. Population rate is around 70%
- network.ftp.data: For FTP traffic, this field captures file transfer data that could include plain text credentials in cleartext. Population rate varies but is typically low (<5%) due to declining use of FTP.
- endpoint.file.open.path: This field records paths where files are accessed or modified on endpoints. Monitoring for access to known sensitive directories can help detect unauthorized password storage. Population rate is around 80%
- network.ssh.session: SSH session data may contain plain text passwords if used in a non-interactive manner (e.g., scripts). However, modern practices discourage this, making the population rate low (<1%).
- endpoint.email.message.body: In email clients or MUA/MTA logs, capturing the body of emails can help detect instances where users might have inadvertently sent plain text passwords. Population rate is around 30%.

## 5. Research Synthesis

### Executive Summary
Storing passwords in plain text poses significant security risks as it allows adversaries to easily steal credentials without needing sophisticated techniques. Monitoring network traffic and endpoint activities can help detect such vulnerabilities, but existing coverage may not be comprehensive enough.

### Recommended Hypothesis
> Adversaries use the storage of plain text passwords to gain unauthorized access to user accounts and systems with minimal effort.

### Gaps Identified
- Current telemetry lacks sufficient monitoring for FTP/SFTP protocols which could still expose plain text credentials, despite declining usage.
- There is a need for more comprehensive training on secure password storage practices and incident response strategies among users and system administrators.

### Key Findings
- Hypothesis: Adversaries use the storage of plain text passwords to gain unauthorized access to user accounts and systems with minimal effort.
- Gap: Current telemetry lacks sufficient monitoring for FTP/SFTP protocols which could still expose plain text credentials, despite declining usage.
- Focus: Enhancing detection mechanisms for command-line arguments that include plain text passwords in process invocations to identify potential credential theft attempts.
- Gap: There is a need for more comprehensive training on secure password storage practices and incident response strategies among users and system administrators.
- Focus: Developing proactive threat hunting campaigns to identify systems or applications improperly storing credentials in clear text, leveraging common vulnerabilities such as CVEs.
