## 1. System Research: How It Works

### Summary
ScreenConnect is a legitimate remote management tool used for initiating and joining sessions through an email link or guest page. However, threat actors abuse this tool by delivering it via phishing emails to gain unauthorized access to user devices.

### Key Findings
- Phishing emails are customized with recipients' personal information such as names and email addresses to increase credibility.
- ScreenConnect is installed on the victim's machine as a service and can hide files through system attributes, making detection difficult.
- The malware leverages Microsoft .NET utilities and sets hidden/system file attributes to evade standard user detection.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries frequently abuse the ScreenConnect remote management tool through phishing campaigns to deliver malware, often masquerading as legitimate software installations. Once deployed, ScreenConnect can act as a persistence mechanism and communication channel with command-and-control servers for further attacks.

### Key Findings
- Phishing emails are used to distribute ScreenConnect payloads via MSI installers that mimic official installations but are actually malicious.
- ScreenConnect is installed in the C:\Temp directory and runs as a Windows service, establishing persistence on compromised machines.
- Adversaries often leverage established credentials for initial access before deploying RMM tools like ScreenConnect to expand their foothold within networks.
- The malware communicates with remote servers to receive additional payloads or commands, enabling further malicious activities such as lateral movement and data exfiltration.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Phishing email delivery of ScreenConnect malware can be detected through monitoring endpoint activities for suspicious behaviors like unexpected process creations, network connections to unauthorized endpoints, and unusual registry modifications. The SIEM should aggregate logs from Windows Security Event Logs, system/application logs, and endpoint telemetry.

### Key Fields
- process_creation (90% populated): Tracks the creation of new processes on endpoints which is crucial for identifying malicious software like ScreenConnect being launched by phishing emails.

## 5. Research Synthesis

### Executive Summary
ScreenConnect, a legitimate remote management tool, is increasingly being abused by threat actors through phishing emails to deliver malware. These attacks typically involve customized emails that trick users into downloading and installing malicious MSI files disguised as legitimate software updates or installations.

### Recommended Hypothesis
> Adversaries use phishing campaigns with ScreenConnect payloads to establish persistence within networks for lateral movement and data exfiltration.

### Gaps Identified
- Current telemetry coverage lacks comprehensive monitoring of email content and attachment analysis to prevent the initial infection vector.
- There is insufficient tracking of remote connections established via ScreenConnect, which can enable lateral movement within networks.

### Key Findings
- Hypothesis: Adversaries use phishing campaigns with ScreenConnect payloads to establish persistence within networks for lateral movement and data exfiltration.
- Gap: Current telemetry coverage lacks comprehensive monitoring of email content and attachment analysis to prevent the initial infection vector.
- Focus: Enhance endpoint security by implementing stricter process creation, network connection, and registry modification rules in SIEM systems.
- Gap: There is insufficient tracking of remote connections established via ScreenConnect, which can enable lateral movement within networks.
- Focus: Develop advanced email filtering mechanisms to detect and block phishing emails containing malicious MSI files or other suspicious attachments.
