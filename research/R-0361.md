## 1. System Research: How It Works

### Summary
This TrickBot variant employs DNS tunneling for command and control (C2) communications, encoding commands in DNS queries to evade detection. It maintains persistence on infected systems through scheduled tasks created via Windows Task Scheduler.

### Key Findings
- TrickBot uses packet type 0x30 for sending requests and 0x31 for querying the size of response data from its C2 server.
- The malware encodes commands using a single-byte XOR key, hex-encodes the result, splits it into chunks, and prepends these to mimic valid domain names in DNS queries.
- Persistence is maintained by creating scheduled tasks through Windows Task Scheduler with randomly generated task names.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
TrickBot uses DNS tunneling to communicate with its command-and-control (C2) servers, employing scheduled tasks for persistence on compromised systems. This method allows the malware to evade detection and maintain stealthy control over infected machines.

### Key Findings
- TrickBot leverages the Windows Task Scheduler to create persistent scheduled tasks that execute malicious code.
- The malware utilizes DNS tunneling as a communication channel, hiding C2 traffic within legitimate-looking DNS requests.
- DNS queries are encrypted and obfuscated to avoid simple signature-based detection methods.
- Public DNS servers are used to relay commands and exfiltrate data between TrickBot-infected systems and the attackers' infrastructure.

## 5. Research Synthesis

### Executive Summary
A TrickBot variant employs DNS tunneling to establish stealthy command and control communications while using scheduled tasks for persistence on compromised Windows systems. The malware uses XOR encoding, hex-encoding, and public DNS servers to evade detection.

### Recommended Hypothesis
> Adversaries use DNS tunneling and scheduled tasks to encode malicious commands and achieve persistent access on compromised Windows machines.

### Gaps Identified
- Current coverage is limited in tracking the specific command line arguments used by schtasks for suspicious activity, as well as monitoring unusual patterns in DNS queries.
