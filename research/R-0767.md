## 1. System Research: How It Works

### Summary
DarkMe RAT operates via a multi-stage chain starting with social engineering to deliver a .pif file that invokes an MSI installer to stage VB6 components. The malware utilizes process hollowing to execute its payload within a legitimate signed Microsoft binary and establishes persistence through custom COM objects and non-standard protocol handlers.

### Key Findings
- The initial delivery mechanism has shifted from zero-day exploits (CVE-2023-38831, CVE-2024-21412) to social engineering, using phishing links disguised as images that deliver .pif files masquerading as shortcuts.
- Process hollowing is employed by staging a legitimate signed Microsoft binary (clspack.exe) in %AppData%\Microsoft\ and executing it via rundll32 with a specific CLSID to load the DarkMe RAT code.
- Persistence is maintained through a custom protocol handler ('Locked://') registered via a COM object (Coconout.dll) and registry imports, alongside standard run keys.
- The malware implements an inverted sandbox check against 329 applications to identify genuine user environments rather than analysis systems, targeting cryptocurrency wallets and financial platforms.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
DarkMe persists by abusing T1547.001 through two distinct mechanisms: establishing a custom 'Locked://' protocol handler via HKCU\Software\Classes and executing logon persistence using a run key that launches explorer.exe with the 'Locked://' URI. This technique allows the malware to load its Visual Basic 6 components automatically upon user login, maintaining access without relying on traditional Run Keys alone.

### Key Findings
- DarkMe utilizes a novel custom protocol handler ('Locked://') registered under HKCU\Software\Classes\Locked\shell\open\command as part of its persistence strategy, diverging from standard Registry Run Keys.
- The attack chain relies on social engineering via phishing emails delivering disguised .pif files, marking a shift from previous exploits like CVE-2023-38831 and CVE-2024-21412 to lower-skill, high-volume tactics.
- Component staging occurs in %AppData%\ComponentsFolder\, with critical loader binaries like Coconout.dll installed there, alongside clspack.exe staged in %AppData%\Microsoft\ for process hollowing.
- Initial execution involves a PIF file invoking msiexec to install an .msi wrapper (built with exemsi) that drops a VBScript (prnfig.wsf) to handle registry imports and loader invocation.
- The malware employs process hollowing into signed Microsoft binaries, specifically staging clspack.exe in %AppData%\Microsoft\ to blend in with legitimate system activity.

## 5. Research Synthesis

### Executive Summary
DarkMe RAT executes persistence via a novel hybrid technique combining standard Registry Run Keys with a custom 'Locked://' protocol handler, allowing the attacker to trigger malicious COM object loading through legitimate system binaries like explorer.exe rather than relying solely on direct executable paths. This evasion strategy leverages process hollowing of signed Microsoft binaries (clspack.exe) and staged VB6 components to maintain access while bypassing standard execution monitoring.

### Recommended Hypothesis
> Adversaries use custom 'Locked://' protocol handlers registered via HKCU\Software\Classes and injected into Registry Run Keys to trigger COM object loading via explorer.exe, achieving persistent execution that mimics legitimate system behavior.

### Gaps Identified
- Standard telemetry often fails to correlate the specific CLSID {CFDC57BA-1705-45AF-BA10-EFC3D592982B} with malicious intent because it relies on generic 'rundll32 /sta' or protocol activation events without linking to the underlying Coconout.dll staging in %AppData%.
- Process hollowing detection is blind to this specific implementation because the loader (clspack.exe) is a legitimate, signed Microsoft binary staged in %AppData%\Microsoft\, making memory injection indistinguishable from normal host process behavior without deep API hooking.
