## 1. System Research: How It Works

### Summary
Trivy is a tool used for scanning container images and file systems to detect vulnerabilities. It can be compromised in the supply chain, leading to secret leaks such as GCP Secret Manager API access or Azure Key Vault SDK usage with credentials that allow unauthorized project enumeration.

### Key Findings
- Normal use of Trivy involves conducting security scans on software packages without any malicious intent.
- Expected behavior includes legitimate calls to cloud service APIs for secrets management but should not include unauthorized actions like secret leaks or project enumeration.
- The presence of unusual API access patterns, especially involving OAuth scopes and SDKs used for accessing secrets in environments like Google Cloud Platform (GCP) or Azure Key Vault, can indicate a compromise.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are exploiting the npm ecosystem by compromising software supply chains using AI tools, enabling them to harvest credentials and replicate themselves across systems. This technique, known as SANDWORM_MODE, leverages AI-generated content for integration into legitimate workflows, making detection challenging.

### Key Findings
- SANDWORM_MODE uses AI-driven toolchains to automate the creation of malicious npm packages that mimic legitimate software components.
- Adversaries harvest credentials and leverage them to spread across interconnected systems within a supply chain, often targeting popular or widely-used dependencies.
- The attack integrates seamlessly with existing workflows by generating convincing AI-created content that bypasses traditional detection methods.
- OpenClaw's skill marketplace is implicated in the distribution of compromised packages, highlighting the risk associated with third-party AI toolchains.
- Compromised npm packages may contain sophisticated obfuscation techniques to evade initial security scans and signature-based detections.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect behaviors associated with SANDWORM_MODE, which leverages sophisticated techniques such as code injection, process spawning, and network communications for malicious purposes in AI toolchains, telemetry should capture detailed logs of executable file creations, unusual process startups, API calls related to malware operations, and network activities indicative of command-and-control (C2) communication. This includes monitoring endpoint event logs, system call traces, and network traffic patterns.

### Key Fields
- process_creation_event: Process creation events are critical as they can reveal the spawning of malicious processes or unusual binaries being executed on endpoints.
- file_change_event (85% populated): Monitoring file changes, especially modifications to executable files without proper authorization, can indicate attempts at code injection or malware payloads.
- network_connection_event (70% populated): Tracking outbound network connections from endpoints can uncover C2 activity patterns typical of sophisticated APT attacks like SANDWORM_MODE.
- api_call: API call logs are crucial for detecting anomalous behavior such as usage of system APIs that might be abused by attackers for privilege escalation or data exfiltration.
