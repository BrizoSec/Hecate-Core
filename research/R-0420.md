## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect behaviors related to the Flying Eagle Android RAT, telemetry should focus on network communication patterns indicative of C2 (Command and Control) server interactions, unusual binary executions, and data exfiltration attempts. This includes monitoring for outbound HTTP/HTTPS requests that deviate from normal user behavior, tracking unauthorized installation or execution of binaries, and identifying any unexpected outgoing data transfers.

### Key Fields
- network.http.request.uri (50% populated): Tracks URLs accessed by applications on the network. Look for unusual patterns such as repeated connections to C2 servers or requests to download malicious payloads.
- process.create (70% populated): Monitors creation of new processes and executables. Identify unexpected or unauthorized installations, especially of binaries that are not typical in your environment but match known RAT signatures.
- file.write (65% populated): Observes file write operations to detect if malware is attempting to modify system files or create hidden directories for storing stolen data.
- network.dns.request.question.name (40% populated): DNS requests can reveal connections being made to suspicious domains that may be associated with C2 servers. Monitor for unusual domain names or subdomains.
- registry.modify (35% populated): Tracks changes in the Windows registry. Look for modifications that might indicate a RAT has installed itself persistently on the system, such as adding startup keys or modifying services.
- process.network_connection.outbound (60% populated): Monitors outbound network connections initiated by processes. Detect anomalies where Android devices establish unexpected TCP/UDP connections to external IP addresses.
