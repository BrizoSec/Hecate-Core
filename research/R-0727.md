## 1. System Research: How It Works

### Summary
Atlassian products utilize a directory traversal protection mechanism that replaces forward slashes with the '::' pattern, which attackers are exploiting by constructing URLs that bypass this escaping logic to access internal files like WEB-INF/web.xml. Telemetry from honeypots captures these specific exploit attempts targeting Jira, Bitbucket, and Confluence instances via crafted HTTP requests. The attacks originate from a cluster of IP addresses associated with DigitalOcean infrastructure.

### Key Findings
- Exploit URLs utilize the '::' delimiter to simulate directory traversal (e.g., '..::..::..') aiming to resolve to '/WEB-INF/web.xml' or 'urlrewrite.xml', targeting Tomcat-based internal configurations rather than standard OS files like /etc/passwd.
- The vulnerability affects multiple Atlassian products including Jira, Bitbucket, and Confluence, with specific payload paths observed for each (e.g., '/download/resources/jira.webresources...' and '/s/1.0/_/download/resources/com.atlassian.bitbucket...').
- Scan traffic originates from a distinct set of IP addresses (including 134.199.229.190, 137.184.112.247, and 143.198.103.58) all belonging to ASN 14061 (DigitalOcean, LLC), suggesting a coordinated effort by a single threat actor.
- Successful exploitation requires the target file to exist within the web application's directory structure, with WEB-INF/web.xml being a reliable target because it is a mandatory component of Tomcat applications.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are exploiting CVE-2026-21589, an arbitrary file access vulnerability in Atlassian products (Jira, Bitbucket, Confluence) that utilizes a unique directory traversal mechanism where slashes are replaced with the '::' pattern to bypass standard input validation. Active scans observed in October 2026 target specific web application resources like 'WEB-INF/web.xml' to exfiltrate configuration files, indicating automated exploitation attempts targeting Tomcat-based deployments.

### Key Findings
- The vulnerability allows pre-authentication arbitrary file reads by exploiting how Atlassian products handle path traversal; attackers use '..::..' sequences which the server translates back to forward slashes, enabling access to sensitive internal files like 'WEB-INF/web.xml' or 'urlrewrite.xml'.
- Successful exploitation requires the target file to exist on the server; researchers confirmed that standard Unix paths like '/etc/passwd' fail, whereas 'WEB-INF/web.xml' works because it is a required component of Tomcat applications.
- Exploitation attempts were observed targeting three distinct Atlassian product endpoints: Jira ('/download/resources/jira.webresources:...'), Bitbucket ('/s/1.0/_/download/resources/com.atlassian.bitbucket.server...'), and Confluence ('/s/1/_/download/resources/com.atlassian.confluence.plugins...').
- The scans originate from a cluster of IP addresses, all associated with DigitalOcean (ASN 14061), suggesting the use of cloud infrastructure for automated scanning or botnet operations.
- Threat intelligence enrichment indicates that several source IPs have low malicious hit counts on VirusTotal (0-2 hits) and no open ports found on Shodan, which may suggest the use of disposable VPS instances or static IPs not previously flagged by major security vendors.
- The activity appears to be driven by a single threat actor or coordinated group, given the consistent timing (starting October 5th, shortly after patch release) and the uniformity of the exploit URLs used across different Atlassian deployments.

## 5. Research Synthesis

### Executive Summary
Threat actors are leveraging CVE-2026-21589 to perform arbitrary file reads on Atlassian products by exploiting a directory traversal logic where forward slashes are encoded as '::'. Telemetry indicates automated scanning from DigitalOcean cloud IPs targeting specific resource endpoints to access WEB-INF configurations, necessitating detection of these unique delimiter patterns in web server logs.

### Recommended Hypothesis
> Adversaries use crafted HTTP requests with '..::..' directory traversal payloads targeting Atlassian REST endpoints to read internal web application configuration files like WEB-INF/web.xml.

### Gaps Identified
- Standard WAF rules often fail to detect this specific abuse of the '::' delimiter pattern, as it does not resemble traditional URL-encoded '%2F' or raw '..' sequences, requiring custom signature logic for these unique traversal markers.
- Current telemetry may lack visibility into the specific internal resource paths (e.g., 'jira.webresources', 'bitbucket-webpack-INTERNAL') that serve as the vector for this exploit, necessitating granular logging of Atlassian-specific API and resource endpoints rather than just general 404/403 errors.

### Key Findings
- Hypothesis: Adversaries use crafted HTTP requests with '..::..' directory traversal payloads targeting Atlassian REST endpoints to read internal web application configuration files like WEB-INF/web.xml.
- Gap: Standard WAF rules often fail to detect this specific abuse of the '::' delimiter pattern, as it does not resemble traditional URL-encoded '%2F' or raw '..' sequences, requiring custom signature logic for these unique traversal markers.
- Gap: Current telemetry may lack visibility into the specific internal resource paths (e.g., 'jira.webresources', 'bitbucket-webpack-INTERNAL') that serve as the vector for this exploit, necessitating granular logging of Atlassian-specific API and resource endpoints rather than just general 404/403 errors.
- Focus: Monitor HTTP logs for high-frequency requests containing '::' sequences adjacent to '..' targeting Atlassian product paths from ASN 14061 (DigitalOcean) and other cloud providers.
