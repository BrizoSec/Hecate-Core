## 1. System Research: How It Works

### Summary
Fileless execution in Linux leverages memory-backed file descriptors for code execution, bypassing traditional filesystem-based detection methods. This technique involves using `memfd_create` and executing through `/proc/self/fd/`, thus evading conventional antivirus solutions that rely on scanning files stored on disk.

### Key Findings
- The use of `memfd_create` to stage payloads in memory is a key indicator of fileless execution attempts, as it creates anonymous file descriptors without writing to the filesystem.
- Execution through `/proc/self/fd/` allows for direct manipulation and invocation of code stored solely within process memory spaces, bypassing traditional signature-based detection mechanisms.
- Detection focuses on specific patterns such as reverse shell executions via `bash -i`, `nc -e`, or Python's `pty.spawn`, which are indicative of fileless malware activities.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit fileless execution techniques on Linux to run malicious code entirely in memory, avoiding detection by traditional disk-based security measures. They leverage system utilities and memory-based methods such as `memfd_create` to inject and execute their payloads.

### Key Findings
- Fileless attacks on Linux use memory-based techniques like memfd_create to stage and execute malicious code without writing to the disk, evading file-based detection systems.
- Attackers can combine primitives like memfd_create with other system utilities to create sophisticated loaders for fileless execution payloads.
- Detection of fileless attacks involves monitoring unusual memory behaviors and ensuring process integrity on Linux systems.
- Traditional signature-based antivirus solutions are ineffective against fileless malware due to the absence of malicious files.

## 5. Research Synthesis

### Executive Summary
Fileless execution in Linux employs techniques such as memfd_create and direct memory manipulation through /proc/self/fd to execute malicious code without touching the disk, evading traditional file-based detection. Detection relies on monitoring specific process activities indicative of these behaviors.

### Recommended Hypothesis
> Adversaries use memory-backed file descriptors and system utilities like memfd_create to stage and execute payloads entirely in memory to evade detection by traditional security measures.

### Gaps Identified
- Current detection mechanisms may miss transient or encrypted payloads that do not generate persistent artifacts on disk, making it difficult to correlate suspicious process activities with known indicators of compromise.
