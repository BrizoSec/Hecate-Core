## 2. Adversary Tradecraft: Attack Techniques

### Summary
DeadLock ransomware targets Windows systems using a Rust-based encryptor with a custom stream cipher encryption algorithm that leverages time-based cryptographic keys, making it challenging for incident responders to decrypt files. The malware also incorporates decentralized recovery infrastructure and anti-forensics techniques to evade detection and analysis.

### Key Findings
- DeadLock ransomware employs a custom stream cipher encryption algorithm with time-varying keys to encrypt files on Windows systems.
- The attack uses BYOVD (Bring Your Own Vulnerability Detection) loader, which adds another layer of complexity in detecting the malware.
- Decentralized recovery infrastructure is utilized by DeadLock to ensure persistence and resilience against takedown efforts.
- Adversaries deploy anti-forensics techniques within the ransomware to impede incident response teams from analyzing the malware effectively.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect DeadLock ransomware behavior, telemetry should monitor for unusual file access patterns (file creation, deletion), encryption activity, network communication to decentralized nodes, and process execution anomalies. Specific focus areas include monitoring for known bad hashes of the malware, unexpected lateral movement, and changes in system state indicative of data exfiltration.

### Key Fields
- process_creation: Monitors new processes being created by suspicious binaries or scripts that are indicative of ransomware activity (e.g., file encryption tools). Typically, this field is populated at a high rate due to the variety of legitimate process creations in an environment, but anomalies should be flagged.
- file_change_monitoring: Tracks changes in files and directories which can indicate data exfiltration or modification activities by DeadLock ransomware. This field is often highly populated as part of routine file system operations, but sudden spikes in activity can signal potential threats.
- network_connection: Detects outbound network connections to unknown or malicious IP addresses or domains that may be part of the decentralized recovery infrastructure used by DeadLock for command and control (C2) communication. This field is less frequently populated than standard traffic patterns, making deviations more noticeable.
- dns_query: Monitors DNS queries made during malware operation, which can reveal attempts to connect with C2 servers or download additional payloads. It's commonly populated in environments but should alert on rare or suspicious domain names.
- file_deletion: Tracks deletions of files that are not part of normal operational processes and could indicate an attempt by DeadLock ransomware to remove backups or traces of its activity, reducing the ability for recovery.
- process_behavior_monitoring: Captures detailed behavior of running processes such as injected code, unusual file operations, or system calls which can be indicative of ransomware encryption routines. This field is less commonly populated but critical for detecting sophisticated attack patterns.
