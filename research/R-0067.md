## 1. System Research: How It Works

### Summary
Netlogon.log is a log file maintained by Microsoft's Active Directory domain service to record user authentication events. Each entry in the log includes unique identifiers for various network logon activities, which can be filtered and analyzed to track specific user login patterns or security incidents.

### Key Findings
- Netlogon.log contains detailed records of both 'Network Logon' and 'Transitive Network Logon' events that indicate when users are logging into the domain.
- Unique identifiers in netlogon.log entries can be used to filter out specific types of logon activities, such as LOGON actions, for analyzing user authentication trends.
- Analyzing netlogon.log files provides insights into user activity that may not be fully captured by other monitoring mechanisms like Event 1644.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries can exploit the limitations of Event 1644 to bypass detection by intercepting and abusing credentials without being logged, while Netlogon.log provides a more detailed record of authentication events that can be used to uncover such activities. Techniques like setting up new network listeners or alternative RPC channels can facilitate such attacks.

### Key Findings
- Adversaries use MITRE ATT&CK technique T1557 (Adversary-in-the-Middle) to intercept credentials without being detected by standard logging mechanisms.
- Tools like NPPSPY are used to open new network listeners that interfere with normal Windows processes, such as Winlogon, creating alternative RPC channels for malicious purposes.
- Netlogon.log records detailed authentication events which can reveal anomalies not captured by Event 1644 logs, making it a critical source for detecting APT activities.
- The Triton Safety Instrumented System Attack (T0830) showcases how adversaries manipulate communication protocols to gain unauthorized control over ICS systems.
