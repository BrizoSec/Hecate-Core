## 1. System Research: How It Works

### Summary
Windows kernel rootkits are highly sophisticated malware that operate at the deepest level of system operations, directly within the Windows operating system's core. They can manipulate and hide their presence from both the operating system and security software by exploiting vulnerabilities or leveraging existing mechanisms like device drivers to gain control over critical OS functions.

### Key Findings
- Rootkits often inject malicious code into kernel mode processes
- They frequently use stealth techniques such as hooking APIs or modifying memory management to evade detection
- Kernel rootkits can manipulate file system and process lists, hiding their presence from users and security tools

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are enhancing the CoolClient backdoor by incorporating a Windows kernel rootkit, which allows them to achieve deeper system-level persistence and evasion. This technique enables adversaries to manipulate core operating system functions, hide their presence from security tools, and maintain access even if standard user-space defenses detect and remove other malicious components.

### Key Findings
- Adversaries are leveraging the Windows kernel rootkit capability of CoolClient to establish stealthy persistence within targeted systems by modifying critical OS structures and processes.
- [UNCERTAIN] The integration of a rootkit into CoolClient might involve hooking system calls or altering file system metadata to hide malicious files, directories, registry keys, and network connections from detection tools.
- The use of kernel-level rootkits suggests adversaries are employing sophisticated techniques such as Direct Kernel Object Manipulation (DKOM) to manipulate the Windows object manager's namespace.
- [UNCERTAIN] Adversaries might be using CoolClient's rootkit component to modify system files or executables, such as lsass.exe or svchost.exe, to ensure ongoing execution and evade detection by leveraging legitimate process integrity checks.
- Indicators of a kernel-level compromise from this backdoor could include unexpected behavior in the Windows Object Manager namespace, unusual entries in the registry related to system drivers, and anomalies in device driver listings.
- Security professionals should monitor for signs of unauthorized or modified kernel-mode code execution, such as unexpected messages logged by Device Guard or CredentialGuard, which can indicate attempts at rootkit deployment.

This includes monitoring driver-level activities, anomalous registry modifications, and deviations from baseline file system operations.

### Key Fields
- process_creation: Monitor for unexpected or unauthorized processes being created by kernel-mode drivers, especially those that are unsigned or have unusual names (10% populated).
