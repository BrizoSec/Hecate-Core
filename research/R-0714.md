## 1. System Research: How It Works

### Summary
The Blinder Tunnel campaign targets Iraqi critical infrastructure by leveraging a trojanized Visual Studio project disguised as a Dubai Airports recruitment coding test. This malware executes via legitimate developer build tooling, deploying payloads before the victim compiles any code, thereby bypassing traditional detection mechanisms.

### Key Findings
- The attack vector involves a fake recruitment lure for 'Dubai Airports' that distributes a malicious Visual Studio project, exploiting trusted developer environments to initiate compromise.
- Malware deployment occurs during the build process using legitimate tooling, specifically leveraging AppDomainManager and potentially Agent Serpens components, allowing execution prior to code compilation.
- Command-and-control (C2) infrastructure is covertly hosted on GitHub, utilizing compromised or malicious accounts (such as johnshelllby and arturshellby) to obscure network-layer detection without specific behavioral controls.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The Iranian state-aligned threat actor CL-STA-1178 targets Iraqi critical infrastructure by impersonating Dubai Airports' IT department to distribute trojanized coding challenges via social engineering. This attack chain utilizes AppDomainManager hijacking and DLL sideloading to deploy ShelbyLoader V2, leveraging GitHub repositories and issues for command-and-control communications.

### Key Findings
- The campaign is attributed to the Iranian state-aligned threat actor CL-STA-1178, with infrastructure preparation observed in November 2025 and active targeting of Iraqi critical infrastructure beginning in March 2026.
- Social engineering lures are crafted as fake recruitment materials from Dubai Airports' IT department, specifically delivering trojanized coding challenges to victims.
- The malware deployment relies on a multi-stage technique involving AppDomainManager hijacking and DLL sideloading to execute ShelbyLoader V2.
- Command-and-control (C2) infrastructure is hosted on GitHub, utilizing repositories and issues as primary and fallback communication channels.
- The campaign incorporates cultural references from the television show 'Peaky Blinders' within its infrastructure and malware components.

## 5. Research Synthesis

### Executive Summary
The Blinder Tunnel campaign, attributed to Iranian threat actor CL-STA-1178, compromises Iraqi critical infrastructure by delivering trojanized Visual Studio projects disguised as Dubai Airports recruitment tests. The attack chain exploits legitimate developer tooling via AppDomainManager hijacking and DLL sideloading to execute ShelbyLoader V2 prior to code compilation, utilizing GitHub repositories for covert command-and-control communications.

### Recommended Hypothesis
> Adversaries use AppDomainManager hijacking and DLL sideloading within trusted Visual Studio build processes to deploy ShelbyLoader V2 and establish GitHub-hosted C2 channels on Iraqi critical infrastructure.

### Gaps Identified
- Lack of visibility into pre-compilation execution phases means standard endpoint detection tools may miss the initial payload deployment, as malicious code runs during the legitimate build hook before any source code is processed.
- Network monitoring often fails to detect this activity because C2 traffic is blended into standard GitHub API requests via HTTP/HTTPS, evading traditional domain reputation checks that do not analyze repository issue content or specific account behaviors (e.g., johnshelllby).

### Key Findings
- Hypothesis: Adversaries use AppDomainManager hijacking and DLL sideloading within trusted Visual Studio build processes to deploy ShelbyLoader V2 and establish GitHub-hosted C2 channels on Iraqi critical infrastructure.
- Gap: Lack of visibility into pre-compilation execution phases means standard endpoint detection tools may miss the initial payload deployment, as malicious code runs during the legitimate build hook before any source code is processed.
- Gap: Network monitoring often fails to detect this activity because C2 traffic is blended into standard GitHub API requests via HTTP/HTTPS, evading traditional domain reputation checks that do not analyze repository issue content or specific account behaviors (e.g., johnshelllby).
- Focus: Implement behavioral analysis on process cmd_line arguments and module loading sequences for Visual Studio-related processes (devenv.exe) to detect anomalies in build tooling usage.
- Focus: Monitor outbound network connections to GitHub APIs for unusual patterns, such as rapid repository cloning or issue creation/comments from unexpected developer accounts, correlating with local file system activity in user project directories.
