## 1. System Research: How It Works

### Summary
Samsung MagicINFO is a digital signage platform that operates as a Java web application deployed on an embedded Apache Tomcat server. The vulnerability CVE-2025-4632 allows attackers to write arbitrary files with system authority, bypassing standard access controls.

### Key Findings
- The attack chain leverages the Apache Tomcat service (tomcat9.exe) as the parent process for all malicious activities, including downloading rogue AnyDesk and disabling Microsoft Defender via SystemSettingsAdminFlows.exe.
- The threat actor used three distinct methods to deploy AnyDesk: initial failed attempts using certutil.exe and PowerShell Invoke-WebRequest, followed by a successful download from IP 194.87.89.30.
- Cryptominer compilation was performed on-endpoint using Silent XMR Miner Builder.exe, which spawned multiple .NET utilities (csc.exe, cvtres.exe) and C compilers (donut.exe, tcc.exe, MinGW64 cc1.exe/gcc.exe).
- The resulting Monero cryptominer executed under explorer.exe with explicit mining arguments connecting to c3pool.org, including '--url=auto.c3pool.org:19999' and specific algorithm flags like '--algo="rx/0"'.
- Defender was disabled using SystemSettingsAdminFlows.exe, and persistence was established by creating a local administrator account named 'oldadministrator' with the same password used for AnyDesk.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
A threat actor exploited a Samsung MagicINFO vulnerability to deploy a rogue AnyDesk instance, after which they uniquely compiled a Monero cryptominer directly on the endpoint using 'Silent XMR Miner Builder.exe' rather than dropping a pre-compiled binary. This on-device compilation process invoked multiple .NET and C compilers, generating conspicuous EDR telemetry that facilitated detection despite the adversary's attempts to remain stealthy.

### Key Findings
- Initial access was gained via exploitation of Samsung MagicINFO vulnerability CVE-2025-4632, which allowed arbitrary file writes as system authority.
- The actor deployed a rogue AnyDesk Remote Management Tool (RMM) after three attempts using different download methods (certutil and PowerShell), eventually succeeding through the Apache Tomcat service (tomcat9.exe).
- Post-compromise persistence and evasion included creating a local administrator account named 'oldadministrator' and disabling Microsoft Defender protections using SystemSettingsAdminFlows.exe.
- The threat actor compiled a Monero cryptominer on the endpoint using 'Silent XMR Miner Builder.exe', executing .NET utilities (csc.exe, cvtres.exe) and C compilers (donut.exe, tcc.exe, MinGW64 cc1.exe/gcc.exe).
- The resulting miner connected to the C3Pool mining service and ran under explorer.exe with suspicious command-line arguments, such as --algo="rx/0" and --url=auto.c3pool.org:19999, which are not normal for legitimate Windows Explorer.

## 5. Research Synthesis

### Executive Summary
This research identifies a threat actor leveraging Samsung MagicINFO CVE-2025-4632 to deploy a rogue AnyDesk instance and subsequently compile a Monero cryptominer directly on the endpoint using Silent XMR Miner Builder.exe. The adversary utilized multiple C and .NET compilers (tcc, MinGW, csc) within the tomcat9.exe process context, generating high-volume EDR telemetry from unsigned parent processes that ironically facilitated detection despite the attempt at stealth.

### Recommended Hypothesis
> Adversaries use on-endpoint compilation of cryptominers via Silent XMR Miner Builder.exe to evade pre-execution signature detection while maintaining persistence through rogue RMM tools and disabled security controls.

### Gaps Identified
- EDR solutions may lack behavioral correlation for unsigned parent processes (e.g., tomcat9.exe) spawning multiple distinct compiler binaries (gcc, tcc, csc), potentially allowing the build phase to blend into legitimate software development or patching activities if not explicitly flagged.
- Detection of cryptominer execution relies heavily on command-line inspection of injected processes (explorer.exe); if the actor successfully hides or obfuscates the mining arguments within the process memory rather than exposing them in the visible command line, detection fidelity drops significantly.

### Key Findings
- Hypothesis: Adversaries use on-endpoint compilation of cryptominers via Silent XMR Miner Builder.exe to evade pre-execution signature detection while maintaining persistence through rogue RMM tools and disabled security controls.
