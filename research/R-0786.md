## 1. System Research: How It Works

### Summary
A Python-based Malware-as-a-Service builder generates customized Windows infostealer executables by embedding XOR-encoded and Base64-encoded webhook URLs into payloads compiled via Nuitka or PyInstaller. The resulting payload executes anti-analysis checks, harvests sensitive data from browsers and applications, and exfiltrates the information to attacker-controlled webhooks.

### Key Findings
- The builder employs automatic dependency installation by invoking pip.exe at startup, which can serve as a behavioral detection indicator in clean environments.
- Webhook URLs are obfuscated using XOR encoding with key 0x5A followed by Base64 encoding, preventing static signature detection based on plaintext endpoints and ensuring unique binary hashes per operator configuration.
- The payload utilizes anti-VM and anti-analysis techniques including IsDebuggerPresent API calls, process blacklisting for hypervisors (VirtualBox, Xen, QEMU), disk size heuristics (<50 GB exit), and timing-based evasion.
- Data exfiltration is performed via attacker-controlled webhooks, with stolen credentials, cookies, and session tokens packaged into in-memory ZIP archives before transmission.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The Stealer Factory is a Python-based Malware-as-a-Service (MaaS) builder that enables adversaries to generate customized Windows infostealer executables using Nuitka or PyInstaller compilation. It automates dependency installation and embeds XOR/Base64-encoded webhook URLs for exfiltration, allowing operators with limited technical knowledge to deploy scalable credential theft campaigns.

### Key Findings
- The builder employs a 'dependency auto-installation' mechanism that invokes pip.exe at runtime to resolve libraries, providing a behavioral indicator of compromise in clean environments.
- Compiled payloads utilize anti-analysis techniques including IsDebuggerPresent API calls, hypervisor process blacklisting (e.g., VirtualBox, QEMU), disk size heuristics (>50GB check), and timing evasion to avoid sandbox detection.
- Webhook URLs are obfuscated using XOR encoding with key 0x5A followed by Base64 encoding before injection, preventing plaintext signature detection and allowing unique binary hashes per operator.
- The infostealer payload harvests credentials, cookies, and credit card data from Chromium and Firefox browsers, as well as Wi-Fi passwords, Discord tokens, and Roblox session cookies.
- Persistence is established via Windows Registry Run keys (Software\Microsoft\Windows\CurrentVersion\Run) and scheduled tasks created using schtasks commands.

## 5. Research Synthesis

### Executive Summary
The 'Stealer Factory' is a Python-based Malware-as-a-Service builder that compiles customized infostealers using Nuitka or PyInstaller, obfuscating exfiltration endpoints via XOR (key 0x5A) and Base64 encoding to evade static signatures. The resulting payloads employ aggressive anti-analysis techniques, including hypervisor process blacklisting, disk size heuristics, and timing evasion, while harvesting credentials from browsers and applications for webhook exfiltration.

### Recommended Hypothesis
> Adversaries use a Python-based MaaS builder with Nuitka/PyInstaller compilation to deploy customized infostealers that evade sandbox detection via hypervisor blacklisting and disk heuristics, ultimately exfiltrating stolen credentials through XOR/Base64-obfuscated webhooks.

### Gaps Identified
- Static analysis tools cannot easily detect the XOR (0x5A) obfuscated webhook URLs embedded in compiled binaries, and dynamic analysis sandboxes may be bypassed by disk size (<50 GB) and timing-based evasion checks before data collection occurs.
