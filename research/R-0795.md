## 1. System Research: How It Works

### Summary
This threat involves a cluster of malicious Chrome extensions masquerading as VPN services that intercept browser traffic by dynamically fetching proxy configurations from remote hosting platforms like GitHub Pages and Telegram. The architecture allows operators to remotely control traffic routing and modify server lists without requiring extension updates, effectively turning user browsers into nodes in a proxy farm.

### Key Findings
- The extensions utilize a dynamic configuration mechanism that fetches obfuscated proxy server lists and credentials from third-party services such as GitHub Pages, Blogspot, Google Docs, and Telegram channels after installation, enabling real-time traffic interception without code updates.
- The malicious cluster consists of 31 Russian-language Chrome extensions sharing a single codebase, published via three linked Google accounts, with the flagship 'RuTracker VPN' extension accounting for approximately 200,000 of the total 356,000 affected users.
- Threat actors employ a monetization strategy by offering a paid VIP tier for 299 roubles and have reused hostnames associated with legitimate services like Browsec VPN premium servers to potentially obscure their infrastructure or imply legitimacy.

This architecture allows operators to alter traffic routing and intercept data without releasing extension updates, targeting approximately 356,000 users through extensive proxy permissions.

### Key Findings

- Extensions dynamically retrieve proxy server configurations from external platforms such as GitHub Pages, Blogspot, Google Docs, and Telegram channels, enabling real-time traffic interception and routing changes without requiring extension updates.
- The operation targets users of blocked services including RuTracker, YouTube, Telegram, Netflix, and ChatGPT, with the flagship 'RuTracker VPN' extension alone accounting for 200,000 installations out of a total estimated 356,000 affected users.

## 5. Research Synthesis

### Executive Summary
This threat cluster leverages 31 Russian-language Chrome extensions masquerading as VPN services to establish a dynamic proxy farm, utilizing remote configuration fetching from GitHub Pages and Telegram to alter traffic routing without code updates. The architecture enables real-time interception of user traffic through shared credentials and obfuscated server lists, with infrastructure partially overlapping legitimate Browsec VPN hostnames to evade detection.

### Recommended Hypothesis
> Adversaries use dynamically fetched proxy configurations from third-party hosting services (GitHub Pages, Telegram) within Chrome extensions to route user traffic through a centralized proxy farm for interception and monetization.

### Gaps Identified
- Current telemetry lacks visibility into outbound HTTPS requests from the 'chrome.exe' process specifically targeting dynamic configuration endpoints like 'mainapi.store', 'api.hhos.ru', or 'de34.rapidstaticserve.cc', allowing C2-like configuration pulls to go undetected.
- Endpoint detection systems fail to correlate file creation events in '%LOCALAPPDATA%\Google\Chrome\User Data\Default\Extensions' with subsequent network connections to known malicious hostnames, missing the persistence and command-and-control initiation phase.

### Key Findings
- Hypothesis: Adversaries use dynamically fetched proxy configurations from third-party hosting services (GitHub Pages, Telegram) within Chrome extensions to route user traffic through a centralized proxy farm for interception and monetization.
- Gap: Current telemetry lacks visibility into outbound HTTPS requests from the 'chrome.exe' process specifically targeting dynamic configuration endpoints like 'mainapi.store', 'api.hhos.ru', or 'de34.rapidstaticserve.cc', allowing C2-like configuration pulls to go undetected.
- Gap: Endpoint detection systems fail to correlate file creation events in '%LOCALAPPDATA%\Google\Chrome\User Data\Default\Extensions' with subsequent network connections to known malicious hostnames, missing the persistence and command-and-control initiation phase.
- Focus: Monitor for network egress from browser processes to domains associated with dynamic content hosting (GitHub Pages, Blogspot, Google Docs) that are not whitelisted for standard application functionality, specifically looking for JSON or obfuscated text payloads indicative of proxy lists.
- Focus: Hunt for the installation of unpacked Chrome extensions by detecting unusual process arguments involving 'crx_unpacker' or direct loading of local CRX files into 'chrome.exe', combined with file integrity monitoring on extension directories for new folders containing SHA256 hashes matching the provided indicators.
