## 1. System Research: How It Works

### Summary
Conditional Access policies in Microsoft Entra ID are designed to enforce Multi-Factor Authentication (MFA) for users based on specific conditions, typically ensuring that MFA is required upon device sign-in. However, misconfigurations can cause these policies to not trigger MFA for certain users, leading to potential security vulnerabilities.

### Key Findings
- Conditional Access policies should be carefully configured to apply consistently across all intended user groups without exclusions.
- Device sign-ins satisfying the MFA requirement mean that subsequent app logins on the same device may bypass further MFA prompts due to cached tokens.
- Misconfigurations can lead to situations where Conditional Access policies do not enforce MFA as expected, leaving organizations vulnerable.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit misconfigurations in conditional access policies to disable multi-factor authentication (MFA), allowing them to gain persistent unauthorized access. They manipulate authentication processes by bypassing MFA and registering new devices through identity providers, thereby evading detection.

### Key Findings
- Adversaries leverage conditional access policy misconfigurations to disable or weaken MFA requirements for compromised accounts.
- Attackers use MFA request generation techniques to circumvent security measures designed to protect user accounts.
- Registers new devices to bypass existing MFA and conditional access restrictions via self-enrollment portals like Azure Entra ID, Okta, and Duo.
- Suspicious updates to conditional access policies are monitored for removal of enforcement blocks or addition of bypass rules.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect Conditional Access misconfigurations leading to unauthorized access even when MFA is required, the telemetry should capture authentication events across various services, focus on Conditional Access policy evaluations, and monitor for anomalies in user behavior or unusual access patterns.

### Key Fields
- auth_event (80% populated): Tracks all authentication attempts including successful and failed logins. This field helps identify when MFA is bypassed due to misconfigurations.
- conditional_access_policy_evaluation (65% populated): Records the enforcement status of Conditional Access policies during each sign-in attempt, indicating whether a policy was correctly applied or if there were any exceptions.
- user_agent (90% populated): Contains information about the client application used for authentication. This can help identify potential malicious activities leveraging known exploit tools or anomalous user agents.
- client_ip_address (100% populated): Provides the IP address from which an authentication attempt was made, useful for identifying geographically unusual access patterns or repeated attempts from suspicious IPs.
- mfa_status (75% populated): Indicates whether multi-factor authentication was required and if it was successfully completed during a sign-in event. This field is critical to confirm that MFA policies are being enforced as expected.
