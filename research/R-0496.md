## 1. System Research: How It Works

### Summary
Falcon Onum is a real-time data processing and enrichment tool that works with CrowdStrike's SIEM to filter out unnecessary telemetry, reduce storage costs, and enhance the quality of security-relevant information. It processes fragmented raw data into structured, enriched data sets that are useful for threat detection and response.

### Key Findings
- Falcon Onum significantly reduces noise in telemetry data by filtering out irrelevant information, thereby improving signal-to-noise ratio.
- The system enriches raw security data with contextual details such as geographical location through integration with services like GeoIP.
- By working alongside CrowdStrike's Falcon Next-Gen SIEM, Falcon Onum helps in detecting and responding to threats faster by providing high-fidelity data.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries may abuse Falcon Onum by leveraging data exfiltration techniques that are not yet fully understood or detected by the system's AI-driven UEBA capabilities. They could also exploit vulnerabilities in the SIEM migration process, potentially using impossible traveler scenarios to mask their movements.

### Key Findings
- Adversaries use shell command obfuscation on VMware ESX to evade detection by Falcon Onum’s threat hunting mechanisms.
- Data exfiltration techniques are employed through novel methods that can bypass traditional UEBA rules and require advanced AI-driven analytics for identification.
- Impossible traveler scenarios, such as unusual travel patterns or rapid geographical transitions in logins, can be leveraged by adversaries to obscure their movements and activities.
- Adversaries may exploit the SIEM migration process to introduce malicious activity undetected due to potential disruptions and vulnerabilities during system integration.

## 3. Telemetry Mapping: OCSF Fields

### Summary
The detection focuses on identifying anomalous process execution and file access patterns that suggest an unauthorized privilege escalation attempt.

### Key Fields
- process.name (95% populated): The name of the executable that was run, which can indicate if a standard user is executing administrative tasks.
- event.category (85% populated): Categorizes events as 'authentication', 'privilege', or 'process' to filter for privilege changes and process creation.
- file.path (70% populated): The full path of the file being accessed, which can reveal attempts to modify system configuration files that require elevated privileges.
- event.type (90% populated): Describes specific events such as 'process_creation', 'file_change', or 'user_login' to identify key actions in a sequence of privilege escalation.
- user.name (85% populated): The username associated with the event, which is crucial for identifying if standard users are performing administrative tasks.
