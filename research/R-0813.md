## 1. System Research: How It Works

### Summary
AutoCAD DWG files can contain embedded OLE objects that store VBA (Visual Basic for Applications) projects, which are structurally distinct from the drawing data itself. These embedded projects can be extracted using specialized tools like autocad.py and cut-bytes.py, then analyzed with oledump.py to inspect the code.

### Key Findings
- DWG files may harbor orphaned VBA projects within their header structures as embedded OLE objects, separate from the primary drawing geometry.
- Embedded VBA content can be carved out of DWG files using a combination of autocad.py and cut-bytes.py scripts for subsequent analysis.
- The extracted OLE streams containing VBA code can be inspected in detail using oledump.py to reveal the stored macros.
- AutoLISP provides a mechanism to remove VBA projects from DWG files via the command (dictremove (namedobjdict) "ACAD_VBA").

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse AutoCAD drawing files (.dwg) by embedding malicious Visual Basic for Applications (VBA) projects within the file structure. This technique allows attackers to store executable code directly inside legitimate engineering documents, which can be executed when the file is opened in compatible software.

### Key Findings
- AutoCAD DWG files serve as a delivery mechanism for malware by hiding embedded OLE objects that contain VBA code, leveraging the trust users place in engineering files.
- The presence of an orphaned or hidden VBA project within a DWG file is a key indicator of compromise, often requiring specialized extraction to detect.
- Attackers may utilize specific tools like 'autocad.py' and 'cut-bytes.py' to carve DWG files and extract embedded OLE streams for analysis or further exploitation.
- Once extracted, the malicious VBA project can be analyzed using forensic tools such as 'oledump.py' to identify payload behavior or malicious macros.
- Defenders can attempt to remediate infected files by removing the VBA component from the drawing database using AutoLISP commands like '(dictremove (namedobjdict) "ACAD_VBA")'.
