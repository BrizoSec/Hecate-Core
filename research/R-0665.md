## 1. System Research: How It Works

### Summary
CLOSEDQUORUM is a Go-based Windows implant that autonomously executes tactical command and control by querying four commercial LLM providers (DeepSeek, Qwen, Mistral, Gemini) to vote on its next action. It aggregates these structured responses via plurality voting within an orchestrator and dispatches the resulting decision to capability modules for execution without human intervention.

### Key Findings
- The implant utilizes a model orchestration architecture where main.queryLLM() dispatches prompts to multiple LLM providers, with results aggregated into an []LLMDecision slice and resolved by interModelDiscussion() via plurality voting.
- During initialization, the gatherSystemInfo() API captures static host telemetry (hostname, OS architecture, CPU count, Windows version, admin status) which is stored as TARGET:%s context to inform subsequent LLM decision-making.
- The implant executes a range of capabilities including credential theft (lsassDump(), dumpBrowserCredentials(), extractCryptoWallets()), code injection (generateShellcode() for process_hollow or earlyBirdInject/APC), and persistence establishment via establishPersistence().
- Decision rationale, including the LLM's Reasoning field and the final action, is exfiltrated to an attacker-controlled Discord server via webhook, indicating a specific C2 communication channel distinct from standard malware traffic patterns.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
CLOSEDQUORUM is a Windows implant that autonomously executes tactical command-and-control decisions by querying up to four commercial large language models (DeepSeek, Qwen, Mistral, and Google Gemini) and aggregating their responses via plurality voting with DeepSeek as the tie-breaker. This architecture displaces human operator involvement in post-compromise operations, allowing the malware to independently select and execute capabilities such as credential theft and process injection based on real-time environmental context.

### Key Findings
- The implant utilizes an 'interModelDiscussion' mechanism where responses from multiple LLM providers are aggregated into a single action via plurality voting, with DeepSeek breaking ties.
- The malware autonomously decides to execute the 'steal' capability, which simultaneously invokes lsassDump(), dumpBrowserCredentials(), and extractCryptoWallets().
- Post-exploitation actions are driven by a 'Reasoning' field that preserves the LLM's rationale at execution time, allowing the system to dynamically route to modules like injectProcess() or earlyBirdInject() based on the voted decision.
- The operator receives stolen data via Discord, indicating that while tactical decisions are autonomous, final exfiltration and command verification may still rely on external communication channels.
- The malware gathers system information (hostname, OS architecture, CPU count, Windows version, admin status) during initialization to create a 'TARGET:%s' context used in each LLM prompt.
- The lateral movement capability ('move') is present in the code structure but is non-functional in the analyzed samples, whereas persistence is established via establishPersistence().

## 5. Research Synthesis

### Executive Summary
CLOSEDQUORUM is a novel Go-based Windows implant that replaces static C2 logic with an autonomous orchestration layer querying multiple commercial LLMs (DeepSeek, Qwen, Mistral, Gemini) to vote on tactical actions via plurality voting. This architecture enables dynamic, operator-independent execution of credential theft, process injection, and persistence modules, exfiltrating both stolen data and the AI's decision rationale to Discord webhooks.

### Recommended Hypothesis
> Adversaries use autonomous LLM-plurality voting mechanisms to dynamically select and execute post-exploitation capabilities (credential theft, process hollowing) without human intervention on Windows endpoints.

### Gaps Identified
- Current EDR telemetry often lacks correlation between the 'Reasoning' field exfiltrated via Discord webhooks and the specific API calls invoked by the implant (e.g., lsassDump, injectProcess), making it difficult to attribute autonomous decision-making events to a single malicious binary.
- Detection of the underlying LLM provider APIs (DeepSeek, Qwen, Mistral, Gemini) is often obscured by generic TLS SNI patterns or legitimate-looking API gateway traffic, failing to distinguish them from standard application telemetry or update checks.

### Key Findings
- Hypothesis: Adversaries use autonomous LLM-plurality voting mechanisms to dynamically select and execute post-exploitation capabilities (credential theft, process hollowing) without human intervention on Windows endpoints.
- Gap: Current EDR telemetry often lacks correlation between the 'Reasoning' field exfiltrated via Discord webhooks and the specific API calls invoked by the implant (e.g., lsassDump, injectProcess), making it difficult to attribute autonomous decision-making events to a single malicious binary.
- Gap: Detection of the underlying LLM provider APIs (DeepSeek, Qwen, Mistral, Gemini) is often obscured by generic TLS SNI patterns or legitimate-looking API gateway traffic, failing to distinguish them from standard application telemetry or update checks.
- Focus: Monitor for unusual outbound HTTPS connections to known LLM provider domains or IP ranges, specifically looking for structured JSON payloads containing keys like 'Reasoning', 'Decision', or 'TARGET:%s' that correlate with local process creation events (e.g., lsass.exe access or shellcode generation).
