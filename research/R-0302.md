## 1. System Research: How It Works

### Summary
SANDWORM_MODE represents an advanced form of supply chain attack that leverages AI tools for automation, rapid propagation, and sophisticated evasion techniques. Organizations need proactive detection mechanisms to identify anomalous behaviors indicative of this threat.

### Key Findings

- Supply chain compromise often involves the injection of malicious code into trusted software packages or dependencies during development stages.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit the npm ecosystem by compromising legitimate accounts to publish malicious packages that self-replicate and spread within the developer community. These packages are designed to harvest credentials and integrate AI-generated content, making detection challenging.

### Key Findings
- SANDWORM_MODE leverages existing publishing rights in the npm ecosystem for package distribution.
- Malicious packages use self-replication techniques to propagate widely across developers' systems.
- Adversaries employ AI tools to generate convincing and deceptive content within compromised packages, complicating detection efforts.
- The attack involves harvesting credentials to gain access to additional accounts and extend its reach within the supply chain.
- Monitoring unusual activity in npm package repositories is crucial for early detection of such threats.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry capturing this behavior would include anomalies in source code changes, unauthorized access to CI/CD pipelines, unusual binary file uploads or downloads, and deviations from normal network communication patterns related to the AI toolchain supply chain.

### Key Fields
- code_repository_changes: This field tracks modifications made to critical project repositories. Population rate is estimated at 95% in development environments where version control systems are heavily utilized.
- ci_cd_pipeline_access_logs: These logs capture accesses and actions performed within CI/CD pipelines, such as job executions and environment configurations. Population rate is around 80-100%. Unauthorized access or unusual operations can indicate a compromise.
- network_traffic_analysis_binary_transfers: This field monitors for atypical binary file transfers over the network that do not conform to baseline norms. It includes tracking of file sizes, transfer times, and source/destination IP addresses. Population rate is highly variable but critical in environments with strict change control procedures (50-90%).
- authentication_and_authorization_logs: Tracks authentication attempts and authorization decisions across systems, especially those pertaining to privileged access management for sensitive resources like AI model repositories or build servers. Population rate varies widely but is often near 100% in monitored environments.
- file_integrity_monitoring_changes: This captures changes made to files that are critical for system integrity (such as configuration files, scripts used in CI/CD processes). Any unexpected modifications can indicate tampering with the supply chain or toolchain. Population rate typically ranges from 85-100% in environments where file integrity is closely monitored.
- dns_queries: This field records DNS queries made by systems accessing external resources during build and deployment phases. Unusual domain resolutions, especially to known malicious IPs or newly registered domains, could signify exfiltration attempts or command-and-control communications. Population rate can range from 60-95% depending on the monitoring capabilities.
