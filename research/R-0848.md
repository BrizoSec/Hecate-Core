## 1. System Research: How It Works

### Summary
The WatchGuard Mobile VPN client functions by establishing an SSL-based secure tunnel for remote network access, typically distributed via the official software.watchguard.com domain. In this specific incident, a phishing campaign impersonated the legitimate download experience but utilized browser pop-ups to exfiltrate credentials to a separate C2 domain before silently loading the genuine, signed installer from WatchGuard's official CDN.

### Key Findings
- The attacker utilized SEO poisoning on watchguard-vpn.net and watchguard-vpn.com to serve a fake 'WatchGuard Support Page' that mimicked legitimate download options for various OS configurations.
- Credential exfiltration was performed via JavaScript (popup.js) wrapping user input in JSON and posting it to the C2 domain watchguard-ssl.online, with a deliberate first submission rejection mechanism to force a second credential attempt.
- To evade detection of malicious payloads, the phishing site downloaded the authentic, validly signed WatchGuard installer (WG-MVPN_SSL_12_11_5.exe) directly from the official CDN URL cdn.watchguard.com/SoftwareCenter/Files/MUVPN_SSL/12_11_5/.
- The infrastructure for the credential collection endpoint (watchguard-ssl.online) resolved to IP 158.94.209.19 hosted by Omegatech LTD, while previous iterations of the domain had resolved to 74.208.236.39.
- Defenders should rely on official sources like software.watchguard.com for client downloads and be wary of domains using legitimate CDN links to deliver signed installers after capturing credentials.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse legitimate software distribution channels by hosting a phishing site that mimics a WatchGuard VPN download page, but instead of serving malicious payloads, the script downloads the genuinely signed, official client from WatchGuard's CDN to evade detection. This technique allows attackers to collect credentials via deceptive pop-ups while ensuring the installed application remains trusted and functional for subsequent lateral movement.

### Key Findings
- The campaign utilizes a 'Clean Install' strategy where the phishing page serves the legitimate, validly signed WatchGuard installer (WG-MVPN-SSL_12_11_5.exe) from the official CDN (cdn.watchguard.com) rather than hosting malicious files.
- Credential theft is achieved through browser pop-ups that capture input twice, deliberately rejecting the first submission to ensure multiple password attempts are collected before forwarding data to the C2 server.
- The attack infrastructure relies on SEO poisoning to drive traffic to fake domains (watchguard-vpn.net and watchguard-vpn.com) that mimic official support pages, with credential data exfiltrated to watchguard-ssl.online.
- The phishing logic is implemented using minimal, unobfuscated JavaScript (popup.js), reducing complexity and potential detection triggers while relying on the legitimacy of the final downloaded executable for stealth.
- Indicators include specific domains (watchguard-vpn.net, watchguard-ssl.online) and IPs (158.94.209.19, 80.249.132.140), with the credential collection endpoint resolving to hosting providers in Amsterdam and Netherlands.

## 5. Research Synthesis

### Executive Summary
Adversaries deploy SEO-poisoned sites impersonating WatchGuard VPN to execute credential harvesting via JavaScript-based pop-ups, deliberately rejecting initial submissions to capture multiple password attempts. To evade endpoint detection, the attack infrastructure retrieves the legitimately signed, genuine WatchGuard installer from official CDNs while exfiltrating collected credentials in JSON format to a separate C2 domain.

### Recommended Hypothesis
> Adversaries use SEO-poisoned phishing sites and legitimate CDN-sourced installers to harvest credentials and deploy trusted VPN clients for persistent network access.

### Gaps Identified
- Lack of DNS telemetry mapping for the credential exfiltration domain watchguard-ssl.online and historical C2 IPs (80.249.132.140, 158.94.209.19) hinders detection of the initial data theft phase.
- Inability to correlate browser-based JSON POST requests with subsequent legitimate executable downloads from cdn.watchguard.com makes it difficult to distinguish this specific credential-stealing workflow from standard software updates.
