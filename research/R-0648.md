## 1. System Research: How It Works

### Summary
SocGholish (FakeUpdates) typically operates by tricking users into downloading a malicious JavaScript payload disguised as a software update from compromised websites. Once executed, it profiles the victim's system via obfuscated WScript commands to download secondary payloads and establishes persistence through scheduled tasks and registry modifications.

### Key Findings
- The malware utilizes JavaScript embedded in compromised sites or HTML smuggling to profile the victim's system before downloading a secondary payload via WScript commands from %APPDATA%\Local\Temp.
- Persistence is achieved by creating scheduled tasks named "UpdateCheck" (e.g., schtasks /create /sc minute /mo 15 /tn "UpdateCheck") and modifying registry run keys.
- The campaign targets election infrastructure in Washington state using electorally themed phishing emails with links to look-alike domains such as wa-elections-support.com and secure-voter-wa.org.
- SocGholish is associated with the MITRE ATT&CK technique T1053.005 for scheduled task persistence and commonly employs 19 techniques including T1082, T1614, T1047, T1105, and T1027.013.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
SocGholish (FakeUpdates) adversaries abuse compromised websites and phishing emails to deliver malicious JavaScript disguised as software updates, facilitating initial access and subsequent system profiling. This technique allows threat actors to execute obfuscated commands that download secondary payloads and establish persistence, with recent activity specifically targeting election infrastructure and officials in Washington state.

### Key Findings
- SocGholish primarily gains initial access by presenting victims with a compromised website or phishing lure that deceives them into downloading malicious JavaScript under the guise of a necessary browser or software update.
- The malware functions as a JavaScript-based downloader that profiles the victim's system using embedded JavaScript and executes obfuscated WScript commands to download secondary payloads from C2 servers.
- A specific targeted campaign has been observed directing this malware at Washington state election officials and political organizations ahead of November elections, utilizing electorally themed lures and look-alike domains such as wa-elections-support.com.
- Adversaries are leveraging SocGholish for reconnaissance beyond initial access, including potential DDoS attacks against election websites to erode public confidence, in addition to targeting networks housing voter registration databases.
- The malware maintains persistence on compromised systems by creating scheduled tasks named 'UpdateCheck' and modifying registry run keys, with recent incidents linked to hands-on keyboard activity in April 2024.

## 5. Research Synthesis

### Executive Summary
Adversaries are executing a SocGholish campaign targeting Washington state election infrastructure via electorally themed phishing, leveraging compromised websites and HTML smuggling to deliver obfuscated JavaScript that profiles victims and establishes persistence through scheduled tasks. Detection strategies must prioritize monitoring for WScript execution from temporary directories and specific schtasks persistence mechanisms rather than relying on static IP indicators which currently lack enrichment.

### Recommended Hypothesis
> Adversaries use obfuscated WScript commands executed via HTML smuggling to download secondary payloads and create scheduled tasks named 'UpdateCheck' to establish persistence on election infrastructure networks.

### Gaps Identified
- Current telemetry sources lack visibility into the specific JavaScript profiling techniques (T1082, T1614) used by SocGholish to fingerprint victim environments before payload delivery, relying solely on post-execution C2 indicators which are currently unenriched.
- There is no defined detection logic for the specific persistence mechanism 'schtasks /create /sc minute /mo 15 /tn "UpdateCheck"', creating a window for lateral movement undetected by generic scheduled task alerts.

### Key Findings
- Hypothesis: Adversaries use obfuscated WScript commands executed via HTML smuggling to download secondary payloads and create scheduled tasks named 'UpdateCheck' to establish persistence on election infrastructure networks.
- Gap: Current telemetry sources lack visibility into the specific JavaScript profiling techniques (T1082, T1614) used by SocGholish to fingerprint victim environments before payload delivery, relying solely on post-execution C2 indicators which are currently unenriched.
- Gap: There is no defined detection logic for the specific persistence mechanism 'schtasks /create /sc minute /mo 15 /tn "UpdateCheck"', creating a window for lateral movement undetected by generic scheduled task alerts.
- Focus: Hunt for high-frequency outbound HTTP/HTTPS connections to unknown ASN owners from endpoints executing WScript or JavaScript engines, specifically looking for the 'WScript.exe' parent-child process relationship originating from browser or email client processes.
- Focus: Deploy behavioral detection rules for the creation of scheduled tasks with the specific name 'UpdateCheck' and high-frequency recurrence (every 15 minutes) via schtasks.exe, correlating these events with file system writes in %APPDATA%\Local\Temp.
