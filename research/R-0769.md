## 1. System Research: How It Works

### Summary
Under normal operation, Google Chrome and Microsoft Windows handle web content rendering and system privilege management through standard, isolated processes without executing arbitrary code from untrusted sources or modifying file integrity markers like the Mark of the Web. Network communications for legitimate applications typically use standard HTTPS headers and domains associated with verified services, rather than encrypted payloads masquerading as user-agent strings to typosquatting domains.

### Key Findings
- The attack leverages a chained exploit targeting Chrome vulnerabilities (CVE-2026-85046, CVE-2026-87491) and a Windows privilege escalation vulnerability (CVE-2026-85880) to execute 'chrome_cleanup.exe' in-process.
- The malware utilizes a technique to strip the 'Mark of the Web' from downloaded binaries and executes them via COM objects to evade detection, replacing standard command-line execution methods.
- CLEANGULP malware installs itself as '%LOCALAPPDATA%\Microsoft\IME\MicrosoftIME.exe' and establishes persistence through a scheduled task named 'MicrosoftIME'.
- C2 communication is conducted over HTTP to the typosquatting domain 'thecovnresation[.]com', using AES-256-GCM encryption and Base64 encoding with a custom alphabet for payload transmission.
- The exploit kit was delivered via phishing emails linking to spoofed domains impersonating legitimate organizations such as 'chinadigitaltimes.net' and 'americanprogress.org'.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Chinese threat actor UTA0565 leveraged a chained zero-day exploit targeting Google Chrome (CVE-2026-85046, CVE-2026-87491) and Microsoft Windows (CVE-2026-85880) via phishing emails containing links to typosquat domains impersonating legitimate organizations. These fake websites hosted an exploit kit that deployed CLEANGULP, a previously undocumented malware family with backdoor capabilities, which communicated with command-and-control infrastructure using encrypted HTTP traffic.

### Key Findings
- The adversary exploited a chain of three zero-day vulnerabilities: two in Google Chrome and one local privilege escalation flaw in Microsoft Windows, delivered through phishing emails targeting Asian government entities.
- UTA0565 utilized typosquatting techniques by registering spoofed domains such as 'americanprgoress[.]top' and 'theconversation[.]com' to impersonate the Center for American Progress and The Conversation, respectively.
- The delivered malware, tracked as CLEANGULP, was heavily obfuscated using control flow flattening and installed itself as a scheduled task named 'MicrosoftIME' within %LOCALAPPDATA%\Microsoft\IME\MicrosoftIME.exe.
- CLEANGULP supports advanced backdoor capabilities including command execution, file upload/download, process listing, and beacon object file (BOF) execution, communicating via AES-256-GCM encrypted HTTP requests using a custom Base64 alphabet.
- The widespread adoption of this specific exploit kit by multiple disparate threat actors suggests coordinated sharing within the Chinese cyber espionage community during the vulnerability window.

## 5. Research Synthesis

### Executive Summary
UTA0565 leverages a chained Chrome and Windows zero-day exploit chain to deploy the CLEANGULP backdoor via typosquatting domains impersonating legitimate media organizations. The malware evades standard detection by stripping Mark of the Web attributes, executing payloads via COM objects, and encrypting C2 traffic with AES-256-GCM using a custom Base64 alphabet. This activity indicates a coordinated sharing of exploit kits within the Chinese cyber espionage community, requiring focused hunting on specific file system anomalies and encrypted HTTP patterns.

### Recommended Hypothesis
> Adversaries use chained Chrome/Windows zero-day exploits delivered via typosquatting phishing domains to deploy the CLEANGULP backdoor with COM-based execution and encrypted C2 channels

### Gaps Identified
- Current telemetry lacks visibility into the stripping of 'Mark of the Web' attributes on downloaded files and the specific COM object invocation patterns used to launch chrome_cleanup.exe, allowing direct process creation without standard shell logging.
- Network detection is blinded by AES-256-GCM encryption and custom Base64 encoding on HTTP traffic to typosquatting domains (e.g., thecovnresation[.]com), preventing inspection of the beacon registration UUIDs and command payloads.

### Key Findings
- Hypothesis: Adversaries use chained Chrome/Windows zero-day exploits delivered via typosquatting phishing domains to deploy the CLEANGULP backdoor with COM-based execution and encrypted C2 channels
- Gap: Current telemetry lacks visibility into the stripping of 'Mark of the Web' attributes on downloaded files and the specific COM object invocation patterns used to launch chrome_cleanup.exe, allowing direct process creation without standard shell logging.
- Gap: Network detection is blinded by AES-256-GCM encryption and custom Base64 encoding on HTTP traffic to typosquatting domains (e.g., thecovnresation[.]com), preventing inspection of the beacon registration UUIDs and command payloads.
- Focus: Hunt for file system artifacts in %LOCALAPPDATA%\Microsoft\IME\MicrosoftIME.exe and scheduled tasks named 'MicrosoftIME' that indicate persistence mechanisms for undocumented malware families.
