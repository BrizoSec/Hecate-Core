## 1. System Research: How It Works

### Summary
LabubaRAT is a Rust-based remote access trojan that masquerades as legitimate NVIDIA software by using the executable name 'nvidia-sysruntime.exe' and fake metadata to blend in with system processes. It establishes persistence via Windows Registry Run keys, profiles the infected host for security tools and browsers, and provides full remote access capabilities including command execution, file operations, and SOCKS5 proxying through a C2 infrastructure managed by 'LabubaPanel'.

### Key Findings
- The malware utilizes the executable name 'nvidia-sysruntime.exe' and includes fake version information referencing NVIDIA Corporation to masquerade as legitimate NVIDIA Container Runtime Monitor software.
- It employs specific evasion and persistence mechanisms, including a mutex named 'Local\NVIDIAContainerMonitor\_SingleInstance' to prevent multiple instances and persistence via the current user's Registry Run keys.
- The malware profiles infected systems to identify installed security tools and browsers before awaiting operator commands, supporting its role as a multi-tenant framework consistent with malware-as-a-service (MaaS).
- LabubaRAT manages command and control through an associated backend infrastructure called 'LabubaPanel', which features Labubu-themed visual elements, and has been observed communicating via domains such as pipicka.xyz.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse PowerShell (T1059.001) as part of the LabubaRAT execution tactic to perform command execution and other operational tasks on compromised Windows systems. This technique is employed alongside legitimate utilities like MSBuild and JavaScript interpreters to facilitate the deployment and activity of a Rust-based remote access trojan masquerading as NVIDIA software.

### Key Findings
- LabubaRAT utilizes PowerShell (T1059.001) for execution, often in conjunction with other command-line interpreters such as Windows Command Shell (T1059.003) and JavaScript (T1059.007).
- The malware masquerades as legitimate NVIDIA components, using the filename 'nvidia-sysruntime.exe' and PDB path 'nvidia_container.pdb' to evade detection.
- Adversaries abuse trusted developer utilities for proxy execution, specifically renaming Microsoft's MSBuild utility to 'BuildCoordinator.exe' to load DotNetZip.dll.
- Indicators of Compromise include specific file hashes (e.g., SHA256: b7443b0ab48d2f5786d1b6f3a580f02621e9ae5a3877ee3a44e01df13d984328) and C2 infrastructure domains like pipicka.xyz.
- The RAT employs a multi-tenant framework with configurable enrollment fields (org, group, server) and an internal ZM_ configuration namespace, suggesting a Malware-as-a-Service model managed via LabubaPanel.

## 5. Research Synthesis

### Executive Summary
LabubaRAT operators abuse PowerShell (T1059.001) and MSBuild proxy execution to deploy a Rust-based implant masquerading as NVIDIA software, utilizing configurable enrollment fields to facilitate malware-as-a-service operations. Detection requires correlating anomalous parent-child process chains involving trusted build utilities with PowerShell invocations and monitoring for specific mutex artifacts that indicate the presence of this multi-tenant RAT framework.

### Recommended Hypothesis
> Adversaries use PowerShell execution triggered by renamed MSBuild (BuildCoordinator.exe) to deploy a Rust-based implant masquerading as nvidia-sysruntime.exe on Windows endpoints.

### Gaps Identified
- Lack of telemetry capturing the full command-line arguments passed to PowerShell when invoked by non-standard parents (e.g., msbuild.exe or BuildCoordinator.exe) may blind detection to initial execution logic.
- Standard EDR rules often fail to detect legitimate MSBuild invocations that load specific malicious DLLs like DotNetZip.dll, requiring custom signatures for this proxy-execution pattern.

### Key Findings
- Hypothesis: Adversaries use PowerShell execution triggered by renamed MSBuild (BuildCoordinator.exe) to deploy a Rust-based implant masquerading as nvidia-sysruntime.exe on Windows endpoints.
- Gap: Lack of telemetry capturing the full command-line arguments passed to PowerShell when invoked by non-standard parents (e.g., msbuild.exe or BuildCoordinator.exe) may blind detection to initial execution logic.
- Gap: Standard EDR rules often fail to detect legitimate MSBuild invocations that load specific malicious DLLs like DotNetZip.dll, requiring custom signatures for this proxy-execution pattern.
- Focus: Hunt for process creation events where 'powershell.exe' or 'pwsh.exe' is spawned by 'msbuild.exe', 'BuildCoordinator.exe', or other build utilities, specifically analyzing command lines for encoded payloads or module loading.
