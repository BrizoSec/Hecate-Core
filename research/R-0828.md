## 1. System Research: How It Works

### Summary
Legitimate Firefox browser extensions operate by injecting content scripts and background processes into web pages to interact with DOM elements, manage local storage, and make authenticated API calls to their respective service providers for data synchronization. Network telemetry from these extensions typically involves HTTPS requests to known developer domains for updates, metrics, or wallet interactions, while file artifacts include signed XPI packages containing JavaScript manifests and resource files.

### Key Findings
- Normal browser extension behavior involves legitimate API calls to verified service endpoints (e.g., api.rabby.io, static.debank.com) rather than exfiltration to obscure Cloudflare Workers domains like icy-star-f45c.workers.dev.
- Legitimate extensions do not intercept or transmit sensitive user credentials, such as 12- or 24-word mnemonic phrases or private keys, via URL parameters in HTTP requests to third-party infrastructure.
- Valid Firefox extensions are digitally signed by Mozilla and distributed through the official Add-ons marketplace, avoiding suspicious file hashes (e.g., 7d9d7e80ed52350616be0215a7ded10aaeb9aaa64e34ff8af7f9177c8c855799) associated with trojan.genericfca/amtb.
- Standard extension telemetry uses established analytics platforms (e.g., matomo.debank.com) for usage statistics, distinct from the malicious credential-handling logic that routes data to attacker-controlled C2 endpoints.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries deployed a coordinated campaign of 16 malicious Firefox extensions masquerading as legitimate cryptocurrency wallet tools (specifically Rabby and OKX Wallets) to steal user credentials. These extensions intercept sensitive recovery phrases and private keys during the wallet import process and exfiltrate the data to attacker-controlled Cloudflare Workers infrastructure.

### Key Findings
- The campaign consists of 16 malicious Firefox extensions: four large variants impersonating Rabby Wallet (misspelled as 'Raabby WaIIet') and twelve smaller variants impersonating OKX Wallet, all designed to intercept recovery phrases and private keys during import flows.
- Stolen credentials are exfiltrated to attacker-controlled Cloudflare Workers endpoints, specifically the active C2 domains icy-star-f45c.workers.dev and fondationanimalaidrelief.workers.dev, using a specific request format containing raw secrets and session tokens.
- The malware utilizes legitimate-looking third-party domains such as rabby.io, debit.com, tabtools.co, and fasttools.co to maintain cover; however, these are identified as historical or non-campaign IOCs that should not be blocked solely based on their presence in the malicious packages.
- Analysis of file hashes reveals that while some artifacts show malicious detections on VirusTotal (e.g., trojan.genericfca/amtb for hash 7d9d7e80...), many other hashes from the campaign were not found in ThreatFox or internal MISP instances, indicating limited global visibility at the time of analysis.
- The campaign reuses code markers, network infrastructure, and credential-handling logic linked to previous crypto-theft operations identified in August 2026, suggesting a persistent and evolving threat actor group.

## 5. Research Synthesis

### Executive Summary
A coordinated campaign of 16 malicious Firefox extensions impersonating Rabby and OKX Wallets intercepts 12/24-word mnemonics and private keys during import flows, exfiltrating credentials to attacker-controlled Cloudflare Workers endpoints (icy-star-f45c.workers.dev) via URL parameters. Detection requires correlating browser extension installation artifacts with outbound HTTPS requests containing raw cryptographic secrets to specific C2 infrastructure, rather than relying solely on static file hashes.

### Recommended Hypothesis
> Adversaries use malicious Firefox extensions masquerading as legitimate wallet utilities to intercept and exfiltrate cryptocurrency private keys via Cloudflare Workers endpoints during the wallet import flow.

### Gaps Identified
- Current telemetry lacks explicit mapping for browser extension installation paths (file_activity.file.path) and outbound DNS resolutions to newly registered Cloudflare Workers subdomains, preventing direct correlation of malicious add-on deployment with C2 traffic.
- Network security controls may fail to detect credential theft if the exfiltration payload is embedded in standard HTTPS GET requests to legitimate-appearing domains (workers.dev), requiring deep packet inspection or behavioral analysis of URL parameters rather than simple domain blocking.

### Key Findings
- Hypothesis: Adversaries use malicious Firefox extensions masquerading as legitimate wallet utilities to intercept and exfiltrate cryptocurrency private keys via Cloudflare Workers endpoints during the wallet import flow.
- Gap: Current telemetry lacks explicit mapping for browser extension installation paths (file_activity.file.path) and outbound DNS resolutions to newly registered Cloudflare Workers subdomains, preventing direct correlation of malicious add-on deployment with C2 traffic.
- Gap: Network security controls may fail to detect credential theft if the exfiltration payload is embedded in standard HTTPS GET requests to legitimate-appearing domains (workers.dev), requiring deep packet inspection or behavioral analysis of URL parameters rather than simple domain blocking.
- Focus: Monitor Firefox profile directories for the creation of unsigned or anomalous extension XPI files and correlate these with outbound HTTP(S) requests to *.workers.dev domains containing sensitive data patterns (e.g., 12/24-word word lists in query strings).
