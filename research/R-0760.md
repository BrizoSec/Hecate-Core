## 1. System Research: How It Works

### Summary
Trusted AI platforms are being exploited as a distribution channel where attackers leverage legitimate features like public artifacts and shared conversations to host malicious content, which is then delivered via SEO-poisoned search results or paid ads. This approach bypasses traditional security controls by relying on user trust in official domains rather than technical exploits within the platform itself.

### Key Findings
- Attackers utilize legitimate AI platform features such as Claude Artifacts and shared conversations to publish public, indexable pages that mimic official download sites or installation guides without breaching platform security mechanisms.
- Malicious payloads are delivered through search engine optimization poisoning and paid ad placements that point to these trusted domains, exploiting the user habit of executing first-search-result commands without verification.
- Specific malware variants include SectopRAT (Windows), which uses DLL side-loading via signed JetBrains binaries and Docker Desktop for persistence, and MacSync/AMOS (macOS), which steal credentials via terminal commands pasted from shared AI conversations.
- The attack chain relies on the convergence of platform design (one-click public publishing), search engine ranking algorithms, and user trust in brand domains, rendering traditional phishing indicators like URL spoofing or certificate warnings ineffective.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse trusted AI platforms by chaining publicly shareable content (such as Claude Artifacts or shared conversations), open lightweight applications, and paid search engine advertisements to deliver malware without breaching platform security controls. By leveraging user trust in legitimate domains like claude.ai and chatgpt.com, attackers deceive victims into executing malicious commands via SEO poisoning or fraudulent download pages.

### Key Findings
- Attackers exploited Claude Artifacts hosted on the legitimate claude.ai domain to distribute SectopRAT, where a Bing sponsored ad directed users from over 29 organizations to a fraudulent download page disguised as an official client.
- On macOS, adversaries used claude.ai/share links impersonating Apple Support installation guides to trick users into pasting curl commands that deployed the MacSync stealer for credential harvesting.
- Another vector involved SEO-poisoned shared conversations on ChatGPT and Grok ranking highly for troubleshooting keywords, leading victims to execute terminal commands that delivered the AMOS stealer.
- The malware payloads utilized sophisticated persistence techniques, such as registering DockerDesktop.exe as a scheduled task, and exploited DLL side-loading vulnerabilities in signed JetBrains binaries.
- Attribution links were established through WHOIS records connecting download-app[.]us to ten domains dating back to December 2025, one of which was previously seized by Microsoft under Operation Endgame.

## 5. Research Synthesis

### Executive Summary
Adversaries are leveraging legitimate, indexable features of trusted AI platforms (Claude Artifacts, shared conversations) combined with SEO-poisoned search results to bypass traditional phishing detection by exploiting user trust in official domains. This attack vector facilitates the delivery of credential stealers and RATs via social engineering commands executed in terminal environments, effectively neutralizing URL-based security controls.

### Recommended Hypothesis
> Adversaries use SEO-poisoned search results linking to legitimate AI platform features (e.g., claude.ai/share) to deceive users into executing malicious terminal commands for credential theft and persistence on targeted endpoints

### Gaps Identified
- Current telemetry lacks correlation between user-generated public content publishing events on AI platforms and subsequent inbound network connections from newly registered domains associated with those specific content IDs, creating a blind spot in supply-chain abuse detection
- Endpoint detection systems fail to distinguish between legitimate signed binaries used for DLL side-loading (e.g., JetBrains) and tampered dynamic libraries within the same directory, missing the initial execution vector before payload download

### Key Findings
- Hypothesis: Adversaries use SEO-poisoned search results linking to legitimate AI platform features (e.g., claude.ai/share) to deceive users into executing malicious terminal commands for credential theft and persistence on targeted endpoints
- Gap: Current telemetry lacks correlation between user-generated public content publishing events on AI platforms and subsequent inbound network connections from newly registered domains associated with those specific content IDs, creating a blind spot in supply-chain abuse detection
- Gap: Endpoint detection systems fail to distinguish between legitimate signed binaries used for DLL side-loading (e.g., JetBrains) and tampered dynamic libraries within the same directory, missing the initial execution vector before payload download
- Focus: Hunt for anomalous scheduled task creation (specifically involving Docker or JetBrains components) and suspicious outbound DNS queries to newly registered domains shortly after user-initiated curl/terminal executions
