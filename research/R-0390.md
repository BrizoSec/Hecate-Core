## 1. System Research: How It Works

### Summary
Chaos ransomware's msaRAT employs a technique where it hides its command and control (C2) communication within legitimate browser processes, specifically targeting Chrome or Edge browsers to blend in with normal traffic. It uses WebRTC for encrypted communication and is deployed through fake Windows updates.

### Key Findings
- msaRAT hijacks the browser's network interface using WebRTC to establish a covert C2 channel that mimics legitimate web traffic
- The malware primarily targets Chrome or Edge browsers, checking fixed locations on disk based on environment variables and registry entries for these browsers
- Chaos ransomware spreads via disguised Windows updates, allowing the msaRAT to infect systems without raising immediate suspicion

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Chaos ransomware utilizes msaRAT to establish a covert command-and-control (C2) channel by hijacking browsers and leveraging WebRTC for encrypted data exfiltration. This technique allows the malware to remain hidden from traditional network monitoring tools.

### Key Findings
- msaRAT leverages WebRTC DataChannel communication with transport-layer encryption handled by the browser, making C2 traffic difficult to detect.
- The malware uses Chrome DevTools Protocol for controlling and manipulating browser activities covertly.
- Double-layer encryption is employed to hide communications from network-based detection systems.
- Unusual browser activity, such as unexpected WebRTC connections or encrypted data transfers, can serve as indicators of compromise (IoCs).
- Detection mechanisms should monitor browser processes for signs of manipulation or unusual API calls indicative of RAT activity.
- Organizations must enhance their threat intelligence to identify and block msaRAT's evasion tactics.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Chaos ransomware's msaRAT leverages the Windows Registry to establish a covert C2 channel, which can be detected by monitoring registry queries and modifications related to common malware activities. This behavior falls under MITRE ATT&CK technique T1012 (Query Registry).

### Key Fields
- registry_key_query: Tracks queries to specific registry keys that msaRAT might use for establishing its C2 channel (e.g., HKEY_LOCAL_MACHINE\Software\Microsoft\Windows NT\CurrentVersion)
- process_name: Monitors process names associated with the execution of commands or scripts that interact with the Registry, such as reg.exe
- registry_key_modification: Detects modifications to registry keys that are commonly targeted by malware for persistence and configuration storage (e.g., HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run)
- network_connection: Tracks network connections from processes known to interact with the Registry, looking for anomalies or communications patterns indicative of a C2 channel
- event_id: Specific event IDs in Windows Security Event Logs that correlate with registry access (e.g., 4657 and 4660) can be monitored for suspicious activity

## 5. Research Synthesis

### Executive Summary
Chaos ransomware's msaRAT employs WebRTC to establish a covert C2 channel within legitimate browser processes, primarily targeting Chrome and Edge browsers. By leveraging the Windows Registry for persistence and configuration storage, it manipulates normal web traffic patterns to evade detection.

### Recommended Hypothesis
> Adversaries use manipulation of legitimate web browser functionalities to enable encrypted data exfiltration and establish a covert C2 channel on compromised systems

### Gaps Identified
- Current network monitoring tools may not effectively detect WebRTC-based communications due to their encryption and resemblance to normal traffic patterns.
- Lack of visibility into the specific registry keys and process names associated with msaRAT's activities limits detection capabilities.

### Key Findings
- Hypothesis: Adversaries use manipulation of legitimate web browser functionalities to enable encrypted data exfiltration and establish a covert C2 channel on compromised systems
- Gap: Current network monitoring tools may not effectively detect WebRTC-based communications due to their encryption and resemblance to normal traffic patterns.
