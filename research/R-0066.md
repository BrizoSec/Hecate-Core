## 1. System Research: How It Works

### Summary
Native AOT (Ahead-of-Time compilation) in .NET compiles managed code to native binaries, allowing direct P/Invoke calls for improved performance and minimizing disk footprint. This technology is supported in ASP.NET Core Web API templates and UWP applications.

### Key Findings
- Native AOT enhances the performance of .NET applications by compiling them into native executables that can make direct P/Invoke calls to unmanaged code.
- The resulting single executable from Native AOT reduces disk footprint, making it suitable for deployment in resource-constrained environments like UWP apps and ASP.NET Core Web APIs.
- P/Invoke bindings are lazily resolved at runtime by default in AOT-compiled binaries to ensure compatibility.

This technique allows them to intercept and alter data transmissions for malicious purposes such as eavesdropping, injecting malware, or blocking legitimate communications.

### Key Findings
- Adversaries use AiTM attacks to position themselves between two communicating parties to intercept network traffic.
- ARP poisoning is a common method used by CHRYSENE to carry out AiTM attacks in targeted environments.
- Tools like proxies are utilized for real-time modification of network communications, allowing the adversary to monitor and manipulate data flow.
- Indicators of AiTM include unexpected DNS requests or responses, unusual network traffic patterns, and discrepancies between expected communication paths and actual observed traffic.
