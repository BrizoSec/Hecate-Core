## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries increasingly exploit trust in software supply chains by compromising upstream providers and development ecosystems, leveraging AI to evade detection. This tactic allows them to inject malicious code into widely used components, affecting numerous downstream organizations.

### Key Findings
- Supply chain attacks are on the rise with adversaries targeting trusted suppliers and open-source repositories to distribute malware or backdoors.
- AI tools enable attackers to create more sophisticated and evasive threats that can bypass traditional security measures, making detection harder.
- Attackers exploit identity management systems like Microsoft's Active Directory Federation Services (ADFS) within supply chains to gain broader access to enterprise networks.
- Zero-trust security models are becoming essential as they reduce reliance on implicit trust assumptions in the network and applications.
- Continuous monitoring and validation of AI agent identities can help mitigate risks associated with AI toolchain attacks, reinforcing secure development practices.

## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect AI-driven and supply chain attack behaviors, telemetry must capture both endpoint and network activities that indicate unusual access patterns, code execution from unexpected sources, lateral movement, and data exfiltration attempts.

### Key Fields
- event.action (50% populated): Indicates the type of action taken by an entity on a system or network. Actions such as 'process creation', 'file modification', and 'network connection' are critical for identifying malicious activities.
- event.category (90% populated): Categorizes events into types like 'authentication', 'application', 'configuration change', 'connection', etc., which help in filtering relevant logs for hunting.
- event.data (30% populated): Contains specific details of the event such as file paths, command lines, and registry keys that are essential for understanding the context of suspicious activities.
- process.pid (85% populated): Process IDs can be used to trace back malicious processes and understand their lifecycle on a system, helping in identifying persistent threats.
- network.destination_port (70% populated): Helps detect unusual network activity such as communication with known bad IP addresses or ports commonly associated with command-and-control servers.
- process.parent.name (65% populated): Provides insights into the parent process of suspicious activities, which can reveal if a legitimate application is being hijacked for malicious purposes.
