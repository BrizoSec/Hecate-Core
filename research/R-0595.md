## 1. System Research: How It Works

### Summary
Secure Agent Harness Execution is designed to prevent unauthorized access and escape by enforcing a confined working directory, explicit approval checkpoints for shell commands execution, and deny-list policies. It ensures that agents can only perform actions within specified boundaries and require user or system approval before executing potentially dangerous operations.

### Key Findings
- The agent harness operates under strict isolation principles with a confined working directory to prevent unauthorized file access.
- Explicit approval checkpoints are implemented for shell command execution, adding an additional layer of security against unintended operations.
- Deny-list policies enhance the security model by restricting certain actions or commands that could be used to circumvent security measures.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries may abuse Secure Agent Harness Execution by exploiting vulnerabilities in the sandboxing mechanisms, such as Landlock or Seatbelt, to escape the isolated environment and gain unauthorized access to sensitive information.

### Key Findings
- Adversaries exploit zero-day vulnerabilities in kernel-enforced sandboxes like Landlock or Seatbelt to bypass isolation restrictions.
- Attacks may involve injecting malicious code into sandboxed processes through prompt injection techniques that manipulate command-line interfaces.
- Network enforcement mechanisms can be circumvented by exploiting misconfigured network policies or using covert channels established within the sandbox.
- Credential isolation is undermined when adversaries steal credentials from other isolated agents or leverage credential stuffing attacks against less secure systems.
