## 1. System Research: How It Works

### Summary
LSASS (Local Security Authority Subsystem Service) is a critical Windows service responsible for managing security-related operations, including handling logon sessions and storing sensitive information such as credentials. The memory dump of LSASS can provide valuable insights into the current state of user authentication and security settings within the system.

### Key Findings
- LSASS memory dumps often contain plaintext or encrypted credentials, making them a prime target for attackers seeking to harvest login information.
- The process of dumping LSASS memory involves accessing volatile data structures that can change rapidly, requiring precise timing and techniques to capture an accurate snapshot.
- LSASS handles various types of security-related processes, including Kerberos tickets, NTLM hashes, and session tokens, which are critical for both legitimate forensic analysis and malicious activities.
- The security mechanisms in place to protect LSASS from unauthorized access include kernel-level protections and encryption of sensitive data. However, these can be circumvented with sophisticated techniques.
- Analyzing LSASS memory dumps requires specialized tools and expertise due to the complexity of the system internals and the potential legal and ethical implications.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit LSASS (Local Security Authority Subsystem Service) memory dumping to exfiltrate sensitive information such as passwords and hashes, which are stored in the LSASS process's memory. This technique allows attackers to capture credentials that users enter or systems generate, providing a valuable resource for lateral movement and privilege escalation within the network.

### Key Findings
- Adversaries often use tools like Mimikatz to access and dump LSASS memory, which can reveal plaintext passwords, hashes, and Kerberos tickets.
- The technique is widely used due to its effectiveness in harvesting credentials that can be reused for further attacks.
- Indicator of compromise (IoC) includes unusual network traffic patterns or attempts to access the LSASS process, often detected through security logs and forensic analysis.
- Defensive measures include implementing strong authentication methods like multi-factor authentication (MFA), regularly updating systems, and employing endpoint detection and response (EDR) tools to monitor for suspicious activities.
- Adversaries may employ persistence mechanisms such as registry keys or scheduled tasks to automate the LSASS memory dumping process, ensuring their access remains undetected over time.
