## 1. System Research: How It Works

### Summary
PolinRider malware spreads through compromised GitHub accounts and repositories, inserting malicious code into development versions of Packagist packages. The attackers have targeted the 'visanduma/nova-two-factor' package with over 700,000 downloads, injecting obfuscated JavaScript to execute during build activities.

### Key Findings
- PolinRider spreads through compromised developer accounts on GitHub and infects Packagist packages.
- The malware targets development branches of the 'visanduma/nova-two-factor' package with over 700,000 downloads.
- Malicious code is injected into configuration files and directly into PHP scripts to execute during build processes.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are exploiting compromised GitHub accounts to insert malicious code into popular open-source packages, specifically targeting the Packagist package `visanduma/nova-two-factor`. The PolinRider malware is spread through developer collaboration channels in Git-based services, compromising source repositories and infecting contributors.

### Key Findings
- PolinRider malware, attributed to North Korea (DPRK), was detected in compromised GitHub pull requests.
- The campaign primarily spreads through developer collaboration in Git-based services by inserting malicious code into development versions of packages.
- Compromised source repositories contain obfuscated JavaScript loaders connecting to blockchain and public RPC infrastructure for payload delivery.
- 162 malicious release artifacts were identified across 108 unique packages and extensions, including npm, Packagist, Go modules, and a Chrome extension.

## 5. Research Synthesis

### Executive Summary
PolinRider malware, attributed to North Korea (DPRK), spreads through compromised GitHub accounts and Packagist repositories by inserting malicious code into popular open-source packages, primarily targeting development branches of the 'visanduma/nova-two-factor' package with over 700,000 downloads. The attackers exploit developer collaboration channels in Git-based services to infect contributors and deliver payloads via obfuscated JavaScript loaders.

### Recommended Hypothesis
> Adversaries use compromised GitHub accounts and Packagist repositories to spread PolinRider malware by inserting malicious code into development branches of popular packages, targeting developers and contributing to lateral movement within networks.

### Gaps Identified
- Current coverage lacks telemetry for monitoring changes in source control systems (like Git) that could indicate suspicious activity such as unauthorized pushes or pull requests from compromised accounts.
- There is limited knowledge on the long-term persistence mechanisms employed by PolinRider after initial infection through package installations, particularly regarding registry keys and scheduled tasks.

### Key Findings
- Hypothesis: Adversaries use compromised GitHub accounts and Packagist repositories to spread PolinRider malware by inserting malicious code into development branches of popular packages, targeting developers and contributing to lateral movement within networks.
- Gap: Current coverage lacks telemetry for monitoring changes in source control systems (like Git) that could indicate suspicious activity such as unauthorized pushes or pull requests from compromised accounts.
- Gap: There is limited knowledge on the long-term persistence mechanisms employed by PolinRider after initial infection through package installations, particularly regarding registry keys and scheduled tasks.
- Focus: Enhancing detection capabilities for malicious activities in source control systems (like Git) to identify unauthorized access or code injection attempts.
- Focus: Investigating potential lateral movement strategies used by PolinRider post-infection, focusing on how the malware establishes persistence and communicates with Command and Control infrastructure.
