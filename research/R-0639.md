## 1. System Research: How It Works

### Summary
The BlueMoon exploit kit chains Chromium V8 type-confusion and Windows kernel local privilege escalation vulnerabilities to execute arbitrary code, typically downloading payloads via curl or deploying the GemStone browser extension for persistent credential theft. Normal system behavior is subverted by rewriting Chrome preference files and relaunching the browser with --restore-last-session to maintain user context while establishing C2 communications through legitimate-looking domains.

### Key Findings
- Exploitation results in a curl command downloading an actor-provided executable, followed by extraction of malicious components to C:\Users\Public\stomp_ext
- The GemStone browser extension utilizes background.js with permissions for cookies, storage, tabs, scripting, and downloads to function as a surveillance backdoor
- C2 configuration is stored in Chrome extension storage under registry keys kc_state and portal_sync_config, with public IP identification via api.ipify.org and ipinfo.io
- Malicious artifacts include trojan.shadowpad/demp variants (e.g., msgbox.exe) and domains such as secboxes.com and msbenefit.com used for initial download stages

## 5. Research Synthesis

### Executive Summary
State-aligned actors are rapidly adopting the BlueMoon exploit kit to chain Chromium V8 type-confusion (CVE-2026-85046) and Windows kernel LPE (CVE-2026-85880) for espionage, deploying the GemStone browser extension for persistent credential theft and ShadowPad payloads. Detection requires correlating malicious Chrome extension storage artifacts (kc_state, portal_sync_config) with unusual process launches (curl, --restore-last-session) and connections to specific C2 domains (secboxes.com, msbenefit.com). The threat landscape is characterized by rapid actor proliferation and AI-assisted development patterns, necessitating deep visibility into browser internals and network traffic to legitimate-looking infrastructure.

### Recommended Hypothesis
> Adversaries use chained V8 and kernel zero-days to install the GemStone malicious Chrome extension for credential theft and ShadowPad deployment on Windows endpoints via compromised or spoofed update mechanisms.

### Gaps Identified
- Standard endpoint detection often lacks telemetry on Chrome extension storage keys (kc_state, portal_sync_config) and browser preference file modifications, allowing the GemStone backdoor to operate undetected until outbound C2 activity occurs.

### Key Findings
- Hypothesis: Adversaries use chained V8 and kernel zero-days to install the GemStone malicious Chrome extension for credential theft and ShadowPad deployment on Windows endpoints via compromised or spoofed update mechanisms.
- Gap: Standard endpoint detection often lacks telemetry on Chrome extension storage keys (kc_state, portal_sync_config) and browser preference file modifications, allowing the GemStone backdoor to operate undetected until outbound C2 activity occurs.
- Focus: Monitor for anomalous child processes spawned by Chrome or system binaries (specifically curl executing downloads from secboxes.com/msbenefit.com domains) and detect the presence of malicious background.js files in user extension directories.
