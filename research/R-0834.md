## 1. System Research: How It Works

### Summary
The PoeLLM malware targets exposed AI/LLM services like LiteLLM and Ollama by exploiting vulnerabilities such as CVE-2026-10520 to deploy cryptocurrency miners (XMRig/Iron) and establish a botnet. It utilizes a unique command-and-control mechanism that derives server addresses from keywords in a poem hosted on GitHub, while also leveraging compromised routers as C2 infrastructure.

### Key Findings
- The malware employs a novel C2 communication method where infected systems parse keywords from a poem titled 'On the Nature of Connection' embedded in a CSS file (dash.css) within a forked Node.js repository to dynamically derive IP addresses for command-and-control servers.
- Financial motivation is confirmed by the deployment of XMRig and Iron miners connected to Kryptex mining infrastructure, with victims serving as both computational resources for mining and scanners/exploit servers to expand the botnet.
- The campaign actively exploits multiple known vulnerabilities including CVE-2018-21027, CVE-2018-21028, CVE-2026-42271, and CVE-2026-10520 to compromise hosts running services such as LiteLLM, Ollama, Gotenberg, Gitea, and potentially Ivanti Sentry.

## 5. Research Synthesis

### Executive Summary
The PoeLLM malware campaign exploits CVE-2026-10520 and other vulnerabilities in exposed AI/LLM services (LiteLLM, Ollama) to deploy XMRig/Iron miners via Kryptex infrastructure. The adversary utilizes a novel C2 mechanism that dynamically derives server addresses from keywords within a poem hosted on GitHub, allowing for agile command-and-control rotation.

### Recommended Hypothesis
> Adversaries use dynamic IP derivation from GitHub-hosted poetic keywords to establish resilient command-and-control channels for cryptocurrency mining and botnet expansion on exposed AI infrastructure.

### Gaps Identified
- Standard network monitoring fails to detect the C2 resolution process because the actual IP addresses are computed locally by the malware at runtime from plaintext text, bypassing direct DNS or static IP blocklist detection.
- Endpoint detection is hindered by the use of legitimate library filenames (e.g., 'libgcrypt', 'python3.6') for ELF binaries, making signature-based detection difficult without deep behavioral analysis or file hash verification in non-standard directories.

### Key Findings
- Hypothesis: Adversaries use dynamic IP derivation from GitHub-hosted poetic keywords to establish resilient command-and-control channels for cryptocurrency mining and botnet expansion on exposed AI infrastructure.
- Gap: Standard network monitoring fails to detect the C2 resolution process because the actual IP addresses are computed locally by the malware at runtime from plaintext text, bypassing direct DNS or static IP blocklist detection.
- Gap: Endpoint detection is hindered by the use of legitimate library filenames (e.g., 'libgcrypt', 'python3.6') for ELF binaries, making signature-based detection difficult without deep behavioral analysis or file hash verification in non-standard directories.
- Focus: Implement network telemetry monitoring for outbound connections to known Kryptex mining endpoints (e.g., edge-ru-07.kryptex.network) and IPs like 5.180.174.162 on ports 8029/7029, alongside scanning for unauthorized ELF executions spawned by web service users.
