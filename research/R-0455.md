## 1. System Research: How It Works

### Summary
Blockchain-based C2 operations typically utilize smart contracts to push commands from a threat actor's server to infected devices, leveraging the immutable and transparent nature of blockchain for operational resilience. However, due to high transaction costs, bidirectional communication is rare or inefficient, often supplemented by traditional channels like HTTP for data exfiltration.

### Key Findings
- Blockchain C2 operations are primarily one-way, with commands pushed from threat actors' servers to infected devices via smart contracts.
- Threat actors frequently combine blockchain-based command and control with more cost-effective methods such as HTTP for data exfiltration and status updates.
- The DPRK has adopted a technique called EtherHiding, embedding malware in Ethereum transactions to ensure stealthy and resilient C2 communications.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are leveraging blockchain-based systems like the Polygon network for Command and Control (C2) communications, enabling decentralized infrastructure that is resistant to takedown efforts. They often use multi-hop proxy techniques such as HTran or Tor to obfuscate traffic further.

### Key Findings
- Use of blockchain networks like Polygon for C2 infrastructure provides a resilient and anonymous communication channel.
- Adversaries implement symmetric cryptography methods, such as RC4, to encrypt C2 communications and evade detection.
- Multi-hop proxies are employed with tools like HTran or Tor to mask the true origin of traffic and complicate forensic analysis.
- Criminals obfuscate their command and control traffic using non-standard protocols (e.g., TCP, ICMP) to bypass traditional network monitoring techniques.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Detection of blockchain-based C2 operations would require monitoring for unusual network traffic patterns, especially DNS requests to known blockchain-related domains. Additionally, process creation events and user activity logs that indicate the use or presence of tools commonly associated with blockchain technologies should be captured.

### Key Fields
- network.dns.query (80% populated): Captures domain names queried by endpoints which may include those related to cryptocurrency exchanges or other blockchain services.
- process.name (95% populated): Logs the name of processes executed on endpoints, useful for identifying tools like `geth` and `parity`, commonly used in blockchain operations.
- user.activity (60% populated): Tracks user actions that could indicate suspicious behavior such as large data transfers related to cryptocurrency transactions.
- network.connection.details (75% populated): Provides details about network connections established by processes, critical for identifying outbound communication patterns indicative of C2 activities.

## 5. Research Synthesis

### Executive Summary
Threat actors leverage blockchain-based systems, particularly the Ethereum network and Polygon, for resilient Command and Control (C2) operations. They employ smart contracts to push commands from their servers to infected devices while using traditional channels like HTTP for data exfiltration and symmetric encryption methods such as RC4 to evade detection.

### Recommended Hypothesis
> Adversaries use blockchain-based C2 infrastructure to deploy malware and maintain operational resilience on compromised Windows systems.

### Gaps Identified
- Current monitoring solutions lack coverage for the identification of multi-hop proxy techniques like HTran or Tor, which are used by adversaries to obfuscate their command and control traffic.

### Key Findings
- Hypothesis: Adversaries use blockchain-based C2 infrastructure to deploy malware and maintain operational resilience on compromised Windows systems.
- Gap: Current monitoring solutions lack coverage for the identification of multi-hop proxy techniques like HTran or Tor, which are used by adversaries to obfuscate their command and control traffic.
- Focus: Enhance detection capabilities for atypical network protocols (e.g., TCP, ICMP) being used in conjunction with blockchain-related activities to identify stealthy C2 communications.
