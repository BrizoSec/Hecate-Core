## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse AI systems by deploying adversarial samples that exploit vulnerabilities in machine learning models, potentially leading to misclassification or incorrect predictions. CrowdStrike's involvement with the Open Secure AI Alliance aims to develop defenses against such threats and enhance overall AI safety.

### Key Findings
- Adversaries use sophisticated techniques to inject malicious data into ML systems, causing them to malfunction or leak sensitive information.
- Common tools include generative models like GANs (Generative Adversarial Networks) for crafting adversarial samples that bypass traditional detection mechanisms.
- Indicators of compromise may include unexpected changes in model performance metrics or anomalous behavior detected through network traffic analysis.
- Threat actors leverage social engineering tactics to manipulate data inputs, leading to skewed predictions and decision-making errors in AI-driven systems.

To capture AI-driven attack behaviors in a SIEM environment, relevant telemetry would include network traffic analysis, process monitoring, and file access logs. This will help identify anomalous patterns or activities that could indicate the use of AI for reconnaissance, lateral movement, or data exfiltration.

### Key Fields
- network.http.uri (80% populated): Tracks HTTP requests and responses which can reveal unusual traffic patterns indicative of malicious activity, such as large data transfers or connections to known bad IP addresses.
- endpoint.process.name (75% populated): Provides visibility into process names and their execution times, helping detect anomalies like unexpected binary executions that could be AI-driven malware.
- file.system.opened (60% populated): Monitors file access operations which can indicate attempts by malicious actors to read sensitive files or write configuration changes.
- network.tcp.connection (75% populated): Tracks TCP connections initiated and received, useful for identifying unusual outbound traffic patterns that could be indicative of data exfiltration.
- endpoint.mutex.name (30% populated): Monitors mutex creation which can indicate the presence of malware attempting to ensure only one instance runs at a time.
- network.udp.packet (45% populated): UDP packets can sometimes be used for fast, stealthy communication between compromised hosts or as part of DDoS attacks.
