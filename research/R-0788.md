## 1. System Research: How It Works

### Summary
Oracle PeopleSoft normally routes HTTP requests through its application server (WebLogic) to handle specific servlets, such as the Environment Management Hub (PSEMHUB). During normal operations, legitimate administrative traffic interacts with these endpoints via standard unencoded paths and authenticated sessions for system management tasks.

### Key Findings
- Normal PeopleSoft web traffic uses literal request paths like `/PSEMHUB/`, whereas the malicious activity specifically utilizes URL-encoded variants such as `/%50SEMHUB/` to bypass string-matching WAF rules that do not decode the path before inspection.
- Legitimate PSEMHUB interactions do not involve the creation of arbitrary JSP files (e.g., `x.jsp`, `u.jsp`) or executable binaries (e.g., `Ple64.exe`) within the web application directory, which are indicators of unauthorized web shell deployment and trojanized backdoors.
- Standard PeopleSoft operation does not generate outbound connections to MeshCentral infrastructure or utilize Neo-reGeorg tunneling tools, which are used by the adversary for persistent command-and-control access.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The provided source intelligence primarily details UNC6240's exploitation of CVE-2026-35273 in Oracle PeopleSoft, focusing on WAF bypass techniques and post-exploitation tooling rather than the specific digital certificate reconnaissance associated with MITRE T1596.003. While external mappings link the campaign to T1596.003, the primary evidence describes adversary activities centered on technical exploitation and persistence via web shells, with no detailed textual support for how or why digital certificates were searched in this specific context.

### Key Findings
- UNC6240 (ShinyHunters) exploited CVE-2026-35273 by URL-encoding the 'P' character in the path '/PSEMHUB' to bypass string-based WAF rules that did not normalize input before inspection.
- The threat actor deployed dual JSP web shells: 'x.jsp' for cross-platform command execution using hex-encoded inputs, and 'u.jsp' for chunked file uploads to stage larger binaries.
- A trojanized installer named 'Ple64.exe', masquerading as a Light Alloy media player installer and signed with a valid Extended Validation (EV) certificate, was used to deliver the SIDEEYE backdoor.
- Post-exploitation infrastructure included Neo-reGeorg for tunneling and MeshAgent for persistent access, indicating a pattern of credential theft and potential data extortion.
- The campaign expanded from academic institutions to global sectors including healthcare, government, and agriculture, targeting organizations that relied on WAF rules instead of patching the vulnerability.

## 5. Research Synthesis

### Executive Summary
UNC6240 (ShinyHunters) exploits CVE-2026-35273 in Oracle PeopleSoft by bypassing string-based WAF rules via URL-encoded paths (/%50SEMHUB/) and deploying dual JSP web shells (x.jsp, u.jsp) for command execution and chunked binary uploads. The campaign progresses to persistent access through a trojanized EV-certified installer (Ple64.exe/SIDEEYE), Neo-reGeorg tunneling, and MeshAgent deployment.

### Recommended Hypothesis
> Adversaries use URL-encoded WAF bypass and JSP web shell staging to deploy trojanized backdoors and establish persistent C2 via Neo-reGeorg and MeshAgent on Oracle PeopleSoft servers.

### Gaps Identified
- Current telemetry may miss the initial exploitation phase if WAF logs do not correlate normalized paths with unnormalized request URIs, failing to detect the `/%50SEMHUB/` bypass before payload delivery.
- Detection of the SIDEEYE backdoor is hindered by valid EV certificate signatures on Ple64.exe and its masquerading as a legitimate media player installer, requiring behavioral analysis of memory injection rather than static binary analysis.
