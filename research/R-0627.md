## 1. System Research: How It Works

### Summary
Magento and Adobe Commerce systems normally process web requests through GraphQL endpoints and template engines, rendering transactional emails using cached template data. Under normal operation, PHP files in the product cache are generated dynamically during image processing, and background processes like chronyd manage system time synchronization. Network traffic includes periodic DNS queries and HTTP/HTTPS requests for external services, typically for legitimate purposes such as IP address lookup or time synchronization.

### Key Findings
- The system normally generates PHP files in the product image cache (e.g., pub/media/catalog/product/cache/ss_<10hex>/sync_<10hex>.php) during image processing, which can be abused by attackers to deploy web shells.
- Legitimate background processes such as chronyd are used by the malware to disguise itself, with the implant relaunching as chronyd after initial execution, indicating a technique to evade detection by mimicking system daemons.
- The system makes periodic DNS queries to domains like ntp.timesync.to and ntp.synctime.to every 60 seconds, sending 48-byte UDP packets to port 123 that resemble NTP server replies, which are used for C2 beaconing.
- Normal system behavior includes HTTP requests to public IP detection services (e.g., api4.ipify.org, ipv4.icanhazip.com) for network reconnaissance, which are exploited by the implant to verify environment and trigger beaconing.
- The system may run processes with misleading names such as [kworker/u:8:0] or sshd: apache@notty, which are not typical of genuine system processes and are used by the malware to evade detection by appearing as kernel threads or SSH sessions.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit the StyleSmuggler zero-day vulnerability in Magento and Adobe Commerce by injecting malicious PHP code through the styles property, which is then executed via a failed payment email template, enabling unauthenticated remote code execution. The attack establishes a persistent backdoor using a Rust-based implant that disguises itself as legitimate system processes and communicates with command and control servers using NTP-shaped traffic and WebSocket over TLS.

### Key Findings
- The attack leverages Magento's GraphQL endpoint and template system to inject PHP code into cached product image files, specifically in the path 'pub/media/catalog/product/cache/ss_<10hex>/sync_<10hex>.php', which acts as a web shell.
- The exploit triggers code execution during the rendering of a 'Payment Transaction Failed Reminder' email, allowing unauthenticated remote code execution without requiring user credentials.
- The implant uses multiple disguises—such as 'chronyd', 'fc-cache', 'sshd: apache@notty', and '-bash'—and runs under process names that mimic legitimate system processes, with three instances of the same binary masquerading under different names and reporting PPID 1.
- Command and control (C2) communication occurs via domains like 'ntp.timesysnc.net' (resolving to 185.157.160.251), 'time.microsft.run', and 'windwsecurity.run', with traffic mimicking NTP responses on port 123 and HTTP/HTTPS requests to '/a9f3k2-c2' on port 80, 443, and 8443.
- The implant downloads additional payloads from public IP detection services (e.g., 'api4.ipify.org', 'ipv4.icanhazip.com') and uses a Unix socket '@wraith-8e32b7a8' for inter-process communication, with the dropper confirming execution via a request to a public OAST domain: '457cfa2fb7p5.daf892t5qau4og8pi4cghbc6fhm1dim3u.oast.site'.
- Indicators of compromise include the file hash 'b79dfdc1eed860e0b76c629d6adfce251db379b0b45a6d728d4ef483f7551420' and the IP address '88.216.72.181', though the primary C2 IPs are '99.84.67.186', '185.157.160.251', and '213.111.146.27' [Note: '88.216.72.181' appears in the OTX Pulse but not in the primary source; thus, confidence is lower and may be incorrect].

## 5. Research Synthesis

### Executive Summary
Adversaries exploit a zero-day RCE in Magento and Adobe Commerce via GraphQL-style injection into product cache paths, deploying a web shell at 'pub/media/catalog/product/cache/ss_<10hex>/sync_<10hex>.php' that triggers execution through failed payment email rendering. The implant uses process masquerading (e.g., chronyd, fc-cache, sshd: apache@notty) and C2 over NTP-shaped UDP beaconing to port 123 and HTTP(S) requests to '/a9f3k2-c2', leveraging DNS resolution to domains like ntp.timesysnc.net and oast.site for command and control.

### Recommended Hypothesis
> Adversaries use GraphQL-based PHP code injection into product image cache paths and exploit failed email template rendering to achieve unauthenticated remote code execution, then maintain persistence through process masquerading and NTP-shaped C2 traffic.

### Gaps Identified
- The use of NTP-shaped UDP beaconing on port 123 with 48-byte packets mimicking NTP replies is not currently mapped in network telemetry for behavioral detection, creating blind spots in traffic analysis.
- The implant’s use of multiple process disguises (e.g., chronyd, fc-cache, [kworker/u16:2]) with PPID 1 and shared Unix sockets (@wraith-8e32b7a8) is not consistently captured in endpoint process lineage or inter-process communication telemetry.

### Key Findings
- Hypothesis: Adversaries use GraphQL-based PHP code injection into product image cache paths and exploit failed email template rendering to achieve unauthenticated remote code execution, then maintain persistence through process masquerading and NTP-shaped C2 traffic.
- Gap: The use of NTP-shaped UDP beaconing on port 123 with 48-byte packets mimicking NTP replies is not currently mapped in network telemetry for behavioral detection, creating blind spots in traffic analysis.
- Gap: The implant’s use of multiple process disguises (e.g., chronyd, fc-cache, [kworker/u16:2]) with PPID 1 and shared Unix sockets (@wraith-8e32b7a8) is not consistently captured in endpoint process lineage or inter-process communication telemetry.
- Focus: Implement detection of anomalous PHP file creation in 'pub/media/catalog/product/cache/' with randomized hex suffixes and non-image file extensions, especially in paths matching the 'ss_<10hex>/sync_<10hex>.php' pattern.
- Focus: Correlate DNS queries for 'ntp.timesync.to', 'ntp.synctime.to', and 'ntp.timesysnc.net' with UDP traffic on port 123 and 48-byte packet sizes to detect NTP-shaped beaconing behavior.
- Focus: Monitor for process creation of 'chronyd', 'fc-cache', or 'sshd: apache@notty' with PPID 1 and multiple instances sharing the same binary, indicating implant disguise and multi-process persistence.
