## 1. System Research: How It Works

### Summary
The TerminalFix campaign employs a multistage intrusion technique to establish a reverse tunnel, typically using TLS WebSocket tunnels over port 443 and disabling certificate verification for stealth and persistence. This method allows the attackers to communicate with compromised systems while evading network security measures.

### Key Findings
- TerminalFix uses TLS WebSockets on port 443 to establish a covert communication channel, upgrading from plain HTTPS to WebSocket at '/tunnel'.
- Certificate verification is disabled during this process, indicating an attempt to bypass SSL inspection and other monitoring mechanisms that rely on proper certificate validation.
- The multistage nature of the intrusion suggests initial foothold establishment followed by lateral movement and privilege escalation before setting up the reverse tunnel.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse reverse tunnel attacks to bypass network security measures by establishing covert channels through outbound connections, typically using protocols like SSH or HTTP/S. This technique allows them to maintain persistent access and control over compromised systems while evading detection.

### Key Findings
- Reverse tunnels are often used to proxy RDP traffic, enabling lateral movement within a network despite firewall restrictions.
- Adversaries employ reverse tunneling to exfiltrate data undetected by routing it through seemingly benign outbound connections.
- SSH is commonly utilized for establishing reverse tunnels due to its secure nature and ability to bypass typical security controls.
- Indicators of compromise include unusual SSH activity from unexpected IP addresses or the presence of tunneled traffic masquerading as normal HTTP/S traffic.
