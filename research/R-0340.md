## 1. System Research: How It Works

### Summary
CAPTCHAs are designed to verify user identity by challenging them with tasks that are difficult for bots but easy for humans, thus preventing automated attacks. reCAPTCHA, a popular CAPTCHA service owned by Google, enhances this verification process through advanced risk analysis and machine learning techniques.

### Key Findings
- Legitimate CAPTCHAs use complex challenges to distinguish between human users and automated bots.
- Malicious actors mimic legitimate CAPTCHA systems to deceive users into engaging with malware or phishing schemes.
- The success of malicious CAPTCHA scams often relies on exploiting user trust and the perceived legitimacy of web security measures.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse fake CAPTCHA systems to trick users into executing malicious commands, often through social engineering and obfuscation techniques. These attacks are designed to bypass traditional security measures and distribute malware or steal information in a multistage payload chain.

### Key Findings
- Fake CAPTCHA campaigns use sophisticated SEO tactics to appear legitimate and evade detection by security systems.
- Adversaries employ multi-stage obfuscation to deliver infostealers, RATs, and other payloads after users execute harmful commands from fake CAPTCHA pages.
- Malicious copy-and-paste techniques are used to instruct victims to paste harmful commands into terminal or Run Dialog boxes.
- Attackers often mimic legitimate Cloudflare Turnstile verification processes before presenting their own malicious CAPTCHA page.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry for detecting fake CAPTCHA and traffic distribution activities should capture anomalous user interactions with web applications, unusual server-to-server communication patterns, and deviations from baseline behavior of web servers handling such requests. Key indicators include unexpected HTTP request volumes, specific URL or endpoint access patterns indicative of CAPTCHA bypass attempts, and irregularities in session establishment and maintenance.

### Key Fields
- network.http.request.method (100% populated): Tracks the HTTP methods used by clients when accessing web applications; suspicious activity includes high volume POST requests to CAPTCHA endpoints without corresponding GET requests for form submission.

- network.http.response.status_code (100% populated): Monitors HTTP response codes from web servers; unexpected high volumes of 4xx errors can indicate issues with CAPTCHA systems or potential abuse.

## 5. Research Synthesis

### Executive Summary
Adversaries are exploiting the trust users place in legitimate CAPTCHA systems by deploying fake ones to distribute malware and steal information. These attacks often involve sophisticated social engineering and obfuscation techniques to bypass traditional security measures, with key indicators being unusual HTTP request patterns and high volumes of error responses.

### Recommended Hypothesis
> Adversaries use fake CAPTCHA systems to deliver multistage payloads on unsuspecting users who trust web security mechanisms.

### Gaps Identified
- There is a lack of comprehensive detection for malicious copy-and-paste techniques that instruct victims to execute harmful commands outside the scope of web interaction.

### Key Findings
- Hypothesis: Adversaries use fake CAPTCHA systems to deliver multistage payloads on unsuspecting users who trust web security mechanisms.
- Gap: There is a lack of comprehensive detection for malicious copy-and-paste techniques that instruct victims to execute harmful commands outside the scope of web interaction.
- Focus: Enhancing anomaly detection around unexpected HTTP request patterns and error response codes from CAPTCHA endpoints, especially those mimicking legitimate services like Cloudflare Turnstile.
