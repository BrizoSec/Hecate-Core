## 1. System Research: How It Works

### Summary
Action1 is a legitimate Remote Monitoring and Management (RMM) tool that installs as the 'A1Agent' Windows service at C:\Windows\Action1\action1_agent.exe, utilizing signed binaries and connecting to its infrastructure via server[.]na-2.action1[.]com. Threat actors are abusing this software by distributing fake MSI installers through phishing emails containing malicious PDFs with URI open actions that redirect to VBS or HTA scripts.

### Key Findings
- The malicious installer (action1.msi) drops four specific files including a1_7z_dll_file, a1_sas_dll_file, action1_remote_exe, and main_service_exe, which are signed with an 'Action1 Corporation' certificate.
- Persistence is established by installing the Action1 Agent service ('A1Agent') and storing configuration details such as CustomerId (49b18106-681d-456a-b098-092e2818c09a), Certificate, PrivateKey, and INSTALLDIR in the registry key HKLM\Software\Action1\Agent.
- The C2 communication is directed towards server[.]na-2.action1[.]com, leveraging the legitimate cloud infrastructure of the RMM provider, likely through a free or test account compromised by the attacker.
- The initial attack vector involves a phishing email with a fake PDF invoice that uses an 'OpenAction' to redirect to a malicious VBS file (e.g., from up-theta-rose.vercel[.]app), which then downloads the MSI payload while displaying a decoy PDF.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are abusing the legitimate Remote Monitoring and Management (RMM) tool Action1 by distributing malicious MSI installers via phishing emails that utilize fake PDF invoices with embedded malicious URLs. The installation establishes persistence through a Windows service ('A1Agent') and connects to the vendor's infrastructure using compromised or free/test accounts.

### Key Findings
- The attack chain begins with a phishing email delivering a fake PDF invoice (e.g., 'Transaction Receipt' or DHL document) that uses an OpenAction/URI to redirect the victim to a malicious VBS file or ZIP archive hosted on Vercel.
- The delivered MSI package contains legitimate Action1 RMM binaries (a1_7z_dll_file, a1_sas_dll_file, action1_remote_exe, main_service_exe) which are largely unsigned or have expired certificates, allowing them to bypass standard detection mechanisms.
- Persistence is achieved by installing the 'A1Agent' service at C:\Windows\Action1\action1_agent.exe and storing configuration details (CustomerId, Certificate, PrivateKey) in HKLM\Software\Action1\Agent.
- The attacker utilizes Customer ID 49b18106-681d-456a-b098-092e2818c09a to connect to the Action1 infrastructure via server.na-2.action1.com, likely leveraging free or test accounts to hide malicious activity within legitimate cloud traffic.
- A decoy PDF is displayed to the user after execution to maintain cover while the background installation proceeds silently.

## 5. Research Synthesis

### Executive Summary
Threat actors are abusing legitimate Action1 RMM infrastructure by distributing malicious MSI installers via phishing emails containing malicious PDFs with URI-based download actions. The payload installs the 'A1Agent' service at C:\Windows\Action1\, utilizing specific signed binaries and a unique Customer ID (49b18106-681d-456a-b098-092e2818c09a) to connect to server.na-2.action1.com for C2 operations. Detection relies on identifying this specific configuration chain rather than just the presence of legitimate RMM tools.

### Recommended Hypothesis
> Adversaries use phishing-delivered MSI installers of Action1 RMM to establish persistent remote access via the A1Agent service and communicate with attacker-controlled Customer IDs on server.na-2.action1.com

### Gaps Identified
- Lack of telemetry correlating 'A1Agent' service creation or HKLM\Software\Action1\Agent registry modifications with outbound connections to non-standard Action1 C2 endpoints (e.g., server.na-2.action1.com) using the specific malicious Customer ID 49b18106-681d-456a-b098-092e2818c09a.
- Inability to detect the initial PDF 'OpenAction' URI redirection to Vercel-hosted VBS/HTA scripts that serve the malicious MSI, as network logs may only show HTTPS traffic to legitimate cloud providers (vercel.app) without inspecting the final payload delivery method.

### Key Findings
- Hypothesis: Adversaries use phishing-delivered MSI installers of Action1 RMM to establish persistent remote access via the A1Agent service and communicate with attacker-controlled Customer IDs on server.na-2.action1.com
- Gap: Lack of telemetry correlating 'A1Agent' service creation or HKLM\Software\Action1\Agent registry modifications with outbound connections to non-standard Action1 C2 endpoints (e.g., server.na-2.action1.com) using the specific malicious Customer ID 49b18106-681d-456a-b098-092e2818c09a.
- Gap: Inability to detect the initial PDF 'OpenAction' URI redirection to Vercel-hosted VBS/HTA scripts that serve the malicious MSI, as network logs may only show HTTPS traffic to legitimate cloud providers (vercel.app) without inspecting the final payload delivery method.
- Focus: Monitor for the creation of the 'A1Agent' Windows service and the existence of files named action1_agent.exe or main_service_exe in C:\Windows\Action1\, specifically verifying the associated CustomerId registry value against known malicious indicators.
