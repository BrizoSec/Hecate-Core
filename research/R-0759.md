## 1. System Research: How It Works

### Summary
Group Policy Objects (GPOs) are normally used to centrally configure and enforce security settings across domain-joined systems by storing configuration data in SYSVOL/NETLOGON shares, which clients periodically refresh every 90 minutes or via gpupdate. From a sensor perspective, this appears as authenticated access to directory services for policy retrieval and subsequent local system-level configuration changes (e.g., registry edits, scheduled task creation) without the presence of malicious binaries.

### Key Findings
- Normal GPO processing involves the replication of policy files to SYSVOL and NETLOGON shares, where domain-joined workstations retrieve these configurations during periodic refresh cycles triggered by Group Policy Client events.
- Legitimate GPO application results in local system telemetry such as registry modifications for wallpaper/logon banner settings and the creation of scheduled tasks or services configured to run under the SYSTEM account.
- Network sensors typically observe SMB traffic between clients and Domain Controllers for policy download, while endpoint sensors see trusted Microsoft processes (e.g., gpupdate.exe) initiating configuration changes without downloading external payloads.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abused Valid Accounts (T1078) by compromising VPN credentials to gain domain admin privileges, then weaponized Active Directory Group Policy Objects (GPOs) to deliver ransomware effects across the entire domain without deploying traditional binaries. This approach allowed for immediate, automated impact on all domain-joined workstations while evading standard endpoint detection systems.

### Key Findings
- Initial access was achieved through compromised VPN credentials, granting the threat actors domain admin-equivalent control over the Active Directory environment.
- The attackers created a malicious GPO named 'PAYLOAD' linked at the domain root to deploy ransom notes, hijack wallpapers/lock screens, enforce logon banners, and disable local administrator accounts across all domain-joined workstations.
- The attack utilized 'encryptionless extortion,' focusing on operational disruption via GPO abuse rather than encrypting files with traditional ransomware binaries on Windows endpoints.
- A one-day delay was implemented between GPO creation and detonation to evade file-based detection, relying on the trusted Active Directory infrastructure for distribution.
- The malicious GPOs were designed to re-apply upon every refresh or reboot, ensuring persistent impact and bypassing endpoint detection and response (EDR) systems that monitor file drops.
- Additional techniques included disabling Windows Firewall across all profiles via GPO modifications and employing advanced anti-forensics such as VSS deletion, backup suppression, and ETW in-memory patching.

## 5. Research Synthesis

### Executive Summary
Adversaries compromised valid domain admin credentials via VPN to inject a malicious Group Policy Object (GPO) into SYSVOL, leveraging trusted Active Directory replication to enforce configuration changes—such as disabling local admins and deploying ransom notes—across the enterprise without executing traditional malware binaries. This technique bypasses standard endpoint detection by utilizing legitimate system processes like gpupdate.exe and registry modifications, effectively achieving domain-wide impact through infrastructure abuse rather than file-based execution.

### Recommended Hypothesis
> Adversaries use compromised domain admin credentials to author and link malicious GPOs at the domain root to enforce operational disruption and disable local security controls across all domain-joined endpoints via trusted replication mechanisms.

### Gaps Identified
- Lack of detection for anomalous SYSVOL write operations or new GPO linkages at the domain root level, as these actions mimic legitimate administrative activity and avoid triggering file-based malware alerts on endpoints.
- Insufficient monitoring of 'encryptionless' lateral movement indicators, specifically the combination of local administrator account disabling via Group Policy and simultaneous VSS deletion/backup suppression, which are often overlooked when no ransomware binary is present.

### Key Findings
- Hypothesis: Adversaries use compromised domain admin credentials to author and link malicious GPOs at the domain root to enforce operational disruption and disable local security controls across all domain-joined endpoints via trusted replication mechanisms.
- Gap: Lack of detection for anomalous SYSVOL write operations or new GPO linkages at the domain root level, as these actions mimic legitimate administrative activity and avoid triggering file-based malware alerts on endpoints.
- Gap: Insufficient monitoring of 'encryptionless' lateral movement indicators, specifically the combination of local administrator account disabling via Group Policy and simultaneous VSS deletion/backup suppression, which are often overlooked when no ransomware binary is present.
- Focus: Monitor Active Directory for the creation or modification of GPOs linked at the domain root, specifically tracking writes to SYSVOL/NETLOGON shares for unusual file types (e.g., .txt, .html, .jpg) that indicate ransom notes or custom assets.
