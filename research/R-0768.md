## 1. System Research: How It Works

### Summary
WordPress is a content management system that typically relies on SQL databases for storing user credentials and site data, utilizing standard web protocols for administrative access. In this specific intrusion, the attacker exploited vulnerabilities (CVE-2026-63030 and CVE-2026-60137) to bypass normal authentication, create unauthorized administrator accounts, and extract sensitive database records.

### Key Findings
- The attacker leveraged a chain of WordPress vulnerabilities (CVE-2026-63030 and SQL injection CVE-2026-60137) to compromise at least 49 organizations across 29 countries, deploying custom webshells and hidden administrator accounts.
- Exfiltrated data from a western government organization included over 18,566 records containing account data, plaintext passwords, and personally identifiable information associated with law-enforcement entities.
- Post-compromise activities involved stealing database configuration files and using password spraying techniques to access internal SQL services from the compromised WordPress instances.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
A suspected Chinese-speaking threat actor, attributed to Red Heron, exploited a WordPress vulnerability chain (CVE-2026-63030 and CVE-2026-60137) to compromise multiple government organizations. The attacker deployed a custom collector script to exfiltrate sensitive data, including over 18,000 records containing plaintext passwords and personally identifiable information.

### Key Findings
- The adversary utilized the wp2shell exploit chain involving CVE-2026-63030 and CVE-2026-60137 to target WordPress installations starting around July 20, 2026.
- A western governmental organization was breached, resulting in the theft of over 18,000 sensitive records containing accounts, plaintext passwords, and PII associated with law enforcement.
- The attacker compromised at least 49 organizations across 29 countries using this specific WordPress exploitation technique.
- Post-exploitation activities included executing a custom collector script to retrieve and stage stolen data for exfiltration.
- GreyNoise attributes the activity to a suspected Chinese-speaking actor operating in UTC+8, potentially leveraging LLMs to generate custom tools with superficial code variations.

## 5. Research Synthesis

### Executive Summary
A suspected Chinese-speaking threat actor (Red Heron) exploited a WordPress vulnerability chain (CVE-2026-63030 and CVE-2026-60137) to bypass authentication, deploy custom webshells, and exfiltrate over 18,000 sensitive records from government entities. The adversary demonstrated sophisticated tradecraft by utilizing LLM-generated code for rapid tool iteration, privilege escalation via setuid binaries, and PowerShell-based data staging before exfiltration to external C2 infrastructure.

### Recommended Hypothesis
> Adversaries use WordPress vulnerability chains (CVE-2026-63030/CVE-2026-60137) combined with LLM-generated custom collectors to bypass authentication and exfiltrate database records from government infrastructure.

### Gaps Identified
- Lack of visibility into PowerShell-based data staging and collection scripts on compromised web servers, allowing the adversary to stage sensitive credentials before exfiltration.
- Inability to detect subtle code variations indicative of LLM generation in custom exploits, as traditional signature-based detection may miss superficially modified but functionally identical malicious payloads.

### Key Findings
- Hypothesis: Adversaries use WordPress vulnerability chains (CVE-2026-63030/CVE-2026-60137) combined with LLM-generated custom collectors to bypass authentication and exfiltrate database records from government infrastructure.
- Gap: Lack of visibility into PowerShell-based data staging and collection scripts on compromised web servers, allowing the adversary to stage sensitive credentials before exfiltration.
- Gap: Inability to detect subtle code variations indicative of LLM generation in custom exploits, as traditional signature-based detection may miss superficially modified but functionally identical malicious payloads.
- Focus: Monitor for anomalous HTTP requests targeting WordPress admin endpoints or plugin paths associated with the specific CVE chain, followed by immediate process creation events involving PowerShell or wget/curl downloading from external IPs.
