## 1. System Research: How It Works

### Summary
The WeaselBiscuit infostealer operates by masquerading as legitimate npm packages, utilizing an initial JavaScript import to spawn a detached Node.js process that fetches its payload from Npoint dead-drop URLs. It profiles the host system and exfiltrates sensitive data, specifically Chrome extension storage for cryptocurrency wallet signing states, clipboard contents, and Windows keystrokes, via plain HTTP polling to a C2 server.

### Key Findings
- The malware is distributed through 11 distinct npm packages (e.g., @biz44/id10-client, process-tailwind) that automatically execute a detached Node loader upon import, storing the process ID in a .pid file for persistence tracking.
- Payload and C2 configuration are dynamically resolved via Npoint APIs; specifically, the second-stage artifact is Base64-encoded within JSON retrieved from api.npoint.io URLs before execution via new Function().
- The malware communicates with a single C2 server at 103.170.217.184:8787 using plain HTTP polling, avoiding complex protocols like Socket.IO or WebSocket.
- Data exfiltration focuses on Chrome extension storage under 'Local Extension Settings' directories to capture wallet signing states, rather than draining wallets directly or decrypting browser passwords.
- Campaign tracking is implemented through numeric identifiers (10, 12, 44, 79, 95, 99) embedded in package names and transmitted with system profiling data, suggesting a segmented operational structure.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries attributed to DPRK are abusing the npm supply chain by publishing malicious JavaScript packages that deploy a lean infostealer named WeaselBiscuit. The malware executes in memory via a detached Node process, retrieves its payload and C2 configuration from Npoint dead-drop URLs, and exfiltrates sensitive data such as Chrome extension storage (containing wallet signing states), clipboard contents, and Windows keystrokes.

### Key Findings
- WeaselBiscuit is distributed through 11+ malicious npm packages (e.g., @biz44/id10-client, process-tailwind) that auto-execute a detached Node loader upon import.
- The malware uses Npoint.io URLs as dead drops for both the second-stage payload and C2 configuration, resolving to HTTP C2 at 103.170.217.184:8787.
- Unlike its predecessors BeaverTail and OtterCookie, WeaselBiscuit lacks wallet-draining code, password decryption, screenshot capabilities, and remote shell features, focusing instead on data theft.
- The infostealer harvests Chrome extension storage files across Windows, macOS, and Linux, which contains critical signing states for cryptocurrency wallets.
- Campaign tracking is implemented via numeric identifiers (10, 12, 44, 79, 95, 99) embedded in package names and uploaded with system profiling data to the C2 server.

The detection engineering focus should be on the initial execution chain (npm import triggering detached Node processes), the use of Npoint services for dynamic payload retrieval and C2 configuration (dead-drop behavior), and subsequent exfiltration of Chrome extension storage data, clipboard contents, and keystrokes to a specific HTTP C2 server.

### Key Fields

## 5. Research Synthesis

### Executive Summary
WeaselBiscuit is a lean, DPRK-attributed JavaScript infostealer distributed via malicious npm packages that execute a detached Node process to dynamically fetch payloads from Npoint dead drops. The malware profiles hosts and exfiltrates Chrome extension storage (containing crypto wallet signing states), clipboard data, and keystrokes via plain HTTP polling to C2 103.170.217.184:8787.

### Recommended Hypothesis
> Adversaries use npm supply chain impersonation and Npoint dead drops to deploy a detached Node loader that exfiltrates Chrome extension storage and system telemetry via plain HTTP polling

### Gaps Identified
- Standard endpoint detection may miss the 'new Function' dynamic execution in memory or the specific .pid file persistence mechanism if only process trees are monitored without file system correlation
- Network monitoring often fails to flag Npoint.io as malicious due to its legitimate SaaS reputation, allowing the initial payload fetch and C2 configuration resolution to bypass domain-based blocklists

### Key Findings
- Hypothesis: Adversaries use npm supply chain impersonation and Npoint dead drops to deploy a detached Node loader that exfiltrates Chrome extension storage and system telemetry via plain HTTP polling
