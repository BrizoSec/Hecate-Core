## 2. Adversary Tradecraft: Attack Techniques

### Summary
The China-nexus UAT-11587 group targets government and policy organizations across Asia using spear-phishing emails with decoy documents to initiate a multi-stage infection chain. This campaign delivers 'Antino,' a custom Rust-compiled Windows backdoor that leverages legitimate Microsoft 365 services (Outlook and OneDrive via Microsoft Graph) for command-and-control communications, thereby evading traditional detection mechanisms.

### Key Findings
- The primary delivery mechanism involves spear-phishing emails containing decoy documents with Simplified Chinese metadata (zh-CN tag) and UTC+8 timestamps, indicating a mainland Chinese preparation environment.
- Antino is a custom backdoor written in Rust that supports host reconnaissance, shell/PowerShell execution, file transfer, and in-memory shellcode loading for persistence.
- The malware's command-and-control channel operates exclusively through Microsoft 365 infrastructure, using Outlook and OneDrive objects as dead drops instead of dedicated external servers.
- Development artifacts reveal the use of rsproxy.cn, a Rust package mirror common in mainland China, along with shared CloudFront infrastructure previously associated with UNC6384.
- The campaign targeted at least 16 institutional environments across eight Asian countries (including Taiwan, India, Philippines, and Cambodia) by July 2026, focusing on defense, diplomatic, and legislative sectors.

## 5. Research Synthesis

### Executive Summary
UAT-11587 deploys a Rust-compiled Windows backdoor, 'Antino,' via spear-phishing to establish persistence in Asian government sectors, utilizing legitimate Microsoft Graph APIs to route command-and-control traffic through Outlook and OneDrive 'dead drops' rather than dedicated C2 servers. This technique leverages Cloudflare infrastructure for payload staging and exploits the high trust of Microsoft 365 services to evade traditional network-based threat detection.

### Recommended Hypothesis
> Adversaries use legitimate Microsoft Graph API interactions with Outlook and OneDrive as dead drops for C2 communications to maintain persistent access on targeted Windows endpoints within Asian government organizations

### Gaps Identified
- Lack of telemetry distinguishing legitimate Microsoft Graph API calls from malicious ones, as the C2 traffic mimics standard synchronization patterns and is encrypted via HTTPS, blinding network-level inspection tools
- Insufficient endpoint detection for Rust-compiled executables (Antino) due to the lack of known IOCs in existing signatures and the use of custom loaders that may bypass heuristic analysis of uncommon languages like Rust

### Key Findings
- Hypothesis: Adversaries use legitimate Microsoft Graph API interactions with Outlook and OneDrive as dead drops for C2 communications to maintain persistent access on targeted Windows endpoints within Asian government organizations
- Gap: Lack of telemetry distinguishing legitimate Microsoft Graph API calls from malicious ones, as the C2 traffic mimics standard synchronization patterns and is encrypted via HTTPS, blinding network-level inspection tools
- Gap: Insufficient endpoint detection for Rust-compiled executables (Antino) due to the lack of known IOCs in existing signatures and the use of custom loaders that may bypass heuristic analysis of uncommon languages like Rust
- Focus: Monitor Microsoft Graph API logs for anomalous file access patterns in OneDrive and Outlook folders, specifically looking for read/write operations by non-user processes or unusual API endpoints used for command retrieval
- Focus: Implement endpoint detection rules targeting process creation events involving PowerShell spawning from unexpected parent processes or the execution of unsigned Rust binaries (e.g., Antino.exe) with suspicious command-line arguments
