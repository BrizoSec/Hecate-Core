## 1. System Research: How It Works

### Summary
Device code authentication is a method designed for devices with limited interfaces, allowing users to authenticate through a secondary device where they enter a unique code displayed on the initial device. This process bypasses traditional MFA methods and relies on secure web interactions to validate user identity.

### Key Findings
- Device code authentication simplifies login processes for devices lacking full keyboard or browser support.
- It leverages OAuth flows, enabling secure logins via a secondary device's web interface.
- This method bypasses traditional MFA mechanisms, including phishing-resistant methods like passkeys.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit OAuth device code phishing to bypass Multi-Factor Authentication (MFA) by tricking victims into registering a malicious device that captures their active session credentials, thus granting unauthorized access without needing further MFA validation.

### Key Findings
- OAuth flows are leveraged in device code phishing attacks to register devices and bypass MFA requirements.
- Adversaries compromise accounts and enroll new devices within MFA systems like Duo or Okta to maintain persistent access.
- Suspicious patterns of device registration can indicate potential account manipulation through OAuth-based phishing tactics.
- Phishing emails redirect victims to malicious sites that prompt them to enter device codes, stealing authentication tokens.
- Enterprise ATT&CK framework identifies T1098.005 'Device Registration' as a sub-technique under Account Manipulation for tracking such incidents.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry capturing account manipulation activities such as unauthorized changes to user accounts, group memberships, or credential modifications can help detect T1098. This includes monitoring of Windows Security Event Logs for event IDs related to account management actions (e.g., 4720-4735) and other system logs that track administrative activities on endpoints.

### Key Fields
- eventID (60% populated): Tracks specific events such as account creation, modification, or deletion. Event IDs like 4720, 4725, 4726, 4732, and 4738 are indicative of suspicious changes to user accounts.
- userPrincipalName (100% populated): Identifies the account name associated with events that could indicate unauthorized actions on user accounts. This helps trace back to who performed the action.
- objectClass (50% populated): Specifies the type of object being manipulated, such as 'User', 'Group', or 'Computer'. Helps in identifying targeted entities within an attack.
- targetUserName (70% populated): Provides information about the target account that is being modified. This field can be critical for detecting when a compromised admin account attempts to modify other user accounts or groups.
- logonType (35% populated): The type of logon used, which could indicate if an attacker is using methods like Kerberos authentication or local system login to manipulate accounts without multi-factor authentication.

## 5. Research Synthesis

### Executive Summary
Adversaries exploit OAuth device code authentication to bypass Multi-Factor Authentication (MFA) by tricking victims into registering malicious devices, allowing unauthorized access and persistent account manipulation. This threat involves phishing attacks that leverage OAuth flows to register new devices within MFA systems like Duo or Okta.

### Recommended Hypothesis
> Adversaries use device code phishing to bypass Multi-Factor Authentication (MFA) by enrolling malicious devices, allowing unauthorized access and persistent account manipulation on compromised accounts.

### Gaps Identified
- Current detection mechanisms may not fully capture OAuth-based phishing activities that exploit device code authentication flows for MFA circumvention.
- Limited telemetry coverage of user and device registration events in cloud-based MFA systems hinders the ability to detect suspicious patterns indicative of adversary activity.

### Key Findings
- Hypothesis: Adversaries use device code phishing to bypass Multi-Factor Authentication (MFA) by enrolling malicious devices, allowing unauthorized access and persistent account manipulation on compromised accounts.
- Gap: Current detection mechanisms may not fully capture OAuth-based phishing activities that exploit device code authentication flows for MFA circumvention.
- Gap: Limited telemetry coverage of user and device registration events in cloud-based MFA systems hinders the ability to detect suspicious patterns indicative of adversary activity.
- Focus: Enhancing monitoring for event IDs related to account management actions, particularly those involving OAuth flows and device registrations within MFA systems.
- Focus: Investigating and implementing additional detection rules for suspicious OAuth device code authentication requests that originate from external or untrusted sources.
