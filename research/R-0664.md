## 1. System Research: How It Works

### Summary
Djinn Stealer is a cross-platform information stealer delivered as a second-stage payload by the TaskWeaver Node.js loader, typically following the exploitation of SimpleHelp vulnerability CVE-2026-48558 to gain technician session access. It operates within a Node.js runtime to harvest credentials and configuration data from cloud platforms, AI coding assistants, browsers, and infrastructure tooling before encrypting and exfiltrating the data via encrypted channels.

### Key Findings
- The attack chain initiates with the exploitation of CVE-2026-48558 to bypass SimpleHelp OIDC authentication, allowing TaskWeaver (a heavily obfuscated Node.js loader) to deploy Djinn Stealer on the endpoint.
- Djinn Stealer employs a rules-based collection engine that enumerates user home directories across Windows, macOS, and Linux to harvest specific AI coding assistant session data, including files like ~/.claude/mcp.json for Claude, as well as tokens for Gemini, Codex, Cline, OpenCode, and Kilo.
- Stolen infrastructure secrets, such as cloud credentials, SSH keys, API keys, and cryptocurrency wallet data, are archived locally and encrypted using AES-256-GCM, with the encryption key protected by RSA-2048 prior to exfiltration to attacker-controlled infrastructure (e.g., 96.126.130.126).

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit the SimpleHelp authentication bypass vulnerability CVE-2026-48558 to gain administrative access to Remote Monitoring and Management (RMM) servers, which serves as a launchpad for deploying the TaskWeaver Node.js loader. This loader delivers Djinn Stealer, a cross-platform information stealer that systematically harvests credentials from cloud platforms, AI development assistants, source control systems, and cryptocurrency wallets before exfiltrating the encrypted data to attacker-controlled infrastructure.

### Key Findings
- The attack chain initiates with the exploitation of CVE-2026-48558, a critical authentication bypass vulnerability in SimpleHelp's OIDC implementation, allowing trusted administrative access to RMM servers.
- Djinn Stealer is deployed as a second-stage payload via TaskWeaver, an obfuscated JavaScript loader disguised as 'jsquery.js' and executed within a Node.js runtime context.
- The stealer employs a rules-based collection engine to target high-value credentials across cloud platforms, AI development assistants, CI/CD pipelines, SSH, browsers, and cryptocurrency wallets.
- Stolen data is archived and encrypted before being exfiltrated to attacker-controlled infrastructure via encrypted channels connected to C2 servers.
- Primary indicators include the exploitation of SimpleHelp CVE-2026-48558, the file hash f4a72600a3735c2a4d843875ea61bbb6f935a1af51a81f2fbc992ce11ba94afc, and the IP address 96.126.130.126.

## 5. Research Synthesis

### Executive Summary
Djinn Stealer leverages the SimpleHelp CVE-2026-48558 authentication bypass to deploy a Node.js-based payload (TaskWeaver) that systematically harvests high-value credentials from cloud, AI development, and infrastructure environments. The threat is characterized by specific file system enumeration of configuration files (e.g., .claude/mcp.json) and encrypted exfiltration to known C2 infrastructure.

### Recommended Hypothesis
> Adversaries use CVE-2026-48558 exploitation to deploy a Node.js loader that executes rules-based credential harvesting from AI assistants and cloud platforms to exfiltrate sensitive data via encrypted channels.

### Gaps Identified
- Standard file integrity monitoring may miss the rapid read-access patterns of numerous small configuration files across user home directories (Windows/macOS/Linux) unless specific path heuristics for AI tools (e.g., ~/.claude, ~/.gemini) are implemented.
- Network detection is blinded by TLS encryption; without SSL/TLS inspection or correlation with the known C2 IP (96.126.130.126), outbound exfiltration traffic from Node.js processes will appear as benign encrypted web traffic.

### Key Findings
- Hypothesis: Adversaries use CVE-2026-48558 exploitation to deploy a Node.js loader that executes rules-based credential harvesting from AI assistants and cloud platforms to exfiltrate sensitive data via encrypted channels.
- Gap: Standard file integrity monitoring may miss the rapid read-access patterns of numerous small configuration files across user home directories (Windows/macOS/Linux) unless specific path heuristics for AI tools (e.g., ~/.claude, ~/.gemini) are implemented.
- Gap: Network detection is blinded by TLS encryption; without SSL/TLS inspection or correlation with the known C2 IP (96.126.130.126), outbound exfiltration traffic from Node.js processes will appear as benign encrypted web traffic.
- Focus: Monitor for suspicious Node.js process creation patterns and command-line arguments indicative of obfuscated loaders like 'jsquery.js', particularly originating from RMM server sessions.
