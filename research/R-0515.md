# R-0515: Hits Safe Mode: Ransomware Rebooting Around EDR Research

**Topic:** Hits Safe Mode: Ransomware Rebooting Around EDR
**Duration:** 2.9 minutes

---

## 1. System Research: How It Works

### Summary
In normal operation, systems can boot into Safe Mode to resolve issues with drivers or software conflicts. Ransomware may exploit this by forcing the system into Safe Mode where EDR solutions are limited or inactive, allowing it to spread and encrypt files without interference.

### Key Findings
- Safe Mode boots only essential services and drivers, which can disable security measures like EDR that require additional components to run.
- [UNCERTAIN] Ransomware might force a reboot into Safe Mode by manipulating system boot settings or exploiting vulnerabilities in the OS.
- Detection of such behavior requires monitoring for unusual reboots and changes to boot configuration files.


---

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries may abuse the system's reboot behavior in safe mode to execute ransomware and disable or evade Endpoint Detection and Response (EDR) systems. By initiating a reboot into safe mode, attackers can temporarily circumvent EDR monitoring tools that are not operational during such states, allowing them to deploy ransomware undetected.

### Key Findings
- Adversaries initiate system reboots to enter Safe Mode where certain security solutions may be disabled or run in reduced functionality.
- [UNCERTAIN] Some ransomware variants employ reboot tactics specifically timed around EDR detection windows to maximize their operational time without interference.
- Attackers leverage the reduced environment of Safe Mode to install malicious payloads that are designed to disable or evade EDR tools upon a subsequent normal boot.
- Detection mechanisms should be in place to identify unusual reboots and activities indicative of ransomware deployment during safe mode sessions.
- Organizations need to ensure their EDR solutions can maintain integrity and functionality across different system states, including Safe Mode, to prevent such abuse.

Telemetry should capture system reboots, changes in boot settings, process executions around known ransomware times, and network communications indicative of command-and-control (C2) activity.

- boot_sequence_changes: Changes in the boot sequence of a system may signal attempts by ransomware to disable security software during startup.
