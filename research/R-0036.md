## 3. Telemetry Mapping: OCSF Fields

### Summary
ACR Stealer is a form of malware that targets financial credentials from infected Windows machines. It uses intrusion chains such as phishing emails or exploit kits to deliver the payload. The telemetry would capture this behavior through system and network logs indicative of unauthorized access, file modifications, and network communications with command-and-control (C2) servers.

### Key Fields
- event.category:network - Events categorized by the SIEM as network-related can help detect C2 communication patterns that are typical for malware like ACR Stealer. These events might include DNS requests to suspicious domains or unusual outbound HTTP/S traffic.
- process.pid - Process IDs associated with malicious binaries or scripts dropped by ACR Stealer would be crucial in identifying and correlating malicious activity within the system's process list.
- event.category:file - File-related activities such as the creation, modification, deletion, or execution of files can indicate the presence of ACR Stealer. Look for suspicious file paths or filenames typically used by this malware to store stolen credentials or communicate with C2 servers.
- user.id (50% populated) - User IDs associated with account logon events (Event ID 4624) and privilege use events (Event ID 4719) can help identify compromised user accounts that the ACR Stealer may leverage to escalate privileges or spread laterally within a network.
- process.name (80% populated) - The process names of executables involved in unauthorized actions, such as dropping malware files or establishing C2 connections, are critical for detection. Common indicators include unfamiliar or obfuscated filenames and paths.
- network.protocol (65% populated) - Protocol details like HTTP, HTTPS, or DNS can help identify the specific methods ACR Stealer uses to communicate with its C2 infrastructure.
