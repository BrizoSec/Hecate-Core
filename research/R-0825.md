## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries deploy sophisticated phishing campaigns disguised as legitimate AI advertising tools (e.g., for ChatGPT, Claude) to target advertising account managers and recruiters. The operation utilizes a Browser-in-the-Browser technique with real-time credential interception via Socket.IO, allowing operators to bypass Multi-Factor Authentication by dynamically adapting to authentication challenges.

### Key Findings
- The campaign employs a 'Browser-in-the-Browser' attack vector where fake authentication windows mimic trusted services like accounts.google.com or Okta, tricking users into entering credentials on phishing domains rather than legitimate sites.
- Infrastructure relies on real-time interception using Socket.IO connections to backend hosts on Railway and Render, enabling a state machine that captures passwords and MFA codes simultaneously while retrying inputs as needed.
- The adversary reuses a single Next.js codebase across multiple impersonated brands (Muse, Gemini, Claude, ChatGPT, Perplexity) and extends the infrastructure to support secondary fraud vectors like refund scams and fake recruitment sites.
- Indicators of Compromise include specific domains such as sync-account.com, verification-security.com, and museads.ai, alongside backend hostnames like backend-production-6d75.up.railway.app and API endpoints api.ipify.org and ipapi.co used for IP geolocation and data exfiltration.

## 5. Research Synthesis

### Executive Summary
The 'Fake AI Ads Campaign' employs a sophisticated Browser-in-the-Browser (BitB) phishing infrastructure disguised as legitimate AI advertising platforms, utilizing real-time credential interception via Socket.IO connections to backend servers hosted on Railway and Render. This operation enables dynamic MFA bypass by reliving authentication challenges to operators who adapt the state machine in real-time, targeting advertising account managers and recruiters with high-fidelity impersonation of services like Claude and ChatGPT.

### Recommended Hypothesis
> Adversaries use Browser-in-the-Browser overlays and Socket.IO-based credential relay infrastructure to bypass Multi-Factor Authentication and harvest credentials from advertising account managers.

### Gaps Identified
- Standard network monitoring often misses encrypted WebSocket (wss://) traffic on port 443, allowing the real-time Socket.IO C2 channel to exfiltrate credentials undetected by traditional HTTP proxy logs.
- Lack of visibility into DNS resolution for newly registered domains mimicking legitimate AI providers (e.g., museads.ai, claude-ads.ai) allows initial access phases to occur before domain reputation services flag them as malicious.

### Key Findings
- Hypothesis: Adversaries use Browser-in-the-Browser overlays and Socket.IO-based credential relay infrastructure to bypass Multi-Factor Authentication and harvest credentials from advertising account managers.
- Gap: Standard network monitoring often misses encrypted WebSocket (wss://) traffic on port 443, allowing the real-time Socket.IO C2 channel to exfiltrate credentials undetected by traditional HTTP proxy logs.
- Gap: Lack of visibility into DNS resolution for newly registered domains mimicking legitimate AI providers (e.g., museads.ai, claude-ads.ai) allows initial access phases to occur before domain reputation services flag them as malicious.
- Focus: Monitor outbound WebSocket connections from web browsers to non-standard backend endpoints hosted on PaaS providers like Railway (up.railway.app) and Render for suspicious Socket.IO handshake patterns.
