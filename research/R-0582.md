## 1. System Research: How It Works

### Summary
The real-time open source software supply chain security system monitors and assesses the integrity, vulnerabilities, and compliance of components used in a software development process. It employs various tools and techniques to track dependencies, detect malicious code, and ensure that all parts of the software adhere to security standards.

### Key Findings
- Continuous monitoring is critical for identifying new vulnerabilities as they emerge.
- [UNCERTAIN] Automated dependency checking can reduce human error in managing package versions.
- Integration with a trusted repository or a curated list enhances the reliability and security of components.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries can exploit the open-source software supply chain by injecting malicious code into popular repositories or tampering with dependencies to compromise a wide range of systems using legitimate-looking updates. This method leverages the trust developers have in well-established libraries and frameworks, enabling widespread propagation of malware or backdoors.

### Key Findings
- Adversaries commonly use social engineering tactics to gain access credentials for trusted repositories or exploit weak permissions settings to inject malicious code.
- Malicious actors often target widely-used dependencies with low security scrutiny, allowing them to distribute compromised software to numerous downstream projects and end-users.
- [UNCERTAIN] Some sophisticated attacks involve the use of supply chain compromise tools that can automate the process of identifying targets and deploying malware.
- Indicators of attack include unusual commit patterns in repositories, such as commits from unfamiliar contributors or updates during periods when the project is known to be inactive.
- Supply chain attacks frequently exploit package managers' reliance on unverified sources for dependencies by injecting malicious packages into public mirrors or registries.
- Compromised open-source projects can serve as a vector for multi-stage attacks, where initial access gained through supply chain compromise leads to further exploitation of network resources.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Real-time telemetry captures unauthorized modifications to critical files related to open source software components, unusual network communications, and deviations from normal build processes.

### Key Fields
- OcsfLog.FileChange (50% populated): Tracks file changes on the system that are relevant for supply chain security, such as updates or deletions of open source packages.
- OcsfLog.NetworkConnection (70% populated): Monitors network connections to detect unusual outbound traffic patterns indicative of data exfiltration or communication with malicious domains/IPs.
- OcsfLog.ProcessExecution (85% populated): Logs process executions that can reveal signs of unauthorized privilege escalation or execution of tools used for tampering with the software supply chain.
- OcsfLog.UserEvent (40% populated): Captures user-related events like authentication attempts and failed login attempts, which are crucial for identifying potential brute force attacks on accounts with access to the build process.
