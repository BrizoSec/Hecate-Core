## 1. System Research: How It Works

### Summary
Normal system operations involve legitimate Identity Provider (IdP) challenges where users authenticate via passkeys or standard credentials to access cloud resources without external interference. This research highlights a deviation where attackers exploit AiTM phishing and device code flows to intercept session tokens, bypassing normal MFA validations by establishing unauthorized persistence methods.

### Key Findings
- Attackers impersonate IT helpdesk staff via phone/SMS to drive victims to passkey-themed phishing sites mimicking Microsoft sign-in pages, leveraging urgency to bypass user skepticism.
- Compromise is achieved through Adversary-in-the-Middle (AiTM) or device code authentication flows, allowing attackers to capture credentials and session tokens without triggering traditional MFA alerts.
- Persistence is established by adding unauthorized Multi-Factor Authentication (MFA) methods to compromised accounts, ensuring continued access even if original credentials are changed.
- Reconnaissance and exfiltration utilize Microsoft Graph API with high-privilege permissions (Mail.Read, Files.Read.All, Directory.Read.All) to map organizational resources before automated mass data collection from SharePoint, OneDrive, and Exchange.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries such as Storm-3121 and Storm-3032 use passkey-themed social engineering via phone or SMS to impersonate IT helpdesk staff, directing victims to phishing sites that mimic Microsoft sign-in pages. By leveraging adversary-in-the-middle or device code authentication flows, attackers capture credentials and session tokens to establish persistence through unauthorized MFA methods.

### Key Findings
- Attackers maintain persistence by adding unauthorized multi-factor authentication (MFA) methods to compromised accounts after initial credential theft.
- Reconnaissance is conducted using Microsoft Graph API to map users, groups, permissions, and resources, specifically targeting high-privilege permissions like Mail.Read, Files.Read.All, and Directory.Read.All.
- Data exfiltration involves automated tools (e.g., python-httpx) collecting high volumes of data from SharePoint, OneDrive, and Exchange at controlled rates to evade detection.
- The campaign utilizes a network of domains related to passkey setup and synchronization (e.g., setupmypasskey.com, keysyncos.com) alongside SSO impersonation domains like integratedsso.com and oktasession.com.
- Hostnames are dynamically generated using victim company names under actor-controlled domains (e.g., company-name.integratedsso.com, contoso.add-passkey.com) to enhance credibility.

## 5. Research Synthesis

### Executive Summary
This hunt targets Storm-3121/Storm-3032 adversaries leveraging passkey-themed AiTM phishing to bypass MFA and establish persistence via unauthorized MFA methods, followed by Microsoft Graph API abuse for cloud reconnaissance. Detection requires correlating anomalous device code flows and SSO domain redirections with high-volume, automated API calls from tools like python-httpx. The attack chain culminates in controlled exfiltration from SharePoint, OneDrive, and Exchange using high-privilege permissions.

### Recommended Hypothesis
> Adversaries use passkey-themed AiTM phishing and unauthorized MFA persistence to access Microsoft Graph API for cloud reconnaissance and automated data exfiltration on compromised identity accounts

### Gaps Identified
- Lack of telemetry mapping for device code authentication flows (OAuth2) which bypasses traditional MFA prompts, and insufficient logging of python-httpx user-agent strings in HTTP request logs for early detection of automated Graph API abuse
- Absence of correlation between initial phishing domain interactions (e.g., setupmypasskey.com) and subsequent creation of new MFA methods or service principals with high-privilege Graph permissions (Mail.Read, Files.Read.All)

### Key Findings
- Hypothesis: Adversaries use passkey-themed AiTM phishing and unauthorized MFA persistence to access Microsoft Graph API for cloud reconnaissance and automated data exfiltration on compromised identity accounts
- Gap: Lack of telemetry mapping for device code authentication flows (OAuth2) which bypasses traditional MFA prompts, and insufficient logging of python-httpx user-agent strings in HTTP request logs for early detection of automated Graph API abuse
- Gap: Absence of correlation between initial phishing domain interactions (e.g., setupmypasskey.com) and subsequent creation of new MFA methods or service principals with high-privilege Graph permissions (Mail.Read, Files.Read.All)
- Focus: Monitor for anomalous HTTP User-Agent strings (specifically python-httpx) accessing Microsoft Graph endpoints at high frequency or controlled rates, indicating automated data collection
- Focus: Audit identity platform logs for the addition of new MFA methods (especially FIDO2/WebAuthn or phishing-resistant methods) immediately following authentication events from suspicious or newly registered domains
