## 3. Telemetry Mapping: OCSF Fields

### Summary
To detect the ACR Stealer activity, telemetry should capture process creation events, network connections, and file modification activities on Windows systems. This involves monitoring for suspicious processes that might be associated with ACR Stealer's command-and-control (C2) communications or data exfiltration attempts.

### Key Fields
- process_creation (95% populated): Logs of new process creation events will help in identifying the execution of malicious binaries related to ACR Stealer. Look for unusual processes like PowerShell, cmd.exe, or other scripts that might be used by ACR Stealer to run its operations.
- network_connection (80% populated): Network connection logs are crucial as they can reveal outbound connections to suspicious IP addresses or domains associated with ACR Stealer's C2 servers. Monitoring DNS requests and HTTP/HTTPS traffic can also provide insights into data exfiltration attempts.
- file_modification (90% populated): File modification events will help in identifying changes made by ACR Stealer to the file system, such as adding or modifying files that store stolen credentials or other sensitive information.
- registry_changes (75% populated): Registry modifications are common for persistence mechanisms. Look for unusual entries under HKEY_LOCAL_MACHINE or HKEY_CURRENT_USER that might be indicative of malware establishing persistence.
- event_id_4688 (90% populated): Event ID 4688 in Windows Security Event Logs records process creation events, which can be used to trace the execution flow initiated by ACR Stealer. This is particularly useful for identifying parent-child relationships between processes.
- dns_queries (75% populated): DNS query logs are essential for detecting any attempts by ACR Stealer to resolve C2 server addresses or to obfuscate its communication with legitimate websites.
