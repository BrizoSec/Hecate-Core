# R-0753: EtherHiding Exposed: Inside a Blockchain-powered Malware Campaign Hiding in Plain Sight Research

## 1. System Research: How It Works

### Summary
The malware operates by first compromising legitimate websites to deliver a 'FakeCaptcha' lure that executes a PowerShell dropper on the victim's machine. This dropper establishes persistence via registry keys and then queries Polygon blockchain smart contracts to dynamically retrieve current command-and-control (C2) addresses, avoiding hard-coded infrastructure.

### Key Findings
- The malware utilizes 'EtherHiding' by querying smart contracts on the Polygon blockchain to resolve C2 domains, updating these addresses for fractions of a cent to bypass traditional domain or IP blocking.
- Infection is initiated through compromised legitimate websites (at least 31 identified) that serve a JavaScript-based 'FakeCaptcha' or 'ClickFix' lure to visitors arriving via Bing or Google search results.
- The initial dropper executes paired PowerShell scripts: one agent handles blockchain C2 queries while the other installs persistence mechanisms via Windows Registry keys to survive reboots.
- The campaign includes gating logic in the malicious JavaScript that uses browser cookies and click-catchers to prevent re-infection of the same browser session, alongside time-boxing or percentage-based filtering for traffic distribution.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse the T1583.001 Domains technique combined with EtherHiding by storing Command and Control (C2) addresses within Polygon blockchain smart contracts, allowing for dynamic infrastructure rotation that bypasses traditional domain blocking. This method enables attackers to maintain persistent access through compromised legitimate websites deploying FakeCaptcha lures, which execute malware that queries the blockchain for current C2 domains.

### Key Findings
- The campaign utilizes the EtherHiding technique by querying smart contracts on the Polygon blockchain to retrieve live C2 addresses, avoiding hardcoded IP/domain strings in the malware payload.
- Initial access is achieved via compromised legitimate websites (at least 31 identified) that serve FakeCaptcha/ClickFix lures to users arriving from Bing or Google search results.
- The attack infrastructure spans six operational waves with 15 smart contracts and two operator wallets, demonstrating a sophisticated approach to maintaining multiple fallback mechanisms.
- Post-infection behaviors include persistence via scheduled tasks and registry keys, followed by the deployment of banking trojans targeting approximately 479 financial and cryptocurrency domains.
- Three C2 domains remain active as of the report's writing: hivinest[.]online, insinght[.]site, and 3262d48df5d75e34[.]shop, while one original domain was taken down by the registrar.

## 5. Research Synthesis

### Executive Summary
The EtherHiding campaign leverages the T1583.001 Domains technique by storing dynamic C2 addresses within Polygon blockchain smart contracts, enabling rapid, low-cost infrastructure rotation that bypasses static domain reputation blocks. Adversaries exploit compromised legitimate websites to deliver a FakeCaptcha/ClickFix PowerShell dropper, which queries these on-chain contracts to resolve active C2 domains for banking trojan deployment.

### Recommended Hypothesis
> Adversaries use Polygon blockchain smart contract queries to dynamically resolve command-and-control domains, avoiding hardcoded infrastructure indicators, via compromised legitimate websites delivering FakeCaptcha lures.

### Gaps Identified
- Standard DNS telemetry often fails to capture the initial C2 resolution because the malware retrieves the domain address from an on-chain smart contract rather than a traditional DNS TXT or A record lookup in the early stages.
- Network security controls lack visibility into 'silent' smart contract reads; without specific application-layer logging for blockchain node interactions, the initial C2 heartbeat appears as benign cryptocurrency wallet activity or standard HTTP/HTTPS traffic to public ledger endpoints.

### Key Findings
- Hypothesis: Adversaries use Polygon blockchain smart contract queries to dynamically resolve command-and-control domains, avoiding hardcoded infrastructure indicators, via compromised legitimate websites delivering FakeCaptcha lures.
- Gap: Standard DNS telemetry often fails to capture the initial C2 resolution because the malware retrieves the domain address from an on-chain smart contract rather than a traditional DNS TXT or A record lookup in the early stages.
- Gap: Network security controls lack visibility into 'silent' smart contract reads; without specific application-layer logging for blockchain node interactions, the initial C2 heartbeat appears as benign cryptocurrency wallet activity or standard HTTP/HTTPS traffic to public ledger endpoints.
- Focus: Deploy endpoint detection rules targeting PowerShell scripts performing HTTP GET requests to known Polygon blockchain explorers (e.g., polygonscan.com) or direct RPC endpoints for contract state reads.
