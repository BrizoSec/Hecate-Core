## 1. System Research: How It Works

### Summary
Jev functions as a 'System One' decision layer that accepts input data and questions to score candidate answers, returning typed decisions (e.g., yes/no, scores) with probability calibration rather than generating textual content. This architecture prioritizes speed and correctness for classification tasks over generative text output.

### Key Findings
- The system operates via a parallel sampler and scoring mechanism where the model evaluates candidate answers to provide probabilities, effectively avoiding hallucinations and type errors inherent in generative models.
- Jev is characterized by high calibration quality, meaning its confidence scores accurately reflect correctness rates (e.g., an 80% confidence claim corresponds to an 80% actual success rate).
- Performance benchmarks indicate efficient processing capabilities, with tests showing the ability to analyze 25,000 movie reviews for 96% accuracy in 22 minutes at a cost of $0.65.
- The official API documentation explicitly defines technical edge cases including literal interpretation, arithmetic precision, date/time comparison, and multi-hop indirection.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse the 'Jev-Clones' technique by registering lookalike domains immediately following the launch of new AI services to impersonate official providers and rank higher in search results. These fraudulent storefronts resell access to legitimate APIs at significantly inflated prices while acting as a man-in-the-middle, routing customer prompts through their own third-party servers before reaching the actual provider.

### Key Findings
- Adversaries use domain squatting and lookalike domains (e.g., jev-ai.pro, jevtypesafeai.com) registered within days of a product launch to capture search engine traffic intended for the official service.
- The attack involves substantial price inflation, with markups ranging from 3x to 11.5 times the official API cost, often using deceptive 'discount' banners and countdown timers to pressure purchases.
- The infrastructure relies on a reusable code template that allows operators to rapidly reskin storefronts for different trending AI models, as evidenced by six identical sites operating under the same logic in an 18-day period.
- Customer data privacy is compromised because all prompts pass through third-party servers (such as those on Railway behind Cloudflare) which may log sensitive information without a Service Level Agreement or clear disclosure.
- Certificate Transparency logs reveal large-scale domain registration activity, with approximately 670 new domains containing specific brand names registered within eight days of a launch event.

## 5. Research Synthesis

### Executive Summary
Adversarial operators exploit the launch velocity of new AI models by registering lookalike domains and deploying reusable, obfuscated storefront code to resell legitimate API access at inflated markups. This activity creates an external threat landscape where customer data is routed through unverified third-party proxies, necessitating detection efforts focused on outbound proxy anomalies and domain registration patterns rather than internal endpoint compromise.

### Recommended Hypothesis
> Adversaries use rapid domain squatting of lookalike URLs and reusable frontend templates to intercept search traffic and resell API access through unauthorized third-party proxies for financial gain.

### Gaps Identified
- Lack of visibility into outbound TLS certificate transparency (CT) logs or DNS registration timestamps prevents early detection of newly registered domains mimicking internal or partner AI services.

### Key Findings
- Hypothesis: Adversaries use rapid domain squatting of lookalike URLs and reusable frontend templates to intercept search traffic and resell API access through unauthorized third-party proxies for financial gain.
- Gap: Lack of visibility into outbound TLS certificate transparency (CT) logs or DNS registration timestamps prevents early detection of newly registered domains mimicking internal or partner AI services.
- Focus: Implement monitoring for outbound network connections to non-whitelisted proxy endpoints (e.g., Railway/Cloudflare infrastructure) handling high-volume API traffic, and establish baselines for domain registration velocity relative to internal product launches.
- Focus: Deploy detection rules identifying HTTP request patterns consistent with the identified reusable storefront code structures, such as specific billing logic parameters or 'site ID' headers found in the malicious JS bundles.
