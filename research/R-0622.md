## 1. System Research: How It Works

### Summary
The ClearFake WebDAV infection chain typically begins with a malicious WebDAV UNC path execution via rundll32.exe, leveraging the WebClient service to load a DLL payload from a randomized subdomain of leaguejazire.com or riyazinikokar.xyz. Once executed, the payload uses memory-based techniques, including a Windows fiber transfer and a signed driver (DCRCVDrv.sys), to maintain persistence and execute further stages, including credential and cryptocurrency stealers and a remote access backdoor.

### Key Findings
- The initial execution occurs through rundll32.exe loading a DLL from a WebDAV path, with the path containing a victim identifier and pointing to a randomized subdomain of leaguejazire.com or riyazinikokar.xyz.
- The payload uses a signed Windows driver (DCRCVDrv.sys) with device path \Device\DCRCVDRV_U and communicates with it via IOCTL 0x2205c0 to send process identifiers for monitoring.
- After initial execution, the malware downloads secondary payloads from URLs such as https://kr.cedar2glanz.ru/jewel.js and https://phys.stunned-amniotic.com/hub.log, with one being a shellcode blob (SHA-256: 643ef355...).
- The Amatera stealer component establishes C2 communication using a dead-drop URL (telegra.ph/Functions-04-03) and later connects to a fixed IP (45.150.34.2) on port 443, while also making JSON-RPC calls to the BNB Smart Chain via bsc.rpc.blxrbdn.com.
- The infection chain installs a persistent backdoor via NetSupport Manager, which uses historical and active domains such as lb.propertyfind.cc and kffd3.vexlatech.cc, with one C2 IP (212.118.56.166) linked to Russia.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries use a WebDAV-based infection chain, leveraging malicious DLLs executed via rundll32.exe from UNC paths, to deliver credential and cryptocurrency stealers such as Amatera, ZigCryptoStealer, and NetSupport Manager. The chain employs stealthy techniques including Cloudflare Workers, blockchain-backed JavaScript, and dead drop C2 infrastructure, with payloads delivered through compromised domains and encrypted communication.

### Key Findings
- The infection chain begins with execution of a malicious DLL (e.g., 'verification.google') via rundll32.exe over a WebDAV UNC path, initiated by the Windows WebClient service.
- Two primary loaders, 'verification.google' and 'pf.ch', are used to deliver different secondary payloads, with the 'pf.ch' branch deploying a NativeAOT loader and shellcode (SHA-256: 643ef355...).
- C2 infrastructure includes dynamic domains like 'leaguejazire.com' and 'riyazinikokar.xyz', as well as dead drop URLs such as 'telegra.ph/Functions-04-03', and hardcoded IPs like 145.249.109.147 and 45.150.34.2.
- The Amatera stealer communicates with C2 via multiple domains, including 'bsc.rpc.blxrbdn.com' and 'lb.propertyfind.cc', and uses blockchain interaction (BNB Smart Chain) to dynamically resolve C2 endpoints.
- A signed Windows driver, DCRCVDrv.sys, is deployed and interacts with user processes via IOCTL 0x2205c0, indicating kernel-level persistence and process monitoring.
- Final payloads include the execution of 'hypersnap.exe' from a ZIP archive extracted to %APPDATA%, with a scheduled task created for persistence, and a modified 'Secur32.dll' used as a loader.

## 5. Research Synthesis

### Executive Summary
Adversaries leverage a WebDAV-based infection chain using rundll32.exe to execute malicious DLLs from randomized subdomains, employing memory-based execution via Windows fibers and a signed kernel driver (DCRCVDrv.sys) to maintain persistence and stage further payloads. The chain uses dynamic C2 infrastructure including dead-drop URLs, blockchain-backed endpoint resolution, and encrypted communication over port 443, enabling stealthy delivery of Amatera, ZigCryptoStealer, and NetSupport Manager with minimal file-based artifacts.

### Recommended Hypothesis
> Adversaries use WebDAV UNC path execution via rundll32.exe with randomized subdomains and WebClient service activation to deliver memory-resident payloads, leveraging a signed driver and blockchain-based C2 resolution to evade detection and maintain persistence.

### Gaps Identified
- Lack of telemetry mapping for `file_activity.path` and `network_activity.dst_endpoint.hostname` prevents correlation of file drops (e.g., hypersnap.exe, DCRCVDrv.sys) and C2 connections (e.g., bsc.rpc.blxrbdn.com, telegra.ph) to initial WebDAV execution events.
- Encrypted payload delivery via shellcode (SHA-256: 643ef355...) and dynamic domain resolution through BNB Smart Chain calls obfuscate the true C2 infrastructure and prevent static signature detection.

### Key Findings
- Hypothesis: Adversaries use WebDAV UNC path execution via rundll32.exe with randomized subdomains and WebClient service activation to deliver memory-resident payloads, leveraging a signed driver and blockchain-based C2 resolution to evade detection and maintain persistence.
- Gap: Lack of telemetry mapping for `file_activity.path` and `network_activity.dst_endpoint.hostname` prevents correlation of file drops (e.g., hypersnap.exe, DCRCVDrv.sys) and C2 connections (e.g., bsc.rpc.blxrbdn.com, telegra.ph) to initial WebDAV execution events.
- Gap: Encrypted payload delivery via shellcode (SHA-256: 643ef355...) and dynamic domain resolution through BNB Smart Chain calls obfuscate the true C2 infrastructure and prevent static signature detection.
- Focus: Implement detection logic for WebDAV UNC path execution via rundll32.exe with randomized subdomain patterns and embedded victim identifiers in the path, particularly when combined with WebClient service startup.
- Focus: Monitor for kernel driver activity involving IOCTL 0x2205c0 and device path \Device\DCRCVDRV_U, especially in conjunction with process enumeration and memory injection behaviors.
- Focus: Correlate outbound connections to known blockchain RPC endpoints (e.g., bsc.rpc.blxrbdn.com) with subsequent communication to dynamically resolved C2 domains (e.g., lb.propertyfind.cc) to detect dead-drop C2 staging.
