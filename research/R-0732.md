## 1. System Research: How It Works

### Summary
Threat actors utilize Web3 smart contracts and blockchain transactions to dynamically resolve Command and Control (C2) endpoints, allowing malware to update its infrastructure without hardcoding static domains or IPs. This technique enables the exfiltration of ephemeral cloud credentials (such as IAM keys and OIDC tokens) from compromised developer workstations and CI/CD pipelines by embedding malicious logic in open-source dependencies.

### Key Findings
- ChainDrop malware uses a 'preinstall' script hook to download a custom Bun runtime, which then harvests ephemeral cloud IAM keys, CI/CD worker tokens, and short-lived OIDC federation keys from both static disk files and the memory of running build processes.
- PolinRider campaigns conceal malicious loaders in repository configuration files, web resources, and IDE workspace automation to trigger silently when developers load a workspace, exfiltrating credentials while establishing persistence in enterprise build pipelines.
- Web3-based C2 resolution has evolved through three phases: Phase 1 (EtherHiding) uses smart contract storage for encrypted data; subsequent phases involve multi-chain transaction queries (TRON, Aptos, BSC) and zero-data address resolution techniques like NullReceiver to bypass network monitoring.
- Attackers deploy hybrid architectures for C2 reliability, using zero-data transfers as a backup channel when primary RPC gateways or multi-chain lookups are blocked, ensuring continuous access even if primary channels are disrupted.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries, particularly North Korea-affiliated groups like Shai-Hulud (ChainDrop) and PolinRider, exploit cloud supply chain compromises via poisoned open-source packages to harvest ephemeral cloud credentials. They subsequently utilize Web3 smart contracts and decentralized blockchain transactions as dynamic command-and-control (C2) channels to evade traditional network monitoring and maintain persistent infrastructure.

### Key Findings
- Supply chain malware such as the ChainDrop npm worm executes preinstall scripts to extract ephemeral IAM keys, CI/CD worker tokens, and OIDC federation keys from developer workstations and memory during build processes.
- Adversaries employ Web3-based C2 mechanisms like EtherHiding to store dynamically encrypted IP/domain endpoints within smart contract transactions, allowing for dynamic botnet updates without hard-coded infrastructure.
- The PolinRider campaign utilizes a multi-registry approach (npm, Go modules, Packagist) and conceals malicious loaders in repository configurations and IDE workspace files to exfiltrate credentials upon developer session initiation.
- To ensure C2 reliability, threat actors use hybrid architectures that combine multi-chain transaction queries (TRON, Aptos, Binance Smart Chain) with zero-data address resolution techniques like NullReceiver as backup channels.
- The evolution of this technique involves three phases moving from observable smart contract storage to zero-data transaction decoding, specifically designed to bypass automated static analysis tools and registry auditors that block hard-coded domains or IPs.

## 5. Research Synthesis

### Executive Summary
Threat actors, including DPRK-affiliated groups like Shai-Hulud and PolinRider, have evolved supply chain attacks by poisoning open-source dependencies to harvest ephemeral cloud credentials (IAM keys, OIDC tokens) from developer workstations and CI/CD pipelines. To maintain resilient Command and Control (C2), these actors utilize Web3 smart contracts—via techniques like EtherHiding, multi-chain transaction queries, and NullReceiver zero-data resolution—to dynamically update infrastructure endpoints, thereby bypassing traditional static domain/IP blocklists.

### Recommended Hypothesis
> Adversaries use poisoned open-source dependencies to harvest ephemeral cloud credentials and Web3 smart contract transactions for dynamic C2 endpoint resolution on developer workstations and CI/CD runners

### Gaps Identified
- Lack of visibility into outbound network traffic directed at blockchain RPC gateways and smart contract storage layers, allowing encrypted or zero-data transaction queries to bypass standard DNS and HTTP monitoring controls
- Inability to detect credential exfiltration from the memory space of build processes (e.g., custom Bun runtimes) during static analysis or standard endpoint telemetry collection, which only captures disk-based artifacts

### Key Findings
- Hypothesis: Adversaries use poisoned open-source dependencies to harvest ephemeral cloud credentials and Web3 smart contract transactions for dynamic C2 endpoint resolution on developer workstations and CI/CD runners
- Gap: Lack of visibility into outbound network traffic directed at blockchain RPC gateways and smart contract storage layers, allowing encrypted or zero-data transaction queries to bypass standard DNS and HTTP monitoring controls
- Gap: Inability to detect credential exfiltration from the memory space of build processes (e.g., custom Bun runtimes) during static analysis or standard endpoint telemetry collection, which only captures disk-based artifacts
- Focus: Implement network egress filtering and inspection specifically targeting RPC endpoints associated with Ethereum, TRON, Aptos, and Binance Smart Chain networks to identify abnormal smart contract interaction patterns
- Focus: Deploy memory forensics capabilities in CI/CD environments to detect the execution of obfuscated loaders (e.g., hidden Bun runtimes) and monitor for unauthorized access to ephemeral IAM keys and OIDC tokens within process memory
