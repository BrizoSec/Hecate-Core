## 1. System Research: How It Works

### Summary
The UAT-11985 threat actor employs AI-generated spear-phishing lures impersonating Taiwanese research events, utilizing both email hyperlinks and QR code phishing (quishing) to deliver a real-time Google Adversary-in-the-Middle (AitM) phishing kit. This infrastructure intercepts credentials and MFA challenges by relaying data via HTTP POST for exfiltration and WebSocket connections for command-and-control synchronization.

### Key Findings
- The phishing kit collects device telemetry including browser locale, user-agent string, screen dimensions, and mobile-device status, transmitting this data to the attacker's infrastructure.
- The attack utilizes a hybrid HTTP and WebSocket architecture where HTTP POST handles credential exfiltration while persistent WebSocket connections enable real-time synchronization of authentication workflows.
- Source code analysis reveals the phishing interface was originally developed in Simplified Chinese (zh-CN) as the base translation object, with Traditional Chinese (zh-TW) and English locales derived subsequently, indicating a Simplified Chinese-speaking developer.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse the Adversary-in-the-Middle (T1557) technique by deploying a reverse proxy that sits between the victim and legitimate authentication servers, enabling real-time interception of credentials and session tokens to bypass multi-factor authentication. In the UAT-11985 campaign, this was achieved using a phishing kit with a hybrid HTTP and WebSocket architecture to relay authentication artifacts dynamically while maintaining a pixel-perfect interface.

### Key Findings
- The UAT-11985 APT campaign targeted Taiwan-based research organizations using AI-assisted spear-phishing emails that impersonated legitimate academic institutions and utilized QR code phishing (quishing) on modified event posters to expand the attack surface.
- The adversary deployed a phishing kit impersonating Google authentication pages, utilizing a hybrid HTTP POST submission and WebSocket connection to synchronize the victim's user interface with the attacker's infrastructure in real time.
- This AiTM framework allows for dynamic control over the victim's login process, enabling the interception of valid session cookies and bypassing standard multi-factor authentication controls rather than just stealing static credentials.
- Technical analysis indicates the phishing kit's interface was originally developed in Simplified Chinese, with localization logic detecting user locales via 'navigator.languages' to serve Simplified Chinese, Traditional Chinese, or English versions.

## 5. Research Synthesis

### Executive Summary
The UAT-11985 threat actor deploys AI-generated spear-phishing lures to deliver a Google Adversary-in-the-Middle (AitM) proxy kit that synchronizes authentication workflows in real-time via WebSocket, allowing for the interception of credentials and MFA tokens. Detection is complicated by the use of legitimate-looking event infrastructure, QR code phishing (quishing), and locale-specific JavaScript obfuscation targeting Chinese-speaking users.

### Recommended Hypothesis
> Adversaries use AI-assisted spear-phishing and WebSocket-synchronized AitM proxying to intercept real-time Google credentials and MFA challenges on researchers in Taiwan.

### Gaps Identified
- Current telemetry lacks visibility into the initial WebSocket upgrade handshake (HTTP 101 Switching Protocols) which establishes the persistent C2 channel, blinding detection of the real-time credential relay.
- Endpoint monitoring does natively capture `navigator.languages` or specific iframe sandbox attributes (`sandbox="allow-scripts"`) within browser processes, missing the localized phishing kit identification.

### Key Findings
- Hypothesis: Adversaries use AI-assisted spear-phishing and WebSocket-synchronized AitM proxying to intercept real-time Google credentials and MFA challenges on researchers in Taiwan.
- Gap: Current telemetry lacks visibility into the initial WebSocket upgrade handshake (HTTP 101 Switching Protocols) which establishes the persistent C2 channel, blinding detection of the real-time credential relay.
- Gap: Endpoint monitoring does natively capture `navigator.languages` or specific iframe sandbox attributes (`sandbox="allow-scripts"`) within browser processes, missing the localized phishing kit identification.
- Focus: Monitor for outbound WebSocket connections from browsers to non-standard ports or unfamiliar domains immediately following HTTP GET requests to Google login endpoints.
