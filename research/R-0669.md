## 1. System Research: How It Works

### Summary
NeedyMantis is a modular, post-compromise malware framework deployed by the Storm-3069 threat actor to maintain long-term access in targeted environments. It utilizes custom encrypted archives and legitimate-sounding library names to load extensible components, communicating with command-and-control infrastructure via HTTPS and WebSockets.

### Key Findings
- The malware employs a loader DLL named WinSparkle.dll (SHA-256: e842dd7642c8e04b5ec20b6393848a9c904e4832930950c16664fe7800ba382e) which unpacks from an archive also named WinSparkle (SHA-256: 9cb68f986043a576e19d32184c583b7d8f571c7219d8dc0065dced1c13f077ef).
- The framework drops and executes files in non-standard locations within %ProgramData% and %ProgramFiles%, including paths such as %ProgramData%\USOShared\libcurl.dll, %ProgramData%\VIM\vim64.dll, and %ProgramData%\office\dbghelp.dll to evade detection.
- Network communications are established with the C2 host corp.tripswithengine[.]com on port 0x12c (300) using HTTPS and WebSockets, utilizing a custom executable file format for modular components.
- The malware enforces process uniqueness by creating a mutex named in the format <username>-<process name>, such as Contoso-Poedit.exe.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
NeedyMantis is a modular post-compromise malware framework employed by the threat actor Storm-3069 to maintain long-term access and support follow-on operations in targeted intrusions. The malware utilizes custom loaders, encrypted archives, and DLL sideloading techniques to disguise its components within legitimate-looking file paths while communicating with command-and-control servers via WebSocket connections.

### Key Findings
- The threat actor Storm-3069, associated with China, deploys NeedyMantis for targeted operations affecting sectors such as telecommunications, academia, medical nonprofits, and government contractors.
- The malware framework combines custom loaders (e.g., WinSparkle.dll) with encrypted archives to deliver extensible components, utilizing older versions that relied on libcurl file archives.
- NeedyMantis employs DLL sideloading by placing malicious or disguised DLLs in non-standard paths like %ProgramData%\USOShared\libcurl.dll and %ProgramData%\VIM\vim64.dll to evade detection.
- Command-and-control communications are established over WebSockets using RC4 encryption, with C2 hosts such as corp.tripswithengine[.]com identified in analyzed samples.
- The malware creates mutexes named in the format <username>-<process name> (e.g., Contoso-Poedit.exe) to ensure single-instance execution or coordinate processes.

## 5. Research Synthesis

### Executive Summary
NeedyMantis, utilized by the Storm-3069 threat actor, employs modular loaders like WinSparkle.dll to unpack encrypted archives into non-standard %ProgramData% paths, using legitimate-sounding filenames (e.g., libcurl.dll, vim64.dll) to evade detection. The framework maintains persistent C2 communications via WebSockets/HTTPS on port 300 and enforces instance uniqueness through custom mutex naming conventions (<username>-<process name>).

### Recommended Hypothesis
> Adversaries use modular DLL sideloading from disguised %ProgramData% paths to establish persistent WebSocket C2 channels for long-term access on targeted enterprise workstations.

### Gaps Identified
- Current detection relies heavily on static file hashes, missing behavioral indicators such as the specific mutex naming pattern (<username>-<process name>) and the creation of libraries in unexpected directories like %ProgramData%\USOShared or %ProgramData%\VIM.
- Network telemetry may fail to identify the custom executable format or RC4-encrypted WebSocket payloads targeting port 300 unless deep packet inspection or specific domain reputation checks are implemented for known C2 hosts.

### Key Findings
- Hypothesis: Adversaries use modular DLL sideloading from disguised %ProgramData% paths to establish persistent WebSocket C2 channels for long-term access on targeted enterprise workstations.
- Gap: Current detection relies heavily on static file hashes, missing behavioral indicators such as the specific mutex naming pattern (<username>-<process name>) and the creation of libraries in unexpected directories like %ProgramData%\USOShared or %ProgramData%\VIM.
- Gap: Network telemetry may fail to identify the custom executable format or RC4-encrypted WebSocket payloads targeting port 300 unless deep packet inspection or specific domain reputation checks are implemented for known C2 hosts.
- Focus: Deploy file integrity monitoring and anomalous library creation alerts in %ProgramData% subdirectories, specifically targeting DLLs named after legitimate libraries (libcurl, dbghelp) placed in non-standard folders.
- Focus: Implement network behavioral analysis to detect outbound WebSockets connections on port 300 (0x12c) and correlate them with the specific mutex creation events observed during process initialization.
