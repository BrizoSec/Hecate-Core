## 1. System Research: How It Works

### Summary
The KREMLIN malware operates by delivering a malicious browser extension that impersonates legitimate updates or drivers to steal banking sessions. It bypasses Chromium's built-in integrity mechanisms by manually extracting its payload into user profile directories and forging cryptographic hashes within the 'Secure Preferences' file, allowing the browser to load the extension as if it were officially approved.

### Key Findings
- The malware manipulates the Chromium 'Secure Preferences' file by enabling developer mode and registering the malicious extension under 'extensions.settings', while simultaneously regenerating the required HMACs and OSCrypt-encrypted SHA-256 hashes to bypass integrity checks.
- Infection begins with a multi-stage JavaScript loader that masquerades as banking documents, performs sandbox evasion via WMI process counts and desktop file checks, and downloads a Node.js runtime to execute subsequent stages.
- The operation leverages Ethereum smart contracts as dead-drop resolvers for dynamic Command and Control (C2) configuration, with attacker activity patterns clustering during São Paulo working hours.
- The malicious extension targets Chrome and Edge profiles by manually copying the ZIP archive into browser profile directories, intercepting credentials and session tokens through keylogging and request interception.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse MITRE ATT&CK T1608 by staging capabilities such as malicious browser extensions through multi-stage JavaScript loaders and custom C++ installers, which manipulate Chromium's 'Secure Preferences' to forge integrity checks. This technique allows the malware to bypass security mechanisms and silently install tools that intercept sensitive banking data and session tokens.

### Key Findings
- The KREMLIN toolkit (REF9334) forges Chrome's integrity checks by manipulating Secure Preferences and regenerating required HMACs to silently install malicious browser extensions in Chrome and Edge.
- Infection chains utilize multi-stage JavaScript loaders disguised as banking documents that perform sandbox evasion, download Node.js, and beacon to C2 servers via Ethereum smart contracts.
- Adversaries impersonate twelve Brazilian financial institutions using Portuguese-language lures, with transaction patterns clustering during São Paulo working hours.
- The operation has evolved over seven campaigns since May 2025, transitioning from PULSAR RAT to REMCOS RAT delivery mechanisms for session hijacking and credential theft.

## 5. Research Synthesis

### Executive Summary
The REF9334 adversary stages malicious browser extensions by manipulating the Chromium 'Secure Preferences' file to forge HMACs and OSCrypt-encrypted hashes, bypassing integrity checks to silently install capabilities in Chrome and Edge. This technique enables persistent session hijacking and credential theft via multi-stage JavaScript loaders that evade sandbox detection before deploying the payload.

### Recommended Hypothesis
> Adversaries use forged HMACs and OSCrypt hashes within the 'Secure Preferences' file to bypass Chromium integrity checks and silently stage malicious browser extensions for session hijacking on Windows endpoints running Chrome or Edge.

### Gaps Identified
- Lack of visibility into the regeneration of HMAC keys and OSCrypt-encrypted SHA-256 hashes in 'Secure Preferences', allowing the malware to appear as a legitimate, approved extension despite being manually staged.
- Insufficient correlation between Ethereum smart contract dead-drop resolutions and subsequent file system activity in user profile directories, missing the link between dynamic C2 configuration and local capability staging.

### Key Findings
- Hypothesis: Adversaries use forged HMACs and OSCrypt hashes within the 'Secure Preferences' file to bypass Chromium integrity checks and silently stage malicious browser extensions for session hijacking on Windows endpoints running Chrome or Edge.
- Gap: Lack of visibility into the regeneration of HMAC keys and OSCrypt-encrypted SHA-256 hashes in 'Secure Preferences', allowing the malware to appear as a legitimate, approved extension despite being manually staged.
- Gap: Insufficient correlation between Ethereum smart contract dead-drop resolutions and subsequent file system activity in user profile directories, missing the link between dynamic C2 configuration and local capability staging.
- Focus: Monitor for anomalous write operations to '%LOCALAPPDATA%\Google\Chrome\User Data\Default\Secure Preferences' that modify 'extensions.settings' or trigger HMAC regeneration outside of normal browser update cycles.
