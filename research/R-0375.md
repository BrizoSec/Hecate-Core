## 1. System Research: How It Works

### Summary
npm (Node Package Manager) is a package manager for the JavaScript programming language, commonly used to install and manage dependencies in Node.js projects. It allows developers to include external packages into their projects via a simple command-line interface and npm registry.

### Key Findings
- npm uses lifecycle scripts such as 'preinstall' and 'postinstall' which can be hijacked by malicious actors for self-propagation purposes.
- Malicious npm packages often use obfuscated JavaScript bundles to evade detection and establish persistence within a target's system.
- Attackers frequently spoof user-agent strings and manipulate network communication patterns to blend in with normal traffic, making it harder for security systems to detect their activities.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit npm (Node Package Manager) by injecting malicious code into widely-used packages, leveraging environment variables to detect CI/CD pipelines and execute specific routines. This allows them to republish the compromised repository or initiate data collection, while masquerading as legitimate updates.

### Key Findings
- Environment variables such as GITHUB_ACTIONS, GITHUB_REPOSITORY, and GITHUB_WORKFLOW_REF are used by attackers to identify CI/CD pipelines for targeted execution of malicious routines.
- The core payload is disguised as a helpful tool (like Bun installer) but contains massive files that could indicate suspicious activity due to their unusually large size.
- Adversaries use static routines within the worm's code to republish compromised repositories without further data collection, likely to avoid detection and maintain persistence in the npm ecosystem.
- The attack involves dynamic package updates where tarball versions of packages are downloaded and manipulated, suggesting a sophisticated approach to supply chain compromise.

## 3. Telemetry Mapping: OCSF Fields

### Summary
A self-propagating npm worm would exhibit behavior patterns like installing malicious packages, initiating network requests to fetch dependencies, and executing scripts or binaries from those packages. Telemetry should capture these actions for effective detection.

### Key Fields
- process_events.command_line (90% populated): Logs of command lines executed by processes can reveal npm install commands with suspicious package names.
- network.http.request.url (85% populated): Capturing HTTP requests made to NPM registries or other sources for fetching malicious packages is crucial.
- file_change_events.file_path (70% populated): Monitoring file system changes related to the installation of new npm packages can indicate propagation attempts.
- process_events.parent_process_id: Identifying parent processes that spawn npm installs can help trace back to initial infection vectors.
- dns.resolved_queries.question.name (80% populated): DNS requests for NPM package registries or other malicious domains can be indicative of worm activity.

## 5. Research Synthesis

### Executive Summary
Adversaries exploit npm by injecting malicious code into widely-used packages, using environment variables to detect CI/CD pipelines for targeted execution. They disguise payloads as legitimate tools and republish compromised repositories without further data collection to avoid detection.

### Recommended Hypothesis
> Adversaries use compromised npm packages with hidden scripts and large files to propagate malware across systems and evade detection on CI/CD pipelines.

### Gaps Identified
- Current coverage may lack telemetry for monitoring large file downloads from npm registries or specific environment variable checks indicative of CI/CD pipeline exploitation.

### Key Findings
- Hypothesis: Adversaries use compromised npm packages with hidden scripts and large files to propagate malware across systems and evade detection on CI/CD pipelines.
- Gap: Current coverage may lack telemetry for monitoring large file downloads from npm registries or specific environment variable checks indicative of CI/CD pipeline exploitation.
- Focus: Enhance logging and alerting for npm install commands, HTTP requests made to NPM registries, and file system changes associated with new package installations. Additionally, develop signatures to detect unusual patterns in package sizes and parent processes spawning npm installs.
