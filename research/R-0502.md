## 1. System Research: How It Works

### Summary
Falcon Onum is a data enrichment and routing tool developed by CrowdStrike that transforms raw security telemetry into actionable insights. It enhances the quality of data sent to various security systems, thereby improving detection capabilities while reducing storage costs.

### Key Findings
- Falcon Onum enriches real-time security data with additional context before forwarding it to different destinations.
- The system reduces noise in security data by filtering out irrelevant information and focusing on critical signals.
- It supports efficient routing of enriched data to CrowdStrike's Falcon platform and third-party tools, ensuring seamless integration and high-fidelity data delivery.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries may seek ways to evade detection by Falcon Onum through advanced obfuscation techniques or by exploiting gaps in data enrichment processes. They might leverage known vulnerabilities or misconfigurations to bypass security controls, thereby reducing the system's effectiveness.

### Key Findings
- Adversaries frequently employ command-line obfuscation and shell scripting tricks to evade detection.
- Insider threats can be challenging to detect due to legitimate access rights; context-aware monitoring is crucial.
- Data exfiltration often involves using common protocols in unconventional ways, such as DNS tunneling or HTTP/HTTPS for data transfer.
- Misconfigurations in cloud environments provide opportunities for adversaries to establish footholds and laterally move within the network.
- Threat actors increasingly use AI and machine learning models to automate attacks and mimic normal user behavior.
- Security teams must continuously update their detection rules and signatures to counteract evolving attack vectors.

### Summary
Detection of unauthorized access patterns indicating potential lateral movement through Remote Desktop Protocol (RDP).

### Key Fields

- destination.ip: Server or workstation being accessed via RDP, helping identify unusual connections patterns across endpoints.
- event.category: Categorizes events into logon, authentication, etc., enabling focus on login activities that could indicate lateral movement.
- process.name: Identifies specific processes (e.g., RDP client applications) used excessively or in an unusual manner.
