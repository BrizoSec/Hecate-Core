## 1. System Research: How It Works

### Summary
The Bun runtime, a package manager and JavaScript runtime similar to npm, is designed to execute scripts directly from the npm internal cache directory. The Shai-Hulud attack leverages this by placing malicious code in the cache that gets executed during the deobfuscation process.

### Key Findings
- Bun executes payloads located in the .npm/_cacache/tmp/git-clone/ directory, which is part of npm's internal caching mechanism.
- The payload undergoes a complex deobfuscation process within this cache directory to execute malicious activities.
- Detection and mitigation strategies need to focus on monitoring and securing access to npm’s cache directories.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are exploiting npm (Node Package Manager) supply chain vulnerabilities to deploy Shai-Hulud-style worms that self-replicate across GitHub repositories, utilizing techniques such as system owner/user discovery (T1033) and time discovery (T1124) to gather credentials and propagate malware.

### Key Findings
- Adversaries are using npm package dependencies in the open-source ecosystem to distribute malicious code that self-replicates across GitHub repositories, targeting Linux and macOS systems.
- Techniques T1033 (System Owner/User Discovery) and T1124 (Time Discovery) are employed to identify system users and gather timing information for optimal exfiltration of credentials.
- The Shai-Hulud worm has compromised hundreds of npm packages, leading to the creation of numerous public GitHub repositories containing stolen credentials and malware artifacts.
- Attackers leverage common system commands such as `ip addr` and `ip route` for network configuration discovery (T1016) to further their objectives in compromised environments.

## 5. Research Synthesis

### Executive Summary
Adversaries are exploiting npm supply chain vulnerabilities to deploy Shai-Hulud-style worms that self-replicate across GitHub repositories, employing techniques such as system owner/user discovery (T1033) and time discovery (T1124) to gather credentials and propagate malware. These attacks leverage common system commands for network configuration discovery, compromising hundreds of npm packages and creating numerous public GitHub repositories.

### Recommended Hypothesis
> Adversaries use npm package dependencies to deploy self-replicating Shai-Hulud worms that exploit system owner/user discovery techniques to gather credentials and propagate malware across compromised GitHub repositories.

### Gaps Identified
- Current detection strategies lack comprehensive coverage for monitoring and securing npm's internal cache directories, where Bun executes malicious payloads during deobfuscation.
- There is insufficient telemetry collection on network connections initiated by specific users, which hinders the identification of anomalous behavior patterns associated with system owner/user discovery.

### Key Findings
- Hypothesis: Adversaries use npm package dependencies to deploy self-replicating Shai-Hulud worms that exploit system owner/user discovery techniques to gather credentials and propagate malware across compromised GitHub repositories.
- Gap: Current detection strategies lack comprehensive coverage for monitoring and securing npm's internal cache directories, where Bun executes malicious payloads during deobfuscation.
- Gap: There is insufficient telemetry collection on network connections initiated by specific users, which hinders the identification of anomalous behavior patterns associated with system owner/user discovery.
- Focus: Enhance detection and mitigation strategies to monitor npm cache directories for suspicious activity, especially around Bun's runtime execution processes.
- Focus: Improve endpoint telemetry collection to capture detailed user-level access information and network connection details to better detect and respond to T1033 activities.
