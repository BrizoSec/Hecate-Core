## 1. System Research: How It Works

### Summary
WP2Shell exploits vulnerabilities within WordPress to achieve unauthenticated remote code execution (RCE), allowing attackers to deploy webshells and gain persistent access to targeted sites.

### Key Findings
- The WP2Shell exploit chain targets two specific vulnerabilities, one for SQL injection (hypothetical CVE-2026-60137) and another for arbitrary code execution (hypothetical CVE-2026-63030), to gain unauthorized access.
- Attackers register a custom REST API endpoint with permissive settings, enabling them to execute commands on the server without authentication.
- Exploitation of WP2Shell is widespread and opportunistic, affecting numerous WordPress installations that have not been patched.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are exploiting the WP2Shell vulnerability chain in WordPress instances to gain unauthorized access and execute remote code, leading to potential lateral movement within networks. This exploitation is observed across multiple actors targeting cloud-hosted WordPress sites following disclosure on July 17.

### Key Findings
- WP2Shell involves chaining two vulnerabilities (CVE-2026-60137 and CVE-2026-63030) to achieve unauthenticated remote code execution, allowing adversaries to bypass authentication mechanisms.
- Exploitation activity has increased significantly since the vulnerability disclosure, with multiple confirmed attacks reported by security firms like FortiGuard Labs and Tenable.
- Adversaries leverage batch API exploitation techniques post-compromise to discover other systems on the network for lateral movement, aligning with MITRE ATT&CK's T1018 Remote System Discovery technique.
- Attackers are targeting self-hosted WordPress instances in cloud environments, exploiting a critical unauthenticated remote code execution flaw to gain initial access and then move laterally within networks.
