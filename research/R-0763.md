## 1. System Research: How It Works

### Summary
INC Ransomware operates via a double extortion model, stealing victim data and threatening to leak it if the ransom is not paid. [A sentence citing an unsourced CVE was removed from this summary.]

### Key Findings
- The malware employs a double extortion methodology, where stolen data is leaked publicly if the victim does not comply with ransom demands, rather than just encrypting files for leverage.
- File encryption logic is size-dependent: files under 1MB are fully encrypted, while larger files have only the first 1MB encrypted, leaving the remainder intact.
- The threat group utilizes multi-threading to accelerate the encryption process and conducts extensive reconnaissance prior to deployment.
- Post-encryption tactics include deleting shadow copies to hinder recovery, changing the desktop wallpaper to display the ransom note, and printing the note via network printers.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse scheduled tasks and remote execution utilities like Impacket's atexec.py to achieve persistence, deploy EDR/AV killers via Bring Your Own Vulnerable Driver (BYOVD) tactics, and execute ransomware across multiple endpoints. This dual extortion campaign involves dropping two distinct ransom notes to pressure victims, with the second note detailing stolen data to threaten public exposure.

### Key Findings
- The INC ransomware group utilizes Impacket's atexec.py to create temporary scheduled tasks for remote execution of malicious tools on compromised endpoints.
- Attackers employ Bring Your Own Vulnerable Driver (BYOVD) tactics, such as deploying a renamed vRx executable, to disable security controls before encryption.
- The campaign features a dual extortion approach with two ransom notes: 'INC-README.txt' for standard payment demands and 'DATALEAK_PRESS_RELEASE.txt' detailing stolen files to threaten media and partner notification.
- File encryption is performed using AES-128 in CTR mode for data and Curve25519 elliptic-curve cryptography for key protection, with encrypted files appending the '.inc' extension.
- The attack timeline suggests a potential split between an Initial Access Broker (IAB) conducting early lateral movement via RDP and a separate ransomware affiliate executing the final deployment phase after a 17-day lull.

## 5. Research Synthesis

### Executive Summary
INC ransomware affiliates utilize a two-phase attack pattern involving early-stage persistence via randomized scheduled tasks and lateral movement, followed by a lull before deploying BYOVD tools (renamed vRx) and AnyDesk to disable security controls prior to encryption. The adversary employs double extortion tactics, dropping a secondary 'DATALEAK_PRESS_RELEASE.txt' note detailing specific exfiltrated file paths to escalate pressure on victims within 48 hours.

### Recommended Hypothesis
> Adversaries use Bring Your Own Vulnerable Driver (BYOVD) masquerading as legitimate updaters and randomized scheduled tasks to disable endpoint protection and maintain persistence, enabling the deployment of INC ransomware across lateralized endpoints.

### Gaps Identified
- Telemetry visibility is significantly reduced during post-incident investigations due to log rotation ('oxidization') and the lack of EDR data during the initial compromise phase, making it difficult to capture the exact initial access vector or the execution of the PowerShell implant 'jocularities.ps1' via its C2 domain.

### Key Findings
- Hypothesis: Adversaries use Bring Your Own Vulnerable Driver (BYOVD) masquerading as legitimate updaters and randomized scheduled tasks to disable endpoint protection and maintain persistence, enabling the deployment of INC ransomware across lateralized endpoints.
- Gap: Telemetry visibility is significantly reduced during post-incident investigations due to log rotation ('oxidization') and the lack of EDR data during the initial compromise phase, making it difficult to capture the exact initial access vector or the execution of the PowerShell implant 'jocularities.ps1' via its C2 domain.
- Focus: Implement detection rules for the creation of scheduled tasks with high-entropy/randomized names pointing to unusual paths (e.g., ProgramData or renamed legitimate binaries like HealthUpdater.exe), and monitor for the execution of AnyDesk coupled with known BYOVD drivers (netscan.exe/vRx) prior to mass file system encryption events.
