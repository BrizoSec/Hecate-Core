## 1. System Research: How It Works

### Summary
AI coding assistants like OpenCode and Hermes generate persistent forensic artifacts on the endpoint, primarily stored in SQLite databases and JSON log files within user-specific configuration directories. These tools record detailed session metadata, conversation turns, API request payloads, and application logs, which can be reconstructed into readable transcripts or structured exports for investigative review.

### Key Findings
- OpenCode stores session data in a SQLite database at ~/.local/share/opencode/opencode.db, utilizing separate 'message' and 'part' tables or a consolidated 'session_message' table to record text, tool calls, reasoning, and cost accounting.
- Hermes maintains evidence across multiple locations: ~/.hermes/state.db for sessions and model usage, ~/.hermes/sessions/request_dump_*.json for full LLM API request/response payloads, and ~/.hermes/logs/ for agent and GUI activity logs.
- Both tools preserve high-fidelity telemetry including original epoch-millisecond timestamps, token counts, cost data, and specific tool input/output artifacts, which may contain sensitive secrets or code snippets.
- Hermes supports isolated profiles stored under ~/.hermes/profiles/<profile_name>/, each containing its own distinct database, session directories, logs, and configuration files.
- Forensic extraction scripts can target specific time ranges using --start/--end parameters and filter by source type (e.g., request dumps vs. application logs), allowing investigators to isolate API interactions from general application activity.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
This intelligence report details forensic methodologies for reconstructing activity from AI coding agents (specifically OpenCode and Hermes) rather than describing how adversaries abuse these systems. It provides two Python scripts designed to extract chat histories, tool calls, API payloads, and logs from local SQLite databases and application artifacts for incident response purposes.

### Key Findings
- Adversaries utilizing AI coding assistants like OpenCode or Hermes leave forensic artifacts in local SQLite databases (e.g., ~/.local/share/opencode/opencode.db or ~/.hermes/state.db), which can be extracted without modifying the original evidence by copying WAL/SHM sidecars.
- Forensic reconstruction must account for both conversation content (user prompts, assistant responses, reasoning) and operational metadata, including tool call inputs/outputs, API request dumps, token usage, and cost accounting records.
- Evidence collection should target multiple artifact types: SQLite session databases for structured chat turns, JSON request dump files for full LLM API payloads (headers, bodies), and application logs for error states and component activity.
- Investigations must consider that AI agents may store data in profile-specific directories (e.g., ~/.hermes/profiles/<profile_name>/) rather than just the default home directory, potentially hiding evidence from standard forensic sweeps.
- Extracted data often contains sensitive information including secrets within tool inputs/outputs and authentication credentials; while scripts do not open auth.json directly, the conversation transcripts themselves may expose compromised credentials.

## 5. Research Synthesis

### Executive Summary
Forensic analysis of AI coding assistants like OpenCode and Hermes reveals persistent local artifacts, including SQLite databases and JSON request dumps, which capture high-fidelity telemetry such as user prompts, tool calls, API payloads, and cost metrics. These artifacts provide a reconstructable trail of agent activity that can be leveraged to detect malicious code generation or data exfiltration attempts facilitated by legitimate developer tools.

### Recommended Hypothesis
> Adversaries use AI coding assistants (OpenCode/Hermes) to generate and execute malicious payloads via local SQLite session logs and API request dumps while evading traditional network egress monitoring.

### Gaps Identified
- Lack of automated parsing for OpenCode's consolidated 'session_message' tables and Hermes' multi-source JSON/Log artifacts prevents efficient correlation of user prompts with resulting tool outputs and API costs.
- Standard forensic workflows often overlook profile-specific isolation directories (~/.hermes/profiles/) and WAL/SHM sidecar files, allowing evidence to persist in non-standard locations or become inaccessible due to database locking issues.

### Key Findings
- Hypothesis: Adversaries use AI coding assistants (OpenCode/Hermes) to generate and execute malicious payloads via local SQLite session logs and API request dumps while evading traditional network egress monitoring.
- Gap: Lack of automated parsing for OpenCode's consolidated 'session_message' tables and Hermes' multi-source JSON/Log artifacts prevents efficient correlation of user prompts with resulting tool outputs and API costs.
- Gap: Standard forensic workflows often overlook profile-specific isolation directories (~/.hermes/profiles/) and WAL/SHM sidecar files, allowing evidence to persist in non-standard locations or become inaccessible due to database locking issues.
- Focus: Implement detection logic that monitors for the creation of opencode.db and state.db artifacts, specifically extracting 'tool_call' inputs/outputs and 'request_dump' headers to identify unauthorized API usage or sensitive data injection within chat transcripts.
