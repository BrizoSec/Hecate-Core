## 1. System Research: How It Works

### Summary
Google Tag Manager is a legitimate service that manages and deploys marketing tags or tracking codes on websites without modifying the underlying website code directly. It functions by injecting scripts into web pages to facilitate data collection and third-party integrations for analytics and advertising purposes.

### Key Findings
- Legitimate Google Tag Manager scripts are hosted on the 'googletagmanager.com' domain, which attackers have begun abusing directly rather than relying solely on impersonated domains.
- The technology generates JavaScript code snippets that are injected into the source code of targeted websites to manage tag deployment.
- While legitimate use involves loading trusted tags, this abuse vector allows for the injection of malicious scripts that can trigger further malicious payloads.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The GrelosGTM group compromises e-commerce websites, particularly those running Magento CMS, by injecting malicious Google Tag Manager scripts into the site source code. This technique allows them to load multi-stage JavaScript payloads via WebSocket connections, ultimately deploying an obfuscated sniffer that captures payment card data through fake checkout forms.

### Key Findings
- Adversaries abuse legitimate Google Tag Manager functionality by injecting custom scripts (e.g., container ID GTM-5SF293J) directly into the source code of targeted e-commerce websites.
- The attack targets Magento CMS platforms and has affected at least seven known sites across Belgium, Italy, the United Kingdom, and the United States.
- Malicious payloads are delivered using multi-stage techniques, initially loading code from domains impersonating legitimate services before evolving to use WebSocket connections for subsequent stages.
- The final payload is a heavily obfuscated JavaScript sniffer that detects checkout pages and creates fake payment forms to steal customer bank card information.
- Exfiltrated financial data is sent to attacker-controlled servers, resulting in financial fraud and reputational damage for the affected businesses.

## 5. Research Synthesis

### Executive Summary
The GrelosGTM group abuses legitimate Google Tag Manager infrastructure to inject malicious scripts into Magento e-commerce sites, establishing WebSocket connections to attacker-controlled domains (e.g., webfaset[.]com) for multi-stage payload delivery. This technique enables the deployment of obfuscated JavaScript sniffers that intercept payment card data via fake checkout forms without relying on traditional domain impersonation.

### Recommended Hypothesis
> Adversaries use legitimate Google Tag Manager scripts to inject malicious WebSocket-based JavaScript sniffer payloads into Magento e-commerce websites to steal payment card information during checkout.

### Gaps Identified
- Current telemetry lacks visibility into non-standard WebSocket ports (e.g., port 80 for wss://) and may fail to distinguish between legitimate GTM script execution and the subsequent download of malicious CSS/JS payloads from attacker-controlled domains like webfaset[.]com.

### Key Findings
- Hypothesis: Adversaries use legitimate Google Tag Manager scripts to inject malicious WebSocket-based JavaScript sniffer payloads into Magento e-commerce websites to steal payment card information during checkout.
- Gap: Current telemetry lacks visibility into non-standard WebSocket ports (e.g., port 80 for wss://) and may fail to distinguish between legitimate GTM script execution and the subsequent download of malicious CSS/JS payloads from attacker-controlled domains like webfaset[.]com.
- Focus: Monitor network connections initiated by browser contexts on e-commerce sites for WebSocket upgrades to non-standard ports or suspicious hostnames, specifically tracking the retrieval of .css files with JavaScript content via the wss:// protocol.
- Focus: Analyze file system and source code integrity monitoring logs for unauthorized injections of Google Tag Manager container IDs (e.g., GTM-XXXXXXX) into Magento template files or header scripts.
