## 1. System Research: How It Works

### Summary
Automated AI analysis pipelines typically extract plaintext strings from malicious samples and submit them to language models for triage or classification, creating a vector where embedded instructions can manipulate the model's verdict. This process allows threat actors to inject natural-language directives that exploit the ambiguity between sample content and analyst queries, potentially steering the AI away from identifying malicious intent.

### Key Findings
- Threat actors embed inert plaintext comments within malware (such as PowerShell scripts or compiled binaries) that explicitly instruct LLMs not to analyze the file or declare it benign, a technique classified under the 'A3: AI-Analysis Evasion' archetype.
- Operators use template spraying to maximize evasion success by embedding instructions formatted in multiple distinct LLM chat template styles simultaneously within the same binary.
- Malware authors employ intimidation and deception tactics, such as falsely claiming the binary is a monitored honeypot or referencing fabricated legal frameworks (e.g., fake DoD contracts, NDA numbers, or copyright protections) to trigger model guardrails.
- The technique requires no complex engineering overhead; it involves adding dummy functions or variables to preserve the evasion strings during compilation, with observed success rates of steering AI outcomes in approximately 35% of test runs.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries employ 'AI-analysis evasion' by embedding natural-language instructions within malware samples to exploit the ambiguity in automated analysis pipelines, attempting to induce language models to treat malicious content as benign or refuse analysis. These techniques range from simple comments claiming non-malicious intent to complex template spraying and intimidation tactics designed to bypass AI guardrails.

### Key Findings
- This technique classifies under CAIRN A3 (AI-Analysis Evasion) and targets the text-extraction pipeline rather than binary analysis layers, exploiting the risk that an LLM might interpret embedded strings as authoritative instructions rather than sample content.
- The FRUITSHELL family initiated this trend with simple, verbatim comments claiming the file performs harmless tasks like prime number generation, a technique later adopted by more sophisticated actors and families such as ROZESHELL without modification.
- Advanced implementations like PLOTSAFE use template-based generation to vary filler keywords (e.g., 'memory allocator fragmentation analysis') while maintaining the same structural evasion skeleton, requiring engineering efforts like dummy functions to prevent compiler string deletion.
- The HOLLOWCLAD family utilizes 'template spraying' by including seven distinct copies of instructions formatted to match different LLM chat templates, alongside deceptive metadata naming known protector frameworks (e.g., Themida, UPX) despite the binary being unpacked.
- MANTLEMAZE combines template-spray injections with intimidation notes and fabricated credentials (e.g., fake DoD contracts, FIPS certifications) to trigger AI guardrails, while its loader stage exploits a known vulnerability in Intel Ethernet drivers (CVE-2015-2291) for EDR bypass.
- Evaluation suggests these techniques are inexpensive to implement but inconsistently impactful, with successful evasion occurring in approximately 35% of test runs; however, the presence of such plaintext instructions serves as a detectable signal for tracking adversary progression.

## 5. Research Synthesis

### Executive Summary
Adversaries are deploying 'A3: AI-Analysis Evasion' by embedding natural language instructions and template-sprayed payloads within malware strings to manipulate automated LLM triage pipelines, successfully steering analysis outcomes in approximately 35% of cases. This technique exploits the ambiguity between sample content and system prompts rather than traditional binary obfuscation, rendering standard behavioral telemetry ineffective as the evasion code remains inert during execution.

### Recommended Hypothesis
> Adversaries use template-sprayed natural language instructions and fabricated legal/intimidation metadata embedded in plaintext strings to mislead automated LLM analysis pipelines into classifying malicious samples as benign or refusing analysis.

### Gaps Identified
- Current endpoint detection relies on behavioral telemetry (process creation, network connections), which fails to capture this technique because the evasion strings are purely static artifacts with zero runtime execution impact; detection requires deep static string extraction and semantic analysis of file contents rather than dynamic monitoring.
