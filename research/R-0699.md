## 1. System Research: How It Works

### Summary
FortiGate SSL-VPN appliances normally provide secure remote access to internal networks by authenticating users and establishing encrypted tunnels, but this environment was compromised via CVE-2024-21762. The attacker leveraged the breach to deploy MeshCentral for persistent command-and-control, targeting 3BB's RADIUS authentication databases and internal infrastructure.

### Key Findings
- The FortiGate 60F SSL-VPN at mail.3bb.co.th was exploited using CVE-2024-21762, with the staging server at 92.63.180.133:8888 serving as both the reverse shell callback host and the source of exploitation scripts.
- MeshCentral was configured for persistence with agents actively connecting to www.ayuthayatech.com under a device group explicitly named 'TH-3BB', indicating established command-and-control infrastructure.
- The attacker targeted 3BB's RADIUS authentication infrastructure (specifically radius_corp and radiusinfo databases) to harvest subscriber credentials, alongside internal hosts in the 10.11.x.x subnet.
- Post-compromise operations included privilege escalation using PwnKit (CVE-2021-4034) and Dirty COW (CVE-2016-5195), followed by lateral movement via SSH brute-forcing across 55+ internal hosts and MySQL credential dumping.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The adversary conducted active scanning (T1595) to validate and exploit CVE-2024-21762 in FortiGate SSL-VPN appliances, using the resulting foothold to deploy MeshCentral for persistent command-and-control. This phase of reconnaissance and exploitation allowed the attacker to harvest credentials from RADIUS databases and establish a staging server containing extensive tooling for lateral movement and privilege escalation.

### Key Findings
- The attacker utilized CVE-2024-21762 against a FortiGate 60F SSL-VPN at mail.3bb.co.th, with the staging server at 92.63.180.133 serving as both the exploit repository and the reverse shell callback host.
- MeshCentral was deployed as a persistent backdoor, with device configurations explicitly targeting a group named 'TH-3BB' and connecting to the C2 server www.ayuthayatech.com.
- Reconnaissance scripts (forti1.sh through forti8.sh) were used for FortiGate fingerprinting and CVE detection, while additional tools probed for F5 BIG-IP vulnerabilities such as CVE-2021-22986 and Ghostcat (CVE-2020-1938).
- The exposed staging directory contained credential harvesting scripts targeting RADIUS databases (radius_corp, radiusinfo) and SSH brute-force utilities that had already enumerated over 55 internal hosts.
- Privilege escalation was facilitated by pre-staged exploits for PwnKit (CVE-2021-4034) and Dirty COW (CVE-2016-5195), alongside tools for MySQL exploitation and web shell deployment.

## 5. Research Synthesis

### Executive Summary
Adversaries executed active scanning against FortiGate SSL-VPN appliances to validate and exploit CVE-2024-21762, leveraging the resulting foothold to deploy MeshCentral for persistent command-and-control while harvesting RADIUS credentials via lateral movement. The operation utilized a staging server to orchestrate extensive network enumeration, privilege escalation exploits (PwnKit/Dirty COW), and SSH brute-forcing across internal infrastructure targeting subscriber authentication systems.

### Recommended Hypothesis
> Adversaries use active scanning and CVE-2024-21762 exploitation to bypass perimeter defenses, enabling deployment of MeshCentral persistence and RADIUS credential harvesting on targeted broadband infrastructure.

### Gaps Identified
- Lack of visibility into internal SSH brute-force traffic patterns and MySQL LOAD_FILE abuse makes lateral movement detection difficult without specific host-based telemetry.
- Encrypted MeshCentral C2 traffic to legitimate-looking domains (www.ayuthayatech.com) blends with normal SSL-VPN usage, obscuring the command-and-control channel in standard network logs.

### Key Findings
- Hypothesis: Adversaries use active scanning and CVE-2024-21762 exploitation to bypass perimeter defenses, enabling deployment of MeshCentral persistence and RADIUS credential harvesting on targeted broadband infrastructure.
- Gap: Lack of visibility into internal SSH brute-force traffic patterns and MySQL LOAD_FILE abuse makes lateral movement detection difficult without specific host-based telemetry.
- Gap: Encrypted MeshCentral C2 traffic to legitimate-looking domains (www.ayuthayatech.com) blends with normal SSL-VPN usage, obscuring the command-and-control channel in standard network logs.
- Focus: Monitor for anomalous FortiGate API calls and HTTP 500 error spikes indicative of CVE-2024-21762 exploitation attempts, specifically looking for reverse shell callbacks to external IPs.
