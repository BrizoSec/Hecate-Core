## 1. System Research: How It Works

### Summary
Microsoft Power BI is a legitimate business intelligence service that allows users to visualize data and share reports via unique, secure URLs hosted on app.powerbi.com. In this campaign, adversaries abused the platform's trusted domain to bypass email security filters, redirecting victims to attacker-controlled sites for initial access.

### Key Findings
- Legitimate Power BI sharing links (app.powerbi.com/view?r=...) are abused as the initial entry point in phishing emails to establish credibility and evade detection before redirecting users to malicious infrastructure.
- The campaign utilizes browser fingerprinting on attacker-controlled domains (e.g., dailylifeproject.site, burnsworth.site) to validate victim environments before delivering rogue ScreenConnect installers from hamham27.screenconnect.com.
- Post-compromise persistence is achieved via a scheduled task named 'SCAutoRepairEvery2Min' that executes malicious PowerShell scripts (SCAutoFix.ps1) and CMD files from the temp directory every two minutes.
- Defense evasion techniques include the execution of HideUL_x64.exe to hide process activity, while C2 communication leverages legitimate ScreenConnect relay domains (instance-g01s1n-relay.screenconnect.com) alongside attacker-controlled onthegotree.site.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are conducting phishing campaigns that exploit legitimate Microsoft Power BI domains to bypass email security controls and distribute rogue ScreenConnect remote monitoring tools. After initial redirection, attackers use browser fingerprinting and Telegram bots to validate targets before deploying multiple persistent RMM instances and defense evasion artifacts.

### Key Findings
- Attackers abuse legitimate Microsoft Power BI infrastructure (app.powerbi.com) to host fake reference documents, leveraging trusted domains to increase credibility and evade email security filters.
- The campaign employs browser fingerprinting and Telegram bot integration to filter victims based on system characteristics before triggering the malicious payload delivery.
- Malicious ScreenConnect installers are distributed via attacker-controlled subdomains of screenconnect.com (e.g., hamham27.screenconnect.com) and rogue domains like onthegotree.site, mimicking legitimate client setup files.
- Persistence is maintained through scheduled tasks such as 'SCAutoRepairEvery2Min' that execute scripts like SCAutoFix.ps1 every two minutes to ensure continued access.
- Threat actors utilize defense evasion tools like HideUL_x64.exe and deploy multiple ScreenConnect clients (ScreenConnect.ClientService.exe) connected to distinct C2 infrastructure for redundancy.

## 5. Research Synthesis

### Executive Summary
Adversaries are abusing legitimate Microsoft Power BI sharing links to bypass email security controls and redirect victims to attacker-controlled domains performing browser fingerprinting before delivering rogue ScreenConnect installers. Post-exploitation, threat actors establish persistent remote access via scheduled tasks executing malicious scripts every two minutes, while utilizing defense evasion tools like HideUL_x64.exe to obscure process activity and C2 communications.

### Recommended Hypothesis
> Adversaries use legitimate Power BI URLs for initial access and attacker-controlled subdomains of screenconnect.com for payload delivery to deploy rogue ScreenConnect RMMs with scheduled task persistence on targeted endpoints.

### Gaps Identified
- Standard endpoint detection may miss the initial phishing phase as it relies on trusted Microsoft domains (app.powerbi.com) which often bypass URL reputation filters, requiring behavioral monitoring of redirect chains rather than static domain blocking.
