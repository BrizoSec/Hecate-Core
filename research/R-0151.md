## 1. System Research: How It Works

### Summary
The Shai-Hulud-style npm worm is a sophisticated piece of malware that targets GitHub and cloud credentials by compromising npm packages. It propagates through the npm ecosystem, manipulates GitHub repositories to spread further, and uses triple deobfuscation techniques to activate its payload.

### Key Findings
- Shai-Hulud harvests and exfiltrates victim's GitHub and cloud credentials.
- The worm utilizes intelligent reconnaissance to adapt its attack vector effectively.
- Triple deobfuscation is employed to execute the malware payload within npm’s internal cache directory.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The 'Shai-Hulud' worm targets the npm ecosystem, compromising developer credentials and exposing them publicly. Although the exact attribution is uncertain, there are links to TeamPCP through shared infrastructure patterns.

### Key Findings
- Adversaries are exploiting the npm package manager by injecting malicious code that steals GitHub and npm credentials.
- Compromised credentials are exposed in public repositories or other accessible locations.
- The attack leverages a worm-like propagation mechanism, infecting multiple packages to maximize credential theft.
- Infrastucture hosting patterns suggest a connection to TeamPCP, particularly the use of AS43641.
- Credential rotation and strict access control are critical mitigation strategies against such attacks.

## 3. Telemetry Mapping: OCSF Fields

### Summary
The telemetry captures unauthorized access to npm registries through compromised GitHub credentials, unusual npm registry interactions, and indications of lateral movement or data exfiltration.

### Key Fields
- user.authenticated_user: Identifies the user account being used for npm operations (10% populated). This field would be crucial in identifying if a known user is involved or if it's an unknown entity.
- event.category: Monitors specific categories such as authentication, file access/change/creation, network activity, and process execution (95% populated). Helps detect unauthorized actions like installing packages from compromised GitHub repositories.
- process.name: Tracks the names of processes related to npm registry interactions or package management tools (80% populated). Useful for identifying if malicious scripts or tools are being executed.
- network.protocol: Identifies protocols involved in network communications, particularly HTTP/HTTPS used by npm and GitHub API calls (92% populated). This helps confirm unusual outbound traffic patterns indicative of data exfiltration or communication with compromised repositories.
- file.path: Monitors file paths for changes to package.json files or other repository configuration files that might indicate unauthorized modifications (75% populated).
- event.module: Identifies specific modules or tools involved in the event, such as npm itself and related scripts (60% populated). This helps pinpoint the exact mechanisms used by the worm.

## 5. Research Synthesis

### Executive Summary
The Shai-Hulud-style npm worm is a sophisticated malware that targets GitHub and cloud credentials through the npm ecosystem, employing triple deobfuscation techniques for payload execution. Although attribution remains uncertain, there are links to TeamPCP based on shared infrastructure patterns.

### Recommended Hypothesis
> Adversaries use compromised npm packages to harvest and exfiltrate victim GitHub and cloud credentials in order to maximize lateral movement and data theft within the npm ecosystem.

### Gaps Identified
- Current telemetry lacks comprehensive coverage of user.authenticated_user fields, potentially missing critical identification of unauthorized entities involved in npm registry interactions.
- There is limited visibility into the specific infrastructure used by adversaries to exfiltrate stolen credentials, hindering full attribution efforts.

### Key Findings
- Hypothesis: Adversaries use compromised npm packages to harvest and exfiltrate victim GitHub and cloud credentials in order to maximize lateral movement and data theft within the npm ecosystem.
- Gap: Current telemetry lacks comprehensive coverage of user.authenticated_user fields, potentially missing critical identification of unauthorized entities involved in npm registry interactions.
- Focus: Investigating unusual npm package installations from compromised GitHub repositories using event.category and process.name telemetry for detecting malicious activity patterns.
- Gap: There is limited visibility into the specific infrastructure used by adversaries to exfiltrate stolen credentials, hindering full attribution efforts.
- Focus: Analyzing network.protocol telemetry to identify anomalous outbound traffic indicative of data exfiltration or communication with compromised repositories.
