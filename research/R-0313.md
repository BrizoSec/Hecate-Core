## 1. System Research: How It Works

### Summary
.NET Native AOT compiles .NET applications ahead-of-time into native code for improved performance and reduced startup time. It supports direct P/Invoke calls to enhance interoperability with native libraries, making the compiled application compatible even in environments without a Just-In-Time (JIT) compiler.

### Key Findings
- .NET Native AOT uses <DirectPInvoke> in project files to enable direct P/Invoke generation for all entry points in the module, enhancing performance and reducing overhead.
- Native code interop is facilitated through the use of LibraryImport attributes, allowing seamless integration with native functions such as those found in Node.js addons.
- Testing Native AOT applications requires ensuring compatibility across various environments to confirm that direct P/Invoke calls work as expected without a JIT compiler.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries using Project CAV3RN's .NET Native AOT communication module employ Microsoft Graph as their primary communication channel and DNS recovery as a fallback mechanism to maintain command and control when the main channel is compromised or inaccessible, thus ensuring reliable and covert communication.

### Key Findings
- Project CAV3RN utilizes Microsoft Graph for initial communications with infected systems.
- DNS recovery serves as a fallback channel in case the primary communication method fails.
- .NET Native AOT compilation helps evade traditional signature-based detection methods.
- Adversaries can switch between communication channels dynamically to avoid network-based defenses.
- The use of DNS for fallback channels complicates traditional traffic analysis and monitoring efforts.
- This technique allows adversaries to maintain persistent access even when faced with sophisticated defensive measures.
