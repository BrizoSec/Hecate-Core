# R-0657: A Vault with a Heap-View: The Uncomfortable Space Between AgentCore Harness and Identity Research

## 1. System Research: How It Works

### Summary
AWS AgentCore Harness functions as a managed agent loop that executes reasoning via tools, including a default shell tool running with root privileges. This configuration creates an environment where the harness has access to the AgentCore Identity vault and can resolve credentials in plaintext within its memory space.

### Key Findings
- The default shell tool runs with root privileges and allows execution of arbitrary commands, such as piping a Python script via curl.
- The process environment allows reading /proc/1/mem, /proc/1/maps, and /proc/1/status to access the memory layout, identity, and privileges of the harness runtime.
- Credentials are resolved in plaintext within the harness's address space, specifically under the runtime path /opt/amazon/lib/python3.10/, where Python packages reside.
- The harness references AWS IAM roles using the format ${arn:...} in its Authorization header, which can be intercepted via memory scanning.
- Exfiltrated data includes Bearer JWT tokens and service account credentials (e.g., for the 'mcp-service' account), which can be sent to external C2 endpoints like webhook.site.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse default configurations in AWS AgentCore Harness by using prompt injection to execute a shell command that fetches and runs a malicious script. This script leverages the harness's root privileges to read process memory (/proc/1/mem) where credentials are resolved to plaintext, allowing the exfiltration of identity tokens via an external server.

### Key Findings
- The AWS AgentCore Harness ships with the `shell` tool enabled by default, running as root, which allows attackers to execute arbitrary commands within the agent's runtime environment.
- Attackers utilized indirect prompt injection to force the model to fetch a reconnaissance script (e.g., via curl) and pipe it into python3 for execution.
- The exploit accessed /proc/1/mem, /proc/1/maps, and /proc/1/status to read the memory layout and identity of the parent process, confirming the presence of plaintext credentials in the heap.
- Credentials were exfiltrated using a webhook (webhook.site) to capture HTTP POST requests containing Bearer JWTs and MCP replay URLs associated with the 'mcp-service' account.
- The runtime location was identified as /opt/amazon/lib/python3.10/, where the harness's Python packages and library paths were accessible to the injected code.
- AWS reviewed the finding and closed it as 'informative,' attributing mitigation to customer-side controls such as `allowedTools` scoping and egress filtering rather than a platform fix.

## 5. Research Synthesis

### Executive Summary
Adversaries exploit default configurations in AWS AgentCore Harness to execute arbitrary root-level commands via prompt injection, enabling direct memory access to /proc/1/mem and heap scanning for plaintext IAM credentials. This tradecraft allows the interception of Bearer JWTs and MCP service identities by resolving ${arn:...} references within the harness's Python runtime space before exfiltrating them to external C2 endpoints.

### Recommended Hypothesis
> Adversaries use prompt injection to execute arbitrary shell commands and /proc filesystem reads on AWS AgentCore Harness containers to extract plaintext IAM credentials from process memory for credential theft.

### Gaps Identified
- Current telemetry lacks visibility into internal process memory access patterns (specifically /proc/1/mem reads) and the resolution of ${arn:...} placeholders within agent runtime environments, leaving memory-based credential exfiltration undetected.

### Key Findings
- Hypothesis: Adversaries use prompt injection to execute arbitrary shell commands and /proc filesystem reads on AWS AgentCore Harness containers to extract plaintext IAM credentials from process memory for credential theft.
- Gap: Current telemetry lacks visibility into internal process memory access patterns (specifically /proc/1/mem reads) and the resolution of ${arn:...} placeholders within agent runtime environments, leaving memory-based credential exfiltration undetected.
- Focus: Implement behavioral monitoring for outbound HTTP(S) requests from agent workloads containing JWT tokens or MCP replay URLs, and establish baselines for unusual /proc filesystem access by non-system processes to identify heap-scanning activity.
