## 1. System Research: How It Works

### Summary
The WordPress REST API's /batch/v1 endpoint is designed to handle multiple requests in a single POST call, allowing for more efficient processing of client-side data. However, vulnerabilities within this endpoint can be exploited by attackers to achieve Remote Code Execution (RCE) without authentication, leading to significant security risks.

### Key Findings
- The /batch/v1 REST API endpoint can accept unauthenticated requests and process them in a manner that allows for exploitation via carefully crafted sub-requests.
- Exploitation of CVE-2026-63030 involves manipulating the parsing logic to cause confusion, while CVE-2026-60137 leverages SQL injection through improperly validated parameters.
- The combination of these vulnerabilities can lead to Remote Code Execution without authentication, highlighting critical flaws in WordPress's core security.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit the wp2shell vulnerability in WordPress by leveraging route confusion in its REST batch endpoint to execute SQL injection attacks and drop web shells onto servers, allowing them to gain remote code execution without authentication.

### Key Findings
- Attackers use an unauthenticated POST request to the /?rest_route=/batch/v1 endpoint with specific parameters to initiate the exploit.
- The vulnerability allows for SQL injection that can be used to drop a web shell onto the server, enabling further exploitation and command execution.
- Detection involves filtering out noisy curl and wget events using deterministic logic to identify genuine wp2shell attacks from background noise.
- Elastic Defend was used to run the attack chain end-to-end, demonstrating the effectiveness of detection rules in identifying such threats.

## 5. Research Synthesis

### Executive Summary
Adversaries exploit vulnerabilities in the WordPress REST API's /batch/v1 endpoint to achieve remote code execution without authentication, using SQL injection and route confusion techniques. This allows them to drop web shells on servers for further exploitation.

### Recommended Hypothesis
> Adversaries use unauthenticated POST requests with specific parameters targeting the /batch/v1 REST API endpoint to execute SQL injection attacks and deploy backdoors onto WordPress servers, aiming to gain remote code execution.

### Gaps Identified
- Current detection rules may not effectively differentiate between legitimate batch processing requests and malicious exploitation attempts based on HTTP request methods and URIs alone.

### Key Findings
- Hypothesis: Adversaries use unauthenticated POST requests with specific parameters targeting the /batch/v1 REST API endpoint to execute SQL injection attacks and deploy backdoors onto WordPress servers, aiming to gain remote code execution.
- Gap: Current detection rules may not effectively differentiate between legitimate batch processing requests and malicious exploitation attempts based on HTTP request methods and URIs alone.
- Focus: Enhance detection by implementing more sophisticated logic to filter out benign POST requests while accurately identifying those that exhibit patterns associated with wp2shell attacks, such as SQL injection payloads or specific process names indicative of shell command execution.
