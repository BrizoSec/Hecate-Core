## 1. System Research: How It Works

### Summary
TrickBot is a sophisticated banking trojan that utilizes DNS tunneling for Command and Control (C2) communication, allowing it to bypass traditional network security measures by encoding C2 data within DNS queries.

### Key Findings
- TrickBot uses DNS requests to establish covert channels with its command servers.
- The malware can download additional payloads and execute them on infected systems.
- DNS tunneling is employed to evade detection by standard security mechanisms.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are abusing DNS tunneling to establish command and control (C2) communications for a TrickBot variant, using specially crafted subdomains to transmit data in small chunks of up to 4 bytes per request. This technique helps evade traditional network security measures by mimicking legitimate DNS traffic.

### Key Findings
- TrickBot uses DNS tunneling to exfiltrate data and receive commands from its C2 servers, limiting each transmission to 4 bytes.
- Spear-phishing emails with malicious attachments are used as an initial infection vector for TrickBot before it leverages DNS tunneling.
- The adversary employs subdomains that follow a pattern indicative of the DNS tunneling technique, making detection challenging due to its resemblance to legitimate traffic.
- OilRig threat group also deploys 'ALMA Communicator', another malware capable of DNS tunneling for C2 communications.

## 5. Research Synthesis

### Executive Summary
TrickBot, a sophisticated banking trojan, employs DNS tunneling to evade detection and communicate with its C2 servers. It uses spear-phishing emails for initial infection and exfiltrates data through DNS queries mimicking legitimate traffic.

### Recommended Hypothesis
> Adversaries use DNS tunneling behavior to establish covert Command and Control (C2) communications on compromised systems, evading detection by network security mechanisms.

### Gaps Identified
- The current coverage lacks specific indicators of compromise (IoCs) for the subdomain patterns used in DNS tunneling by TrickBot variants, making it difficult to distinguish malicious activity from legitimate traffic.
- There is a lack of visibility into long-term persistence and lateral movement techniques employed by TrickBot after initial infection through spear-phishing emails.

### Key Findings
- Hypothesis: Adversaries use DNS tunneling behavior to establish covert Command and Control (C2) communications on compromised systems, evading detection by network security mechanisms.
- Gap: The current coverage lacks specific indicators of compromise (IoCs) for the subdomain patterns used in DNS tunneling by TrickBot variants, making it difficult to distinguish malicious activity from legitimate traffic.
- Gap: There is a lack of visibility into long-term persistence and lateral movement techniques employed by TrickBot after initial infection through spear-phishing emails.
- Focus: Investigating unusual DNS query patterns and correlating them with HTTP/HTTPS data exfiltration attempts can help identify TrickBot's presence in the network.
- Focus: Enhancing detection mechanisms to monitor process creation events related to network utilities abused for DNS tunneling, such as nslookup or dig.
