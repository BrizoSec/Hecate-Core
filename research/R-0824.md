## 1. System Research: How It Works

### Summary
Attackers deliver DCRat malware by staging a PowerShell payload within the user's 'INTERNAL_DB_CACHE' environment variable and hiding it inside PNG images hosted on Firebase storage. The execution chain progresses from an initial VBS loader to a .NET loader that retrieves steganographic payloads, ultimately spawning MSBuild.exe as a legitimate process to execute the final malicious code in memory.

### Key Findings
- The attack utilizes environment variable staging by dynamically setting and later clearing the user-scoped 'INTERNAL_DB_CACHE' variable to pass the initial PowerShell payload without writing it directly to the disk.
- Steganography is employed as a delivery mechanism, where malicious data is concealed within PNG files (e.g., JAMAICA.png, img_144505.png) hosted on Firebase Storage URLs.
- The final stage of the delivery chain involves spawning MSBuild.exe as a Living-off-the-Land Binary (LOLBin) to execute the payload, leveraging a trusted system utility to evade detection.
- PowerShell execution is heavily obfuscated and concealed, utilizing flags such as -ExecutionPolicy Bypass, -NoProfile, and -WindowStyle Hidden to run silently without user interaction or obvious console output.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries deliver DCRat malware by embedding the final executable within a steganographic PNG image hosted on Firebase Storage. The victim's machine retrieves this image, extracts the hidden payload using a .NET loader, and executes it via MSBuild as a Living-off-the-Land Binary (LOLBin) to avoid detection.

### Key Findings
- The attack chain utilizes environment variables for initial payload staging, specifically executing a PowerShell command that reads from $env:INTERNAL_DB_CACHE and then clears the variable post-execution to evade memory forensics.
- Steganography is employed as a delivery mechanism, with malicious payloads hidden inside legitimate-looking PNG images (e.g., 'JAMAICA.png', 'img_144505.png') stored on Google Firebase Storage to blend in with normal web traffic.
- The final execution phase relies on MSBuild.exe as a Living-off-the-Land Binary (LOLBin) to run the extracted payload, leveraging trusted system tools to bypass security controls.
- Indicators of Compromise include specific SHA256 hashes for the initial archive and potential payloads, Firebase storage URLs containing token-based access parameters, and C2 infrastructure associated with domain 44444.dynuddns.com and IP 94.154.35.160.

## 5. Research Synthesis

### Executive Summary
Adversaries are leveraging a reusable DCRat delivery chain that stages PowerShell payloads in the user-scoped 'INTERNAL_DB_CACHE' environment variable and conceals the final executable within steganographic PNG files hosted on Firebase Storage. This chain culminates in memory-only execution via MSBuild.exe, effectively bypassing disk-based detection by eliminating file drops and clearing environmental artifacts post-execution.

### Recommended Hypothesis
> Adversaries use environment variable staging and steganographic PNG carriers hosted on Firebase to deliver DCRat malware in memory, evading traditional endpoint monitoring by leveraging MSBuild.exe as a LOLBin.

### Gaps Identified
- Standard telemetry may miss the initial payload if the VBS script executes too rapidly or if logging does not capture the transient population of $env:INTERNAL_DB_CACHE before it is cleared.
- Network detection systems often fail to flag Firebase Storage URLs (firebasestorage.googleapis.com) as malicious due to their legitimate cloud infrastructure status, allowing the steganographic PNG payloads to download without triggering alerting on the carrier domain.
