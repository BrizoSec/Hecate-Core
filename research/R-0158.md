## 1. System Research: How It Works

### Summary
MISP is an open-source threat intelligence platform that facilitates the sharing of indicators of compromise (IOCs) among security professionals. It uses a standardized format to map CSV data fields into its attributes, allowing for efficient and effective threat information exchange.

### Key Findings
- The `feed_name` attribute in MISP is set to 'MISP' if the `event_source_org` field is empty; otherwise, it takes the value from `event_source_org`.
- IP addresses are mapped to `ioc.ip_and_ports.ip_address`, provided that the corresponding CSV data contains an `ip` field.
- URLs in MISP attributes are directly linked to the `entity.entity.url` if the attribute type is 'uri' or 'URL'.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploited Krawczyk Industries Limited on July 3, 2026, using the pass-the-hash technique with NTLM hashes obtained via Mimikatz to gain unauthorized access and initiate sessions without password cracking. This attack is categorized as medium threat level.

### Key Findings
- Pass-the-Hash (PtH) technique was employed to exploit NTLM authentication hashes.
- Mimikatz tool was used to extract and reuse NTLM hashes for session initiation.
- The incident highlights the risk associated with weak or compromised internal network security controls.
- ProxyShell vulnerabilities were likely leveraged in conjunction with PtH attacks to extend lateral movement within the network.
- Monitoring execution points related to pass-the-hash activities can help detect such intrusions early.
- Implementing out-of-band multifactor authentication (MFA) challenges could mitigate PtH attack success.

### Summary

Key data points include unusual outbound connections, DNS requests for suspicious domains, and potentially malicious HTTP/HTTPS traffic patterns.

- event.category (50% populated): Indicates the category of events such as authentication, process creation, network communication, or file system changes which are critical for identifying potential C2 activity. Categories like 'network' should be closely monitored.

- dns.query (45% populated): DNS query logs help in detecting attempts to resolve suspicious domain names, which is a common technique used by malware for establishing command-and-control channels or downloading additional payloads.
