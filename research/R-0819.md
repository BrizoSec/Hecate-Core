## 1. System Research: How It Works

### Summary
Langflow is an AI application-building platform that processes user-submitted Python code via its validation endpoint to test or execute logic within the development environment. Normal operation involves receiving JSON payloads containing code snippets, which are evaluated by the backend without authentication in vulnerable versions, allowing for potential system introspection.

### Key Findings
- The primary attack vector targets the unauthenticated POST /api/v1/validate/code endpoint, where attackers inject Python code into the JSON 'code' field to achieve Remote Code Execution (RCE).
- Malicious payloads specifically attempt to read /proc/self/environ via __import__ or subprocess calls to harvest environment variables, including cloud credentials and database secrets.
- Exploitation activity includes capability probing using unique markers and timing-based execution checks to verify if the injected Python code successfully executed on the server.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are exploiting CVE-2026-0768, an unauthenticated remote code execution vulnerability in the Langflow AI development platform, to inject Python code via the POST /api/v1/validate/code endpoint. These opportunistic attacks aim to harvest sensitive environment variables, such as cloud credentials and API keys, by reading /proc/self/environ rather than executing arbitrary system commands.

### Key Findings
- Attackers are leveraging CVE-2026-0768 to perform unauthenticated Python code injection on Langflow instances, specifically targeting the validation endpoint without authentication requirements.
- Exploitation payloads focus on capability probing and environment harvesting, using markers like exec, subprocess, __import__, and file reads of /proc/self/environ to extract secrets such as model API keys and database credentials.
- The activity originates from two distinct infrastructure clusters: Google Cloud hosts utilizing forged AI-crawler User-Agents for harvesting, and European scanning subnets employing spoofed localhost headers for probing.
- Indicators include traffic from 55 distinct IP addresses, with specific known malicious sources identified in the CHINA UNICOM China169 Backbone ASN (e.g., IPs 125.46.149.49 and 61.163.138.201).
- Detection should prioritize inspecting POST requests to /api/v1/validate/code for suspicious JSON code fields containing Python execution patterns or attempts to access system environment files.

- Endpoint detection systems may fail to correlate the initial network exploitation with subsequent process creation if the injected Python code executes within the same process context without spawning new distinct binaries, evading traditional command-line monitoring.
