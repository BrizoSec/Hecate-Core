## 1. System Research: How It Works

### Summary
ConnectWise ScreenConnect is a legitimate Remote Monitoring and Management (RMM) tool that installs an MSI package to establish remote access sessions, typically managed via a system.config file. In this specific attack vector, the technology was abused by threat actors who delivered a malicious installer disguised as a Florida healthcare licensing document via social engineering.

### Key Findings
- The campaign utilized a multi-stage delivery chain starting with Cloudflare Pages hosting (floridalicense.pages.dev) that mimicked legitimate verification workflows to lure victims into downloading a ZIP archive.
- The malicious payload was contained in an HTA file ('Florida Background Screening Notice.hta') which employed Base64-encoded VBScript to decode and execute commands using living-off-the-land binaries like mshta.exe, curl.exe, and msiexec.exe.
- The attacker modified Windows registry keys (HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer and HKLM\SOFTWARE\Policies\Microsoft\Windows\System) to disable Microsoft Defender SmartScreen before silently installing the ScreenConnect client via msiexec.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries executed a sophisticated web-based attack chain by impersonating DocuSign and targeting Florida healthcare professionals with fraudulent licensing lures to deliver ConnectWise ScreenConnect remote access software. The campaign utilized cloud-hosted infrastructure to deploy a malicious HTA file that employed defense evasion techniques, such as disabling SmartScreen, to silently install the RMM tool via native Windows utilities before being blocked at the entry point.

### Key Findings
- The attack leveraged social engineering by impersonating trusted brands (DocuSign) and using a Florida healthcare screening lure to deceive victims into downloading a ZIP archive containing a malicious HTA file.
- Defense evasion techniques included modifying registry keys to disable Microsoft Defender SmartScreen (HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer and HKLM\SOFTWARE\Policies\Microsoft\Windows\System) and checking for administrative privileges via HKEY_USERS\S-1-5-19.
- The adversary utilized living-off-the-land techniques, executing the payload through native Windows tools including mshta.exe to run the VBScript, curl.exe to retrieve the installer, and msiexec.exe to silently install ScreenConnect.
- Infrastructure relied on deceptive cloud services, using Cloudflare Pages for staging (floridalicense.pages.dev) and worker scripts for download redirection (docusig-document-sign6702.docusign-sign.workers.dev), alongside a custom domain (admin.rshiahub.com) hosting the ScreenConnect.ClientSetup.msi.
- The campaign was classified as 'Zero Hour Fraudulent' and successfully blocked by Menlo Security at the web entry point, preventing the payload delivery despite the sophisticated evasion layers designed to establish legitimacy.

## 3. Telemetry Mapping: OCSF Fields

### Summary
The threat intelligence describes a multi-stage attack involving social engineering via fake DocuSign workflows, delivery of a malicious HTA file within a ZIP archive, and subsequent execution of VBScript to download and install ScreenConnect. Key behaviors include the creation of the malicious HTA file, process spawning by mshta.exe, network connections via curl.exe and msiexec.exe to retrieve payloads from admin.rshiahub.com, file system modifications (dropping Installer.msi and f1040.pdf), and registry value changes to disable SmartScreen.

## 5. Research Synthesis

### Executive Summary
Adversaries deploy ConnectWise ScreenConnect via a multi-stage chain involving Cloudflare Pages staging, DocuSign impersonation, and a malicious HTA file that utilizes living-off-the-land binaries (mshta.exe, curl.exe) to disable SmartScreen and silently install the RMM client. The attack relies on registry modifications to evade detection and native Windows utilities for payload retrieval, indicating a high-fidelity execution chain designed to bypass standard endpoint controls before establishing persistent remote access.

### Recommended Hypothesis
> Adversaries use fake DocuSign social engineering lures and HTA-based VBScript execution to disable SmartScreen and deploy ScreenConnect via living-off-the-land binaries on healthcare infrastructure

### Gaps Identified
- Lack of telemetry for mshta.exe parent-child process anomalies (e.g., explorer.exe spawning mshta.exe) allows initial script execution to go undetected if process creation auditing is insufficient
- No specific indicators for the custom domain admin.rshiahub.com or the specific Cloudflare worker subdomains mean DNS and HTTP request telemetry will not inherently flag this campaign without broad allow-listing of .pages.dev domains

### Key Findings
- Hypothesis: Adversaries use fake DocuSign social engineering lures and HTA-based VBScript execution to disable SmartScreen and deploy ScreenConnect via living-off-the-land binaries on healthcare infrastructure
- Gap: Lack of telemetry for mshta.exe parent-child process anomalies (e.g., explorer.exe spawning mshta.exe) allows initial script execution to go undetected if process creation auditing is insufficient
- Gap: No specific indicators for the custom domain admin.rshiahub.com or the specific Cloudflare worker subdomains mean DNS and HTTP request telemetry will not inherently flag this campaign without broad allow-listing of .pages.dev domains
- Focus: Monitor for mshta.exe execution chains involving curl.exe and msiexec.exe, specifically looking for command-line arguments indicating silent installation (/qn) and SmartScreen registry modifications in HKLM\SOFTWARE\Policies\Microsoft\Windows\System
