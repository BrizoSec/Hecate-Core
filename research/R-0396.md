## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries abuse the Remote Services technique (T1021) to gain unauthorized access to enterprise environments by exploiting remote management protocols such as RDP, WinRM, and SSH. They leverage these services for lateral movement within a network, often using stolen credentials or phishing attacks to establish initial footholds.

### Key Findings
- Adversaries frequently exploit Remote Desktop Protocol (RDP) due to its ubiquity in enterprise environments and the ease of misconfigurations that allow unauthorized access.
- Windows Remote Management (WinRM) is a popular target for adversaries as it provides another vector for remote command execution with valid credentials, often bypassing less secure RDP configurations.
- SSH is increasingly being targeted by threat actors to establish backdoors into Linux-based systems and facilitate lateral movement across mixed environments.
- Phishing campaigns are commonly used to distribute malware that steals credentials or directly initiates Remote Services connections on behalf of the adversary.
- Misconfigured or unsecured cloud services can be abused for remote access, enabling adversaries to pivot from compromised cloud assets to internal network resources.
- Organizations often neglect to disable unnecessary remote service protocols, leading to expanded attack surfaces and easier lateral movement opportunities.

## 3. Telemetry Mapping: OCSF Fields

### Summary
Telemetry capturing the establishment and usage of remote connections via services such as Telnet, SSH, RDP (Remote Desktop Protocol), VNC, or other remote management tools using valid user credentials would help in detecting T1021 - Remote Services. This includes logging of authentication attempts, successful logins, and activities performed on the system by authenticated users.

### Key Fields
- event.action: Records the action taken (e.g., login, logout) related to remote services
- process.name: Identifies the process name associated with the remote service application (e.g., sshd.exe for SSH daemon)
- user.id: Represents the unique identifier of the user who performed actions over a remote session
- network.protocol: Specifies the network protocol used in establishing the remote connection, such as TCP or UDP
- source.ip_address: Provides the IP address from which the remote access was initiated
- destination.port: Identifies the destination port associated with the service (e.g., 22 for SSH)
- (event.action and process.name): Typically populated when an event related to a remote service is logged
